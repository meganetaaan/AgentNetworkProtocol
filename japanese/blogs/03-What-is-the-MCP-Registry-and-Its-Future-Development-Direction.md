# 分析：MCP Registryとは何か、今後どのように発展するのか

今日、MCPがレジストリの紹介を公開したというニュースを見ました。詳細はこちらです：https://blog.modelcontextprotocol.io/posts/2025-09-08-mcp-registry-preview/

MCPのエコシステムに深く関わっているわけではありませんが、エージェントのプロトコルは継続して研究しています。私の視点から、簡単に分析してみます。

1. まず、その性質を整理します。MCP Registryは、App Storeというより、MCPエコシステムの「DNS」に近いものです。

2. DNSとApp Storeの最大の違いは、DNSが非営利の基盤に近い一方、App Storeには非常に強い営利性があることです。

3. MCP Registryが公式に掲げる目標は、MCPサーバーの配布方法と発見方法を標準化することです。これまでもMCPのマーケットや集約プラットフォームは数多くありましたが、公式の中心となる場所や発見の仕組みはありませんでした。MCP Registryは、実質的にMCPエコシステムの「DNS」を構築し、MCPクライアントとサーバーが接続する際の障壁を大幅に下げます。

4. MCP Registryは有料なのでしょうか。現時点では、コミュニティが維持する無料の仕組みに見えます。将来、課金されるかどうかは分かりません。

5. MCP RegistryのMCPサーバーは信頼できるのでしょうか。公式の説明では、寛容なライセンスのもと、コミュニティ主導で審査します。登録する事業者にとっては容易ですが、情報を深く検証するわけではありません。その後、フィードバックに基づき、スパム、悪意あるサーバー、公式を装うサーバーを禁止します。つまり、レジストリからMCPサーバーを取得しても、その信頼性が完全に保証されるとは限りません。ただし、一定期間が経過しても削除されていないサーバーには、ある程度の裏付けがあります。

6. このレジストリがMCPの最終的な発見方式になるかは不明です。この方式は、A2AやANPと大きく異なります。A2AとANPはいずれもRFC8615を使い、ドメインのwell-knownパスに文書を置いて、エージェントとドメインを関連付けます。実質的には、既存の成熟したDNSと検索エンジンの発見の仕組みを利用します。

7. 既存のMCPナビゲーションサイトやマーケットには影響があるのでしょうか。MCPの公式説明によると、コミュニティや企業が構築した既存レジストリを置き換える意図はありません。既存レジストリ（MCPマーケット）は、MCPが公開した仕様を使い、MCPの公開サブレジストリとして自分たちのレジストリを構築できます。また、上流のMCPレジストリから取得したデータを自由に拡張し、充実させることができます。

8. ここから、MCPがエコシステム、特にそこに参加する企業の発展を重視していることが分かります。既存のナビゲーションサイトやマーケットでは、適切な差別化が必要になるかもしれません。単純に「集約」することの価値は、公式レジストリに吸収される可能性があるためです。独自の付加価値を見いだす必要があります。

9. サーバーやエージェントの発見には、二つの技術的な方向性があります。一つはMCP RegistryやAgent Name Serviceのようなレジストリ方式です。もう一つは、A2AとANPがRFC8615を使っているように、既存のDNSを拡張する方式です。それぞれに長所と短所があります。ただし、現在はいずれも、App Storeのような閉じたエコシステムではなく、開放性の原則に従っています。
