# Agentic Web — 10 回の講演 · 1 日目: World Wide Web からスーパー プラットフォームへ — Web エンクロージャの歴史的必然性

> **核心的な質問**: 「つながり」を可能にするネットワークはなぜ誕生し、必然的にプラットフォーム化されクローズド化するのでしょうか?

1989 年、CERN で働くティム・バーナーズ・リーという英国の科学者は、「情報管理: 提案」という一見平凡な提案を提出しました。彼の上司はその提案書に「漠然としているが刺激的だ」と書いた。

その「曖昧な」提案が最終的に世界を変えた。それは、現在ワールドワイドウェブと呼ばれているものの始まりでした。

30 年以上後、この歴史を振り返ると、不可解な矛盾に気づきます。**接続を可能にするために生まれたオープン ネットワークが、最終的にはプラットフォームとデータ サイロに支配されるようになったのはなぜですか?**

これは道徳的な選択についての話ではありません。それは生産力の進化に関する物語です。この歴史を理解することは、なぜ AI 時代に新しいインターネットが必要なのかを理解するための前提条件です。

## この記事の主なアイデア

- **ウェブと呼ばれる理由**: ティム・バーナーズ・リーの当初のビジョンは、「接続は力である」、つまり人々は自由に情報を接続し、互いに接続できるべきであるということでした。
- **HTTP が成功した理由**: シンプルさ、オープン性、パーミッションレス、既存インフラへの依存 - インターネット革命を可能にした 4 つの原則。
- **Web 2.0 の転換点**: オープンから囲いへの移行は裏切りではなく、人間の注意力と運用能力を最適化した必然の結果でした。
- **セマンティック Web が失敗した理由**: 手動による注釈の高コスト、商業的インセンティブの欠如、および過度に複雑な技術スタック - 3 つの山が美しいビジョンを打ち砕きました。
- **Web3 の限界**: Web3 は、ユーザー エクスペリエンスと生産性の現実を無視して、「信頼の問題」を「チェーン上の問題」に貶めました。
- **重要な判断**:囲い込みは陰謀ではなく、古い生産力の条件下での最適な解決策でした。規模の経済がプラットフォーム独占の形成を推進しました。

## I。ウェブの当初のビジョン: 接続は力です

「World Wide Web」という名前を初めて聞くと、多くの人は疑問に思います。なぜ「Web」なのでしょうか?

Tim Berners-Lee 氏の答えはシンプルでした。**情報はツリーとして配置されるべきではないからです。ウェブとして配置する必要があります。**

Web が登場する以前は、ほとんどの情報システムは、図書館分類システムやファイル システムのディレクトリ ツリーのように階層構造でした。しかし、現実世界の情報は決してそのように整理されていません。論文は複数の分野にまたがる場合があります。人は複数の役割を演じることがあります。情報間の関係は複雑な網のように見えます。

**ハイパーリンク** が Tim Berners-Lee の答えでした。 URL と HTML を使用すると、誰でも Web ページを作成し、それをインターネット上の他のページにリンクできます。情報が孤立した島に閉じ込められることはなくなりました。リンクを通じて自由に流れることができます。

この背後にあるアイデアは、**「つながりは力である」** でした。

### 「つながりは力」の本来の意味

Web が誕生したとき、「接続は力」には 3 つの意味がありました。

1. **接続できる人は誰でも見ることができます**: あなたのページがインターネット上に公開されると、世界中の誰もがそのページにアクセスできるようになります。
2. **つながりを築くことができる人は誰でも知識を整理できます**: ハイパーリンクを通じて、誰でも独自の知識のネットワークを構築できます。
3. **自由に接続できる人には自治権があります**: 仲介者も許可も必要ありませんでした。

この考えは今では時代遅れに聞こえるかもしれませんが、30 年以上前には革新的でした。

重要なのは、初期Webだった **インフラ、プラットフォームではなく**. . . 法人に所属せず、機関の運営を行なう。 誰でも自由に使えるように。

**オープンさはスローガンではなく出発点でした。**

## Ⅱ. Web 1.0: HTTP はなぜ成功したのか?

ハイパーリンクが Web の魂であるなら、HTTP プロトコルはその骨格です。

なぜHTTPは成功したのでしょうか?なぜ 30 年以上経ってもインターネットの基盤であり続けているのでしょうか?

その答えは、次の 4 つの主要な条件に要約できます。

### 1. シンプルさ

HTTP の中心的な考え方は非常にシンプルです。クライアントがリクエストを送信し、サーバーがレスポンスを返すというものです。それでおしまい。

最も初期の HTTP/0.9 仕様はわずか 1 ページでした。リクエストは 1 行でした: `GET /index.html`;応答は単なる HTML ドキュメントでした。リクエスト ヘッダー、ステータス コード、複雑なハンドシェイクはありませんでした。

この非常にシンプルなため、誰でも HTTP をすぐに理解して実装できることがわかりました。博士号も高価な機器も、特別なトレーニングも必要ありません。少しプログラミングを知っていれば、Web サーバーを構築できます。

**シンプルさによって障壁が低くなりました。障壁が低いため、より多くの参加者が集まりました。より多くの参加者がエコシステムを構築しました。**

### 2. 開放性

Tim Berners-Lee は、Web テクノロジーの特許を取得したり、非公開の標準化団体を設立したりしないという重要な決断を下しました。その代わりに、HTTP、HTML、URL の仕様を完全にオープンにしました。誰でも無料で使用、変更、拡張できます。

それは当時としては珍しいことでした。 1990 年代、多くの企業が独自の「情報スーパーハイウェイ」を構築しようとしていましたが、そのほとんどは専用のクライアントを必要とする閉鎖的な有料システムでした。

Web はオープンであるため、競争の中で目立つことができました。 **オープン性とは、単一の制御ポイント、レントシーキング、参入障壁がないことを意味します。** 誰でも Web サイトを構築できました。誰でも訪れることができます。仲介者が介入することはなかった。

### 3. 権限の無さ

これは Web の最も強力な機能の 1 つです。**Web サイトの作成、コンテンツの公開、または別の Web サイトへのリンクに誰の承認も必要ありません。**

レビューやゲートキーピングはなく、「最初に支払ってから運用を開始する」こともありませんでした。必要なのは、グローバル ネットワークに参加するためのサーバーとドメイン名だけです。

この許可のない性質は、莫大な創造的エネルギーを放出しました。個人のブログから Wikipedia、GitHub から YouTube に至るまで、数え切れないほどの偉大なイノベーションは、誰の承認も必要としない Web サイトとして始まりました。

**許可の無さは、イノベーションの速度がもはや承認プロセスによって制限されず、作成者の想像力によってのみ制限されることを意味しました。**

### 4. 既存のインフラストラクチャ上に構築

HTTP は車輪を再発明しようとしたわけではありません。これは TCP/IP に基づいて構築され、ドメイン名解決に DNS を使用し、既存のインターネット インフラストラクチャに依存していました。

これは、Web が初日から世界中で機能できることを意味しました。新しいネットワーク プロトコルが展開されたり、新しいハードウェアが製造されたり、新しい標準が承認されたりするのを待つ必要はありませんでした。オンラインに接続できれば、Web にアクセスできるでしょう。

**既存のインフラストラクチャ上に構築することで、展開コストが大幅に削減され、導入が加速されました。**

### 本質的な成果: 情報の制作と配布の解放

Web 1.0 の中心的な成果は、**情報の作成と配布** を解放することでした。

それ以前は、情報を出版するには出版社、印刷機、流通チャネルが必要でした。ウェブでは誰でも出版者になれるようになりました。

しかし、この時代には決定的な特徴が 1 つありました。**人々は依然として主要な「通訳」および「執行者」でした。**

Web ページは人々が読むためのものであり、ハイパーリンクは人々がクリックするためのものであり、情報は人々が処理するためのものでした。 Web 全体は人間の認知能力と操作能力を中心に設計されています。

**人々は引き続き主要な生産力でした。**

この事実が、その後のプラットフォーム変革の種を蒔きました。

## III. Web 2.0: プラットフォーム化は裏切りではなく、効率性のための選択でした

Web 1.0のキーワードが「オープン性」と「つながり」であれば、Web 2.0のキーワードは「プラットフォーム」と「ユーザー生成コンテンツ」でした。

2000 年代初頭、ブロードバンドの普及とテクノロジーの進歩に伴い、インターネットは「読み取り専用」から「読み取り/書き込み」に移行しました。ブログ、フォーラム、ソーシャルネットワークが普及しました。ユーザーはもはや情報の受動的消費者ではありませんでした。彼らはアクティブなクリエイターになりました。

これは良いことのはずでした。しかし、それには大規模な権力移譲が伴った。

### プラットフォームはなぜ登場したのか？

プラットフォームの台頭を商業的貪欲や道徳的衰退のせいにする人は多いが、その説明は単純すぎる。

プラットフォームは、次の 3 つの実際の問題に対応して登場しました。

#### 1. 情報過多

Web 1.0 は情報公開の問題をうまく解決しましたが、情報が多すぎるという新たな問題も生み出しました。

インターネットに何十億もの Web ページが含まれていたとき、人々は必要な情報を自分で見つけることができませんでした。この問題を解決するために検索エンジンが登場しました。

Google の PageRank アルゴリズムは、基本的に情報の価値を測定するために「つながり」を使用しました。多くの場合、より高品質なページによってリンクされているページほど、価値が高くなります。

**これは「接続は力である」の最初の歪みでした。接続はもはや平等ではありませんでした。重みがありました。**

#### 2. 人間関係を管理するコストが急激に上昇

Web 1.0 の時代には、RSS を通じて何十ものブログをフォローするかもしれません。しかし、連絡先の数が数百、数千に達すると、人間関係を手動で管理することは不可能になります。

この問題を解決するために登場したのがソーシャルネットワークです。 Facebook、Twitter、WeChat は、友達が誰なのか、興味のあるコンテンツが誰なのか、誰がオンラインなのかなどの関係を管理するのに役立ちます。

**プラットフォームは関係の主催者および仲介者になりました。**

#### 3.  照合トランザクションの複雑さ

電子商取引の台頭により、新たなニーズが生まれました。買い手は売り手をどうやって見つけることができるのでしょうか?どうすれば取引を安全にできるでしょうか?紛争はどのように解決できるでしょうか?

これらの問題を解決するために登場したのがタオバオ、アマゾン、eBayです。彼らは、検索、支払い、物流、評価、アフターサポートなどの一連のサービスを提供しました。

**プラットフォームは取引の仲人および信頼の仲介者になりました。**

### プラットフォーム化の内部ロジック

最終的に、プラットフォームは次の 3 つの主要な問題を解決しました。

1. **コンテンツフィルタリング** (検索と推奨)
2. **関係組織** (ソーシャルグラフ)
3. **トランザクションマッチング** (電子商取引および広告)

これら 3 つの問題には 1 つの共通の特徴がありました: **それらはすべて人間の注意力と操作能力に合わせて最適化されていました。**

人間の注意力には限界があり、行動能力にも限界があります。情報と関係の規模が私たちの処理能力を超えると、フィルタリング、整理、照合のために何らかの仲介者が必要になります。

**プラットフォームはその仲介者です。**

これは道徳的な問題ではなく、効率の問題です。人間が主要な生産力であった時代には、プラットフォーム化は避けられない選択でした。

## IV.エンクロージャとモノポリーの内部要因

プラットフォームの出現自体が問題ではありませんでした。問題は、なぜプラットフォームが閉鎖的かつ独占的になったのかということです。

答えはソフトウェアの経済性にあります。

### ソフトウェアの限界費用がゼロに近づく

従来の製造業では、製品の製造には原材料、労働力、設備が必要です。 100 個のユニットを生産するコストは、1 個のユニットを生産するコストの約 100 倍です。

ソフトウェアが違います。ソフトウェアの開発にはお金がかかりますが、コピーにはほとんどお金がかかりません。 100 人のユーザーにサービスを提供する場合と 1 億ユーザーにサービスを提供する場合のコストの差は、100 万分の 1 よりはるかに小さくなります。

**これは、ソフトウェアには自然に規模の経済があることを意味します。**

### 規模が大きいほど価値も大きくなります

プラットフォーム ソフトウェアの場合、規模の影響はさらに顕著になります。

- **より多くのユーザー** → より多くのデータを生成
- **さらなるデータ** → より良いアルゴリズムをトレーニングする
- **より良いアルゴリズム** → より良いエクスペリエンスを提供
- **より良い体験** → より多くのユーザーを惹きつける

これにより、正帰還フライホイールが作成されます。

> **ユーザーの増加 → 効率の向上 → ロックインの強化 → プラットフォームの拡大**

これが、インターネット業界が勝者総取りの結果をいとも簡単に生み出してしまう理由です。

### 囲い込みは規模の経済の必然の結果である

プラットフォームが支配的になると、それ自体を閉鎖する強い理由があります。

1. **データはコア資産です**: データをオープンにするということは、競合他社にコア資産への自由なアクセスを与えることを意味します。
2. **ユーザーの囲い込みは堀**: ユーザーの離脱を困難にすることが独占を維持する鍵です。
3. **エコシステムの制御は力の源**: 開発者のエコシステムを制御することは、イノベーションの方向を制御することを意味します。

WeChat は、どのリンクを共有してよいか、どのリンクを共有できないかを決定できます。タオバオはどの商品を推奨し、どの商品を推奨しないかを決定できます。 App Store は、どのアプリケーションをリストに掲載するかを決定できます。

### オープン性の高いコスト

対照的に、オープン性を選択すると、多大なコスト圧力が生じます。

情報空間にはオープンなビジネスがあります。電子メール、音声通話、テキスト メッセージは、典型的なオープン インターネット アプリケーションです。しかし、それらには 1 つの特徴があります: **シンプルです。**

電子メール プロトコル (SMTP/POP3/IMAP) は 1970 年代から 1980 年代に誕生しました。その中心的な機能は、単純にテキスト メッセージを送受信することです。音声通話とテキストメッセージも同様で、機能は限定されており、規格も明確です。

しかし、ビジネスがより複雑になるにつれて、オープン化のコストは急激に上昇します。

- 異なるベンダーによる実装は互換性を維持する必要があります。
- プロトコルのアップグレードには、すべての参加者間の調整が必要です。
- 偶然の複雑さは、本質的な複雑さと複合します。
- デバッグとメンテナンスのコストは急激に増加します。

WeChat のモーメント、チャネル、支払い、ミニプログラムがすべて他のプラットフォームとオープンに相互運用する必要がある場合を想像してみてください。いくつの標準が必要になるでしょうか?交渉は何回くらいですか？テストは何回行いますか?それは、**大規模なソフトウェア エンジニアリング災害**となるでしょう。

**したがって、インターネット ビジネスがより複雑になるにつれて、オープン性が低下しました。これは道徳的な選択ではなく、工学上の現実でした。**

### 重要な判断

従来のソフトウェア時代には、次のような基本的なロジックがありました。

> ** ソフトウェアを一度開発すれば、すべての人に役立ちます。ユーザーが多ければ多いほど、効率は高まります。独占は偶然ではなく、内生的な結果です。**

これは、プラットフォームの独占が正当化されると言っているわけではありません。つまり、**基盤となるテクノロジーが変わらなければ、インターネットは自動的にオープンな状態に戻ることはできません。**

セマンティック Web と Web3 の歴史がこの点を証明しています。

## V.セマンティック Web はなぜ囲いを破らなかったのでしょうか?

Web 2.0 が囲い込みに向かうにつれて、セマンティック Web という別の道が模索されました。

1998 年、Tim Berners-Lee は、機械が単に Web ページを表示するのではなく、その意味を理解できるようにするというセマンティック Web のビジョンを提案しました。データにセマンティックな注釈を追加することで、マシンは自動的に情報を推論、統合、分析し、真にインテリジェントなネットワークを構築できるようになります。

それはよく知られていますか？それが今日AIエージェントがやろうとしていることではないでしょうか？

Tim Berners-Lee が *Scientific American* に掲載したセマンティック Web に関する記事を読むことをお勧めします。これには、今日のエージェント ネットワークのビジョンと非常によく似たエージェント ネットワークの具体的な説明が含まれています。

しかし、セマンティック Web が大量に採用されることはありませんでした。なぜ？

根本的な理由は 3 つの点に要約できます: **手動アノテーションのコストが高すぎる、商業的インセンティブが欠如している、技術スタックが複雑すぎる。**

セマンティック Web では、Web サイト開発者は RDF や OWL などの言語でデータに注釈を付ける必要がありました。しかし、これはオペレータに直接的な利益をもたらしませんでした。ユーザーは注釈を見ることができず、検索エンジンは注釈を上位に表示しませんでした。さらに重要なのは、技術的な障壁が高すぎて営利企業が導入を推進していない場合、エコシステムが形成できず、ネットワーク効果が発揮できなかったということです。

セマンティック Web は私たちに重要な教訓を残しました。

> ** マシンがデータのセマンティクスを理解できるようにすることは正しい方向ですが、手動のアノテーションに依存することはできません。データを自動的に理解するマシンに依存する必要があります。**

それはまさに、大規模な言語モデルによってもたらされる革命的な変化です。

しかし、AI が登場する前、セマンティック Web は失敗する運命にありました。なぜなら、セマンティック Web は当時の生産的な現実と闘うために「制度的または技術的な理想」を利用しようとしたからです。

## VI. Web3 はなぜエンクロージャを破壊しなかったのか?

Web3 はブロックチェーンでプラットフォームの独占を解決しようとしました。つまり、ユーザーデータをオンチェーンに置き、スマートコントラクトを通じてアプリケーションを実行し、NFT を通じてデジタル資産の所有権を確立しました。ビジョンは美しかったですが、それは実現できませんでした。

問題は 3 つありました。**信頼をオンチェーンの問題に落とし込んだ** (現実世界の信頼には、実行、責任、紛争も含まれます)。 **そのパフォーマンスのボトルネックは克服することが困難でした** (ビットコインは 1 秒あたり 7 トランザクションを処理しますが、Alipay は 100,000 トランザクションです)。 **ユーザー エクスペリエンスがあまりにも悪かった** (シード フレーズ、秘密キー、ガス料金が一般ユーザーを遠ざけました)。

Web3 のより深い問題はセマンティック Web の問題と同じでした。**Web3 は当時の生産的な現実と闘うために「制度的または技術的な理想」を使おうとしました。** 人間が主な生産力だった時代、秘密キーの管理、ガス料金の支払い、ブロック確認の待機は容認できないコストでした。 Web3 は「誰が行動するか」という問題を解決しませんでした。依然として人間が主な実行者でしたが、人間の能力と意欲は分散型ビジョンをサポートするには十分ではありませんでした。

## 結論:Webの進化は間違いではなく、Each Eraが最適なソリューションを発見しました

まずは質問に戻る: **どうしてもネットワークが生まれ、積極的にプラットフォーム化し閉じられるようになったのでしょうか?**

回答は: **時代ごとに、その時を生産的な条件下で最適なソリューションを選択しました。**

- Web 1.0 は、情報の生産を解放しましたが、情報積み過ぎを作成しました。
- Web 2.0は膨大な量の情報を集めたが、プラットフォームのモノポリスを生成した。
- マシンがデータを理解しようとしたSemantic Webは、マニュアルの注釈に依存して、コストも高すぎます。
- Web3は、ブロックチェーンでインターネットを分散しようとしましたが、ユーザエクスペリエンスと効率性を無視しました。

**エンクロージャは、陰謀ではありませんでした。 人間が主力であった時代、スケールの効率性や経済性が必然的に変化した。**

重要なレッスンを受講します。

> **生産性が根本的な変化を受けていない場合、インターネットは自動的に開放性に戻りません。**

そこで、生産性の力の変化は、このサイクルを壊すことができるのでしょうか?

回答は: **人からAIエージェントに変化する時。**

AIエージェントは、グラフィカルなユーザーインターフェイスを必要としません。注意して制約を受けず、プライベートキーの管理の複雑性を気にせず、情報過負荷を恐れていません。 プロトコルを直接通信し、サービスに自動で発見・接続したり、タスクを自動的にやり取りしたり、自動的に実行したりすることができます。

**エージェントのWebの歴史的な機会です。**
