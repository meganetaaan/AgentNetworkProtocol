# ANP 誕生の年: web3、Agora プロトコル、WebAgents、did:web のコミュニティへの感謝

ANP オープンソース プロジェクトの開始と開発からほぼ 1 年が経過しました。この期間中、私は自分のエネルギーのほとんどをこの取り組みに捧げ、昨年はフルタイムで専任するためにアリババを辞めました。

起業家精神は困難を伴いますが、このような困難な資金調達環境で資金なしでオープンソース プロジェクトを維持することはさらに困難です。ちょっと自慢させてください: **私は 1 年前に未来を予見し、なんとか耐え忍びました。**

私の粘り強さは、回復力だけによるものではなく、むしろ旅そのものが信じられないほど楽しかったからです。この仕事の本質的な面白さと、オープンソース コミュニティの活気に満ちた雰囲気、世界中の開発者との交流が相まって、アリババ時代に比べて私の身体的および精神的な健康状態は大幅に改善されました。 （財布だけが不満のままです。）

**本当に興味のあることをすることで、体も心も豊かになります。**

今日は、ANP の創設の背景にある完全なストーリーを共有し、これまで私たちをサポートしてくれたコミュニティに感謝の意を表したいと思います。

最近、インターネットの将来に対する私たちのビジョンがより広く認識されつつあることがますます明らかになってきています。肯定的なフィードバックが増えており、より多くのオープンソース愛好家や協力者がコミュニティに参加しています。

ANP はまだ完璧ではなく、実装を待っているアイデアや計画がまだたくさんありますが、ANP はすでにエージェントの通信プロトコルの間で影響力を持っています。当社 **は、明確な技術パス (エージェント Web + 分散化 + セマンティック Web)** を表しており、このパスに沿った当社の探求は引き続き業界の最前線にあります。

## 原点

ANP は、次のような単純な質問 (オーディオとビデオに密接に関連した私の以前の仕事から生じた) から生まれました: ** パーソナル アシスタントを使用してビデオ会議に参加するにはどうすればよいですか? ** しばらくの間、この質問が私の心にしつこく残りました。

さらに詳しく調査した結果、エージェントの接続とコラボレーションにおける重大な技術的ギャップが見つかりました。既存のテクノロジーでは、インテリジェント エージェントのニーズを十分に満たすことができませんでした。インテリジェント エージェントには、すべてのエージェントがシームレスに相互接続し、基盤となるデータを直接交換できる、よりネイティブな形式の接続が必要です。

この考え方と設計は、最終的に ANP プロトコルの作成につながりました。

設計プロセス全体を通じて、ANP は大規模な再構築を行い、他のコミュニティからの優れたアイデアを取り入れました。

## web3

ANP に大きな影響を与えた最初のコミュニティは web3 でした。

2022 年、個人データ主権に対する強い信念に突き動かされて、私は空き時間に Web3 について研究し始め、多くの Web3 実践者と広範な議論を行いました。

Web3 コミュニティ内で、私はブロックチェーン テクノロジを学び、分散化の背後にある哲学と手法を理解し、その後、分散型識別子 (DID) の概念と W3C DID 標準に出会いました。また、Nostr、AT プロトコル、Lens プロトコルなどの魅力的なプロトコルについても調査しました。

分散化は ANP の中核原則でもあります。ただし、ブロックチェーンのような完全な分散化を追求するのではなく、特にエージェント ID の相互運用性に合わせて調整された、ローカル集中化と組み合わせたグローバル分散化のモデルを提唱します。

W3C DID は、ANP におけるエージェント ID の基礎となるテクノロジーとして機能し、現時点ではこの目的に最も適したテクノロジーであると考えています。

最後に、web3 コミュニティに関する注意事項を示します。

web3 は金融面と密接に関係しており、主流ユーザーからはやや遠いものの、従来の web2 とは異なる独自の価値観、世界観、技術的枠組みを持っています。これらの側面は非常に興味深いものです。

さらに、web3 コミュニティはオープンな雰囲気を醸成しており、私はそのビルダー文化、DAO 組織構造、およびトークンベースのインセンティブ メカニズムを特に高く評価しています。これらの要素は、私の ANP の設計に大きなインスピレーションと影響を与えました。

## アゴラプロトコル

私の感謝に値する 2 番目のコミュニティは、Agora Protocol です。

Agora Protocol は、オックスフォード大学と Camel AI のチームが共同開発したメタプロトコル テクノロジーで、インテリジェント エージェント間のプロトコル ネゴシエーションのために設計されています。

プロトコル関連の仕事での豊富な経験を考えると、体系的に調査したことはありませんでしたが、プロトコルのネゴシエーションと統合に対する AI の潜在的な影響は以前から認識していました。

Agora プロトコルに触発されて、私はさらに深く検討した後、アイデンティティと暗号化層、メタプロトコル層、アプリケーション プロトコル層という ANP の 3 層アーキテクチャを正式に確立しました。

この 3 層アーキテクチャは現在も使用されており、進化し、改善され続けています。

当社のメタプロトコル層の実装では、主に Agora Protocol の研究論文を参照し、通信プロトコルの経験に基づいたエンジニアリングの最適化を組み合わせています。

その後、私は、Agora Protocol の著者であるオックスフォード大学の smarro 氏と、Camel AI の創設者である Li Guohao 氏と、エージェントの通信プロトコルに関する技術交流を行いました。最近、smarro はエージェント通信プロトコルの標準化に特化したワーキング グループを立ち上げ、積極的に参加しています。

## Webエージェント

私が感謝したい 3 番目のコミュニティは WebAgents です。

WebAgents は、私たちのコミュニティの海外メンバーである James によって紹介されました。

Web エージェントは主にセマンティック Web テクノロジーを活用して、Web ベースのマルチエージェント システム (MAS) を構築します。私は WebAgents コミュニティからの資料、特に会議記録を徹底的にレビューし、セマンティック Web の概念についての貴重な洞察を得ました。

その後、セマンティック Web の起源、特に World Wide Web の発明者である Tim Berners-Lee の記事や、JSON-LD、RDF、OWL などの関連標準を体系的に研究しました。

セマンティック Web は魅力的な概念です。 Scientific American でティム バーナーズ リーの 2001 年の記事を読んだことがあれば、彼の驚くべき先見の明がわかるでしょう。彼が説明したシナリオは、広範なインテリジェント エージェントに対する現在のビジョンによく似ています。

しかし、当時の AI テクノロジーの制限により、セマンティック Web はデータ アノテーション アプローチを追求しましたが、最終的にはその思い描いていた可能性を実現できませんでした。その後、インターネットはより閉鎖的な、モバイル中心の時代に進化しました。

それにもかかわらず、セマンティック Web から継承されたテクノロジーは、インテリジェント エージェント間の通信を効果的に促進します。セマンティクスを事前に定義することで、さまざまなエージェントがデータを一貫して理解できるようになり、自然言語コミュニケーションに固有のあいまいさを効果的に解決できます。

これが、セマンティック Web テクノロジーがエージェント記述プロトコルの中核を形成する理由です。

## やった:ウェブ

感謝に値する 4 番目のコミュニティは、did:web です。

Did:web は、W3C の DID 標準の実装方法であり、Web テクノロジーを利用して分散型 ID を実現します。その全体的な設計は電子メールに似ており、強力な相互運用性を備えてグローバルに分散されていますが、内部的には集中化されており、数十億のユーザーをサポートできます。

当初、私たちは Did:all と呼ばれる DID メソッドを採用しました。これは、ビットコイン アドレスに似た自己検証型 DID メソッドであり、これも Web テクノロジーに基づいています。しかし、私たちの方法は、DID に関連付けられた秘密キーを失った後の回復という、未解決の重大な問題に直面していました。興味のある読者は、詳細について非推奨のドキュメントを参照してください。

その後、did:web デザインに出会いました。これは、秘密キーの回復の問題をエレガントに解決し、私たちの全体的なデザイン哲学と密接に一致していました。

その結果、私たちは Did:Web ソリューションに移行し、エージェントの説明、エージェント ID のプライバシー保護、エージェント ID に対する人間の認証などのインテリジェント エージェントのサポートを追加しました。私たちはdid:wba（ウェブベースエージェント）と呼ばれる新しい手法を提案しました。

また、did:web の作者とも Twitter でやり取りをしており、最終的には私たちの 2 つの方法が統合されることを願っています。

## オープンソースとコミュニティ

ANP プロトコルとそのコア コード実装は MIT ライセンスに基づいてライセンスされており、今後もそのライセンスが維持されます。

ANP の設計プロセス全体を通じて、私たちはオープンソース コミュニティからの優れた成果を幅広く取り入れており、コミュニティへの還元も目指しています。

私たちは、**クローズドプロトコルには未来がなく、増分価値のないオープンソースには意味がないと固く信じています。**

オープンソースとコミュニティ構築への参加を通じて、私はオープンソースの力と価値を目の当たりにしてきました。私たちは、より多くの開発者、コミュニティ、企業が ANP コミュニティの構築に参加してくれることを心から願っています。

## 連絡先情報

AgentNetworkProtocol の目標は、インテリジェント エージェント インターネット時代の HTTP プロトコルになることです。

私たちのビジョンは、インテリジェントなエージェント間の接続を定義し、数十億のエージェントのためのオープンで安全かつ効率的な共同ネットワークを構築することです。

エージェントの通信プロトコルに興味がある場合は、オープンソース コミュニティに参加し、共同でエージェントの接続を定義し、エージェントティック Web の将来を探索することを心よりお勧めします。
