# AIとインターネットのやり取りの三つの技術的な方向性：OpenAI Operatorから考える

Operatorの公開で、エージェントの議論が、再び盛んになりました。

紹介記事は多くあります。公式の説明も参照できます：https://openai.com/index/computer-using-agent/。

簡単に言えば、ブラウザーやコンピューターを操作し、日常の作業を支援します。最大の意味は、AIを、現在のインターネットのエコシステムにつなぐことです。

この記事では、四つの技術的な方向性を比較します。要点は、次のとおりです。
- Computer Use Agent、ヘッドレスブラウザー、端末側API、リモートAPI／プロトコルの四つがあります。
- Computer Use Agent（CUA）は、既存のアプリを変更せず、すぐ接続できます。ただし、実行コストが高く、非同期化できません。
- ヘッドレスブラウザーは、非同期で、より低コストですが、Web限定で、ページへの対応の保守に手間がかかります。
- 端末側APIは、アプリがSiriなどに機能を公開する、AIスマートフォンの主な方式です。非同期で体験もよい一方、携帯端末とアプリに限られ、開放性に依存します。
- リモートAPI／プロトコルは、AIが最も得意な方法です。非同期、低コスト、自動認証が可能ですが、アプリの改修が必要で、統合のコストが高くなります。
- 短期には、CUAとヘッドレスブラウザーは、適した用途で、早く事業価値を生めます。
- 長期には、体験とコストに優れるAPI／プロトコルに期待します。AIのプログラミング能力の向上で、改修のコストは下がり、標準も現れると考えます。
- 私たちも、プロトコルの実用化を探り、進展を得ています。

## Computer Use Agent（CUA）

画面を撮影し、モデルの視覚能力で、ボタン、メニュー、入力欄などのGUIを認識して、人の画面理解を模倣します。

その後、仮想カーソルとキーボードで、クリック、入力、スクロールを行い、アプリやインターネットとやり取りします。

利点は、次のとおりです。

1. **すぐに、インターネットとやり取りできる**

人向けに作られた既存のインターネットに、最も早く接続するには、人を模倣することです。ツールの不足を解消し、価値のある作業を支援し、商用化を早められます。

2. **データの孤立を破る**

人とインターネットの間に個人アシスタントを置き、すべての情報にアクセスして、より賢い判断を助けます。

3. **アプリの変更コストが低い**

ほとんど変更せず、AIが利用できます。

一方、欠点もあります。

1. **実行コストが高い**

視覚に依存し、画像処理の費用がかかります。価値の高い用途では成立しても、一般の消費者向けへの普及には、大きな課題があります。

2. **非同期で実行できない**

画面の撮影と制御をAIに任せる間、人はコンピューターを使えません。理想は、裏で非同期に処理し、必要なときだけ、介入を求める体験です。

3. **頻繁に、手動のログインが必要**

消費者向けでは、人がアプリにログインする必要があり、本人認証を自動化できません。

4. **短期には、正確さの問題がある**

単純なWebタスクでは87%と優れますが、複雑なローカル操作は38.1%、動的なWebの操作は58.1%で、制約があります。

**最初に実用化しやすいのは、企業向け、特に価値が高く、個別性もある用途**でしょう。単純な繰り返しなら、RPAの方が適するかもしれません。

消費者向けでも、動画編集者などの専門家には、よい用途がありそうです。

一般の消費者では、コスト、体験、ほかの方式との競争のため、あまり競争力がないかもしれません。

## ヘッドレスブラウザー

GUIなしに、コマンドラインやプログラムから、裏で動くブラウザーです。ページの読み込み、JavaScript、描画など、通常と同じ処理ができますが、目に見える画面はありません。

AIを接続する方法は、次のとおりです。
- Puppeteerなどで、Webアプリのページのデータ全体を、描画せず取得する。
- AIで処理し、目的の操作に必要な要素を見つける。
- AIや人が書いたコードで、フレームワークのAPIから操作する。
- このコードをAIのツールとして呼び出させる。

**利点：**

1. **非同期の処理**

裏で動き、コンピューターの制御を奪わず、必要なときだけ人を呼べます。

2. **Webアプリは変更不要**

素早く接続できます。

3. **CUAより低コスト**

テキストの処理と、事前のコードで、視覚依存より安くできます。

**欠点：**

1. **Web限定**

ローカルアプリなどは使えません。CUAには、この制約はありません。

2. **ページへの対応のコスト**

多くのコードが必要で、ページが変わると、作り直し、テストし、配布し直すため、保守の費用がかかります。

3. **手動のログイン**

CUAと同じく、人の操作が必要で、自動認証できません。

毎回、ページの全データをLLMに入れる方法もありますが、非効率で高価です。専用のモデルを学習させる方が、よいかもしれません。

ミニプログラムのプラットフォームは、よい用途かもしれません。本質的にはWebアプリなので、アカウントの相互接続を解決できれば、利用者のアカウントで、人の介入なしに操作するアシスタントを作れます。

## 端末側API

OSが開く標準の機能インターフェースで、センサー、アプリのデータ、ハードウェアを直接使います。システム単位で、意図のやり取りのプロトコルを設け、人を模倣せず、正確に操作します。

**実装の原理：**

1. 意図の登録

「メッセージの送信」「予定の作成」などの技能の意図を、パラメーター形式と権限の範囲とともに、アプリがOSに宣言し、全体の能力の一覧を作ります。iOS 18のApp Intentsは、200を超える中心的な機能の登録をサポートしています。

2. 意味の対応付け

自然言語理解（NLU）が、「今撮った写真を仕事のグループに送って」を、構造化したAPIの連鎖に変え、写真、連絡先、即時メッセージのAPIを、自動的につなぎます。

3. 安全なサンドボックス

TEE（Trusted Execution Environment）で、アプリをまたぐデータの流れを実現します。一度の認可で、位置情報とメモなど、複数のAPIを組み合わせられますが、元のデータは端末を出ません。

**利点：**

1. UIの変更コストはゼロ

標準のインターフェースを登録し、実装すればよく、既存の画面は変更不要です。変更は主に、内部の機能です。

2. 本当の非同期処理

航空券、ホテル、レンタカーなどを、裏で複数呼び出し、人は、いつでも中断できます。

3. CUAより低コスト

視覚の能力は不要です。

**欠点：**

1. エコシステムの断片化

Android、iOS App Intents、HarmonyOSのAtomic Servicesなどで、標準が異なります。

2. アプリの開放性

携帯端末のメーカーとの競争があるため、中心的なデータを渡しにくい問題があります。

3. 用途の制限

主にスマートフォンで使われ、その基盤を持たないチャットボットでは、使えません。

## リモートAPI／プロトコル

AIが、APIやプロトコルで直接接続します。外部APIがあれば、関数呼び出しやtoolsで、情報を取得し、操作できます。

既存のAPIは、AI専用ではないため、人のコーディングや、キーの事前設定が、認証やアクセス制御に必要かもしれません。

MCPやANPなど、専用の方式も現れています。共通の目標は、AIが最も得意な方法で、インターネットにアクセスすることです。

MCPは、LLMと外部のデータやツールの通信を標準化し、コンテキストを効率的に使って、応答の質と実用性を高めます。

ANPは、Agent Network Protocolの略です。https://github.com/agent-network-protocol/AgentNetworkProtocol にある、業界初のオープンソースのエージェント通信プロトコルです。MCPとは異なり、対等な立場のエージェントを中心に、効率的な協働ネットワークを目指します。

**利点：**

1. **データ中心のやり取り**

人のアクセスを模倣するCUAやヘッドレスブラウザーと違い、最も得意な、元のデータを直接扱えます。

2. **非同期の処理**

コンピューターを占有せず、裏でAPIやプロトコルを使います。

3. **低コスト**

画面の画像処理も、ページ用のコードの保守も不要です。

4. **自動の本人認証**

DIDなどの分散型技術で、プラットフォームをまたいで自動認証できます。人の介入は、支払いなどの重要な操作だけです。ANPは、すでにDIDをサポートしますが、MCPは、まだしていません。

**欠点：**

1. **改修コストが高い**

既存のシステムを変える必要があり、最大の弱点です。ただし、AIのプログラミングの進歩で、下がるでしょう。

2. **初期段階で、標準が不明**

既存の方式が少なく、標準は確立していません。主な研究は、MCPとANPです。

ただし、W3Cや中国のIIFAAなどの標準化団体も、取り組んでいます。

## まとめ

四つの方向性を、全体から見てみます。

短期には、CUAとヘッドレスブラウザーは、制約があっても、適した用途なら、素早く事業価値を生めます。

長期には、最もよい体験と低い実行コストを持つ、API／プロトコルに期待します。AIのプログラミング能力で、改修費用も下がるでしょう。標準も必ず現れると考え、私たちは、その重要な参加者を目指します。
