# 人類のMCP 2025H1マイルストーンの解析

Anthropic MCP は、ロードマップを 2025 の初期にリリースしました。 [https://modelcontextprotocol.io/development/roadmap#roadmap](https://modelcontextprotocol.io/development/roadmap#roadmap).

エージェント通信プロトコルを調査し、MCPに細心の注意を払っていただき、またコミュニティへの提案の一部を提出しました。

今回は、MCPの理解に基づき、公式のマイルストーンを分析し、MCPやエージェント通信プロトコルに関するご意見を共有します。

この記事の主なポイントは次のとおりです。

- リモートサーバのサポート とても大切です。 リモートサーバのサポートの中で、認証スキームの対応は最も重要な側面です。
- 利用しきい値の低下。 MCP の現在の使用率が高すぎます。一般的に、特定の開発背景を効果的に使用する必要があります。
- コミュニティと基準 今後、業界標準となるMCPが取り組んでまいります。


## マイルストーン分析

### リモートMCPサポート

以前の記事では、MCPのリモートデータアクセスサポートが欠如していることを言及しました。これは重要な欠陥です。包括的なアイデンティティ認証スキームがないことです。

コミュニティがこの問題を認識したのは、最初のマイルストーンがリモートMCP接続をサポートし、認証と認可を主力として認識しているからです。

現在、OAuth 2.0 を用いたアイデンティティ認証のレビューでは提案しています。 コミュニティのメンテナーとコミュニケーションをとり、OAuth 2.0の標準化と普及の活用に最も役立つアプローチであると考えております。

この提案のベストアスペクトは、OAuth 2.0 を標準プロセスとして扱い、プラグイン可能な認証スキームを提案するものです。 これにより、他の認証方法は、仕様の柔軟性と開放性を大幅に高める実験ソリューションとして仕様に組み込まれることができます。

本提案に基づき、W3C DIDベース認証スキーム(W3C DIDベース認証方式)を開発https://github.com/agent-network-protocol/AgentNetworkProtocol/blob/main/03-did%3Awba%20Method%20Design%20Specification.md), プラグ可能なスキームをPRを送信する前にマージするのを待ってください。 W3C DID認証とOAuth 2.0の違いについては、この記事を参照してください。 [エージェントの最も適したアイデンティティ認証技術: OpenID Connect、API キーを比較し、次のようにしました。](https://github.com/agent-network-protocol/AgentNetworkProtocol/blob/main/blogs/Comparison%20of%20did%3Awba%20with%20OpenID%20Connect%20and%20API%20keys.md)

リモートMCP対応の他の2つの項目は、次のとおりです。

- サービス説明を含んだサービス発見。 MCP クライアントがインターフェイスを呼び出して、好みのサーバーを見つけることができる OpenAI の GPTs に類似した製品を開発する可能性があります。
- サーバ開発の複雑性を主に減らすために、ステートレスな操作。

### 流通・ディスカバリー

第三マイルストーンですが、第二のマイルよりも重要だと思い浮かび上がっています。

MCPの最大の現状問題は、その不安定な問題です。 MCPの機能は、非常に強く、LLMと対話する強力な手段を提供する一方で、OpenAIのGPTと比較して、その使いやすさはGPTsの背後まで遅れます。 現在、開発やコンピューターの専門知識を持たせて、様々なソフトウェアやサービスをインストールする必要があります。 これにより、MCP の使用に参入する障壁が大幅に上昇します。

このマイルストーンの4つのコンポーネント - パッケージ管理、インストールツール、サンドボックス作成、サーバー登録 - 確かにMCPをよりユーザーフレンドリーにすることができます。

ビジョンでは、MCPが普及するためには、使用障壁を下げる必要があります。 そのためには、コミュニティエコシステムと相互作用する必要があります。ブラウザプラグインと同様のメカニズムを必要とし、ユーザーはさまざまなMCPサーバーを簡単にロードできます。 こうした4つのコンポーネントは、この目標に向かって動くように見えます。

また、ユーザビリティの向上のため、リモートMCPサーバーの割合が増加しなければなりません。 遠隔で行なうことができることは、ローカルでは行かない。 リモートサーバが重要な理由は、もうひとつです。

### エージェントサポート

レイヤードエージェントシステム、インタラクティブワークフロー、ストリーミング結果の3つの項目があります。 コミュニティの議論が少なく、最後の項目を除いては、まだ他の2つを十分に理解していない領域です。 今後も監視を続けていきますが、このエリアに良いインサイトがあれば、コメントは無料でお願いします。

### より公式エコシステム

MCP は、現在、メインメンテナーが Anthropic 開発者であるにもかかわらず、コミュニティ主導の標準的な開発を期待しています。 これらは、すべてのAIプロバイダが同じ参加と共有ガバナンスを通じてオープンスタンダードにMCPを形づけるのを助けることができる共同エコシステムの構築を目指しています。さまざまなAIアプリケーションのニーズやユースケースを確実に満たします。 標準化機関と連携し、標準化を進めるのも期待しています。

業界標準の確立と共通慣行です。 現在、MCPコミュニティは、提案レビューを含むAnthropicによって主に主導されています。 パートナーの拡大や単価優位希釈など、より広範な採用を支援します。 これからも、このプロセスに深く関わっていきます。

## 未来のために必要とするプロトコルの何種類

エージェントが将来的に通信するための標準的なプロトコルを必要とするかどうかは、もはや不安定ではないようです。 最近、テナートテクノロジーAI未来の記事で述べたように、人々は徐々にその必需品を見てきました([AIがコーヒーを注文するのに役立つとき、アプリは同意しますか?](https://mp.weixin.qq.com/s/vRSn0jKRwGa-Ut6G5keD8w)).. 業界関係者との会話で、コンセンサスになるという点がわかりました。

不確実なままのことは、将来に必要なプロトコルと業界への受け入れを得る方法です。

今後のプロトコルの概略について、私たちは考えています([エージェントのWebを異なるものにする](https://github.com/agent-network-protocol/AgentNetworkProtocol/blob/main/blogs/What-Makes-Agentic-Web-Different.md)).. 弊社では、理想のエージェント通信プロトコル、AgentNetworkProtocol(ANP)を設計し、以下の取り組みを行っています。 [https://github.com/agent-network-protocol/AgentNetworkProtocol](https://github.com/agent-network-protocol/AgentNetworkProtocol).

将来のエージェントは相互接続されなければならないと確信しています。, 基礎的なデータ(APIまたはプロトコル)を介してインターネットとの通信, そして等しい存在として存在します. ANP設計のコア原則です。

ANPとMCPの最大の違いは、世界観に立ち向かう:
- MCPは、インターネット全体がコンテキストとツールとして機能するモデル中心です。
- エージェント・ネットワーク・プロトコルは、各エージェントが同じステータスを持ち、分散型のエージェント・コラボレーション・ネットワークを形成するエージェント・セントリックです。

弊社では、MCP から少し違ったパスをとり、成功するかどうか、業界の可能性を探りたいと考えています。
