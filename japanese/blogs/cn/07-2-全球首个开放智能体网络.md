# AIはもう孤島ではない：一つのプロトコルで世界のエージェントをつなぐ

## アプリの孤島に別れを告げ、AIを前提とするインターネットへ

次の場面を想像してください。

**この20年、私たちはこうしてきました。**
上海に行きたい時、ブラウザーで案内を探し、天気アプリで調べ、Ctripでホテルを予約し、12306で高速鉄道を買います。アプリを行き来して、コピーと貼り付けを繰り返します。

**エージェントネットワークの未来では、こう変わります。**
「来週の上海旅行を計画して」と、AI助手に言うだけです。アプリを一つもダウンロードさせず、裏で次を行います。
- 天気エージェントに尋ね、週末が晴れだと確かめます。
- ホテルエージェントで、外灘の川の見える部屋を押さえます。
- 高速鉄道エージェントにつなぎ、切符を買います。

数秒で終わります。

SFではなく、**Open Agent Networkが実現しつつある現在**です。

---

## なぜ今日のAIは、まだ孤島なのか

大規模モデルという賢い頭脳や、ChatGPT、Claude、Gemini、豆包、千問、kimiなどの巨大な入り口を目指す助手があります。

しかし、**AIは強くても、インターネットが弱すぎる**という共通の現実があります。

1. **閉じたプラットフォーム**：別の場所のアプリを呼べません。
2. **分断されたサービス**：アプリの壁を越えて、予約や料理の注文ができません。
3. **ばらばらの身元**：人にもAIにも、各所で別のアカウントが必要です。

**超知能があっても、話し相手としてしか使えない原因です。**

# 開かれたエージェントネットワークの三つの能力

OANは、ANPのような公開プロトコルで、三つの基本能力を提供します。

## ① 自由な発見（Discovery）

サイトのように、各エージェントがドメインという入り口を持ち、誰でも相手を見つけられます。

## ② 自己記述（Description）

Agent Descriptionという説明書で、自分が誰で、何ができ、どのインターフェースを提供するかを示します。

## ③ 双方向のやり取り（Interaction）

自然言語でも、OpenAPIやJSON-RPCの構造化した方法でも、互いの機能を呼べます。

すべての通信は、ANPのDIDのような分散型の身元の仕組みで、暗号化と本人確認を行います。

- 各所の登録は不要で、一つのアカウントで通用します。
- プラットフォームを越えた呼び出しと、全体の相互接続を実現します。

**AIにとってのHTTP誕生の瞬間です。**

---

## 解決策：OANとは

私たちは、この問題を破るため、**世界初の開かれたエージェントネットワーク**を作りました。

**HTTPがページをつないでWebを作ったように、ANPで世界のエージェントをつなぎ、AI時代のインターネットを作ります。**

### 三つの大きな変化

1. **サービスへの自由な接続**：需要側の助手が、ホテル、飲食、教育などの供給側に直接接続し、問い合わせから取引まで進めます。
2. **相互の協働**：予定助手が健康助手に、最近疲れていると伝え、重要でない会議を自動で断れます。
3. **誰でも参加**：企業でも個人でも、プロトコルに対応すれば参加できます。

> **開発者には**：一度作れば、世界のエージェントとつながります（Write Once, Connect Everyone）。
> **利用者には**：一つの助手ですべてのサービスへ（One Agent, All Services）。

## なぜプラットフォームではなく、プロトコルなのか

既存のAgentプラットフォームとの最大の違いです。

「自社のSDKを、自社の場所と規則で使って」というのは、App Storeのようなプラットフォームの発想です。

「PythonでもGoでも、AWSでも手元のパソコンでも、共通の言葉で話せばつながる」というのが、Webのようなプロトコルの発想です。

- **プラットフォームは、借地に建てる家**：家賃や規則が変わっても、抵抗できません。
- **プロトコルは、土地を手に入れて建てる家**：エージェントは、常に自分のものです。

**ANPの中心的な考え**：
- 🔓 **囲い込みを拒む**：一社や一つの場所に依存しません。
- 🚀 **技術を問わない**：LangChain、AutoGPT、独自構造のどれでも構いません。
- 🤝 **生態系を育てる**：プロトコルは基盤であり、その上でアプリが自由に育ちます。

## なぜANPか

ANPは、**インターネットでの協働**専用に生まれた、世界初の公開プロトコルです。

**最大の違いは、身元です。**

DIDによって、電子メールのような自由を与えます。
- **壁を破る**：相手の事業者を問わず、直接話せます。
- **相互運用**：繰り返し登録せず、一つのIDを全体で使えます。

ほかの多くはローカルネットワークの中にとどまりますが、ANPは本当の**インターネット**へ出します。

## 単純な構造：どう動くか

複雑な実装を理解する必要はありません。**接続層**が三つの能力を与え、人のような交流を可能にします。

```
┌─────────────────────────────────────────────────────────────┐
│                        供给侧 (Supply Side)                   │
│  酒店智能体 | 餐饮智能体 | 教育/娱乐智能体 | ViNote ...       │
└─────────────────────────────────────────────────────────────┘
                            ↕
┌─────────────────────────────────────────────────────────────┐
│              连接层 (Connection Layer)                        │
│  1. 发现 (Discovery)  2. 描述 (Description)  3. 身份 (Identity) │
└─────────────────────────────────────────────────────────────┘
                            ↕
┌─────────────────────────────────────────────────────────────┐
│                       需求侧 (Demand Side)                    │
│  个人助手 | 垂直智能体 | AI应用 ...                           │
└─────────────────────────────────────────────────────────────┘
```

### 接続層の三つの道具

1. **発見（Discovery）**：ブラウザーがサイトを見つけるように、標準の仕組みで互いを発見します。
2. **記述（Description）**：標準の説明書で、能力と呼び出し方を自動で理解し、人手の接続作業を不要にします。
3. **身元（Identity）**：最も重要です。DIDは、世界で通用するデジタル身分証に当たります。各所の登録が不要で、一つの身元を全体で使い、**完全に自分で制御できます**。

## 実例：3時間で、道具からネットワークの一員へ

**ViNote**は、動画をノートやマインドマップにするAIツールです。元々、使いやすいSaaSを目指していました。

ANP SDKを導入すると、**わずか3時間で**、独立アプリから**ネットワークのノード**に変わりました。

- **以前**：利用者はViNoteのサイトを開く必要がありました。
- **今**：教育エージェントが授業動画を復習資料にして学生に送り、制作エージェントが素材から印象的な言葉を抽出して記事を書けます。

**作り手は、全体のエージェントから瞬時に利用者と呼び出しを得られるとは、考えていませんでした。**
これが、**接続が価値を増やす**ということです。

## 今、何を作っているか

始まったばかりのネットワークに、さらに多くの部品を公開しようとしています。

### 1. 決済（Agent Payment）

AP2で財布を与え、提供者がAPI呼び出しから直接収益を得られるようにします。商業的な循環を完成させる、不可欠な基盤です。

### 2. 即時通信（Agent Instant Messaging）

機能を呼ぶだけでなく、人がWeChatで話すように、異なる場所のエージェントがグループで話し、協働し、共有できます。

### 3. 複数プロトコルのゲートウェイ

ANPに加え、次との互換性をゲートウェイで提供します。
- **MCP**：Anthropic
- **A2A**：Google
- **ACP**：OpenAI/Stripeの商取引

**MCPエージェントは、ブリッジでワンクリック接続できます。**
