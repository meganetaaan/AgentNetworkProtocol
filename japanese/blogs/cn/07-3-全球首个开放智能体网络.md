# **AI インターネットが誕生します: 未来を書き換えるオープン エージェント ネットワーク**

ChatGPT が初めて登場したとき、誰もがさまざまなシナリオを想像しました。

たとえば、AI アシスタントに次のように言うだけです: ** 「来週の上海への旅行の手配を手伝ってください。」 **

クリックするために大量のアプリがポップアップ表示されることはありませんし、追加のアカウントの登録を要求されることもありません。
バックグラウンドで静かに動作し、すべてを実行します。

- 気象局に確認したところ、週末は旅行に適していることが確認されました。
- 外灘のリバービュールームはホテルのシステムにロックされています
- 鉄道インターフェースから適切な列車番号を取得し、予約を完了します

数秒後、完全な旅行計画があなたの目の前に静かに現れます。

過去 3 年間、世界のテクノロジー界は、ChatGPT、Gemini、Kimi、Doubao、Quark、Qianwen、Lingguang などの「スーパー アシスタント」を生み出してきました。

モデルの機能は飛躍的に進歩していますが、それぞれの生態系では限界があります。

- クロスプラットフォームのデータは相互に参照できません
- 商用サービス間の相互運用が困難
- 異なるエージェント間で連携するのが難しい

つまり、**AI は強力ですが、依然として「今日のインターネットの構造」に制約されているということです。 **

これらの制約を解くために、私たちは一連の ** エージェント プロトコル ** を設計し、このプロトコルの上に新しいネットワークを構築しました—
** を使用すると、あらゆるインテリジェント エージェントが相互に接続、共同作業、およびトランザクションの完了を行うことができます。 **

HTTP 対応の Web ページが相互にアクセスできるように、このネットワークにより、最終的には世界中のインテリジェント エージェントが自由に移動し、相互に会話し、真の価値を生み出すことができるようになることを願っています。



# ** オープン エージェント ネットワークとは何ですか?一文ではっきりと話してください**

**オープン エージェント ネットワーク = 一連のプロトコル + ネットワーク。これにより、任意のエージェントがプロトコルを使用して相互に接続できるようになります。 **

簡単に言えば:

* ** 開発者 **: たった 1 回の開発で、エージェントは世界中のすべてのサービスに接続できます
* **ユーザー **: たった 1 人のアシスタントで、インターネット全体のサービスにアクセスできます
* **エンタープライズ**: 企業の1つの展開およびスマートなsは世界中すべてのユーザーに役立つことができます

「AIインターネット」の第一号機です。

# **なぜAIは、このネットワークを必要としているのか?3つの基本的な痛み。**

**1. . 人工知能は理解が良く、接続しないで自然に良いです。**

現在のAIは、あなたの意味を理解していますが、インターネット(ホテル、天気、輸送、教育)の実際のサービスに直接アクセスしていない。

素晴らしい脳ですが、「手足」が欠けています。

**2. . アプリおよびプラットフォームで封印されたサービス**

旅行、支払い、医療、教育...さまざまなアプリ、異なるプラットフォームや企業でカットされています。

AI、呼び出し、ジャンプし、登録し、登りを逆転させる、プライベートAPI...
自動化は全くありません。

**3. . 人工知能は、互いに機能しない。**

アシスタントがホテルをチェックインしましたが、他のアシスタントは対応できませんでした。
友達のアシスタントと調整できないグループです。
顧客のサービスインテリジェンスと接続することはできません。

島のようなAIは、AIの能力を制限し、機能する。

# **オープンソースネットワークの3層構造**

スマートネットワークを開くと3つのレイヤーで、ネットワークの抽象化です。

![3層構造](../../../blogs/images/agent-network/network-architecture.png)

1. 要求の側面
パーソナルヘルパー、縦型アシスタント、AIアプリケーションを含む。
ユーザーの意思を理解し、ネットワークへの要求を開始する責任があります。
最終的な実現:**ネットワーク全体でポータル。**

2. レイヤーの接続
インテリジェントな組織は、インテリジェントな組織が検出可能で、理解しやすい、信頼できる接続性を発揮します。
プラットフォームではありません。彼らはプラットフォームです。**プロトコル駆動型接続レイヤー**。

3. 供給の側面
スマートな身体は、ホテル、レストラン、教育、エンターテインメントなどのサービスを提供します。
最終的な実現:**ワンアクセス、すべての利用可能な。**

# **誰がこのスマートウェブを所有していますか?**

**会社の1人、誰にも所属しません。**

ネットワーク プロトコルに基づいて構築されているため、プロトコル要件を満たすエージェントはすべてこのネットワークに参加できます。

使用しなければならないサービスや接続しなければならないシステムはありません。これがオープン性の基本的な意味です（もちろん、オープン性は法令の範囲内にあります）。

当社はネットワーク内でいくつかの接続インフラストラクチャ サービスを提供していますが、このサービスはどの企業でも構築でき、ネットワーク アクセスの要件ではありません。

# **なぜ「プラットフォーム」ではなく「プロトコル」ルートにこだわるのでしょうか? **

多くの企業が AI プラットフォーム、AI アプリケーション ストア、AI フレームワークを開発しています...
しかし、プラットフォームは「相互接続」の問題を解決することはできません。

## プラットフォーム = 囲まれた庭園

* そのルールに従って開発する必要があります
* はそのSDKを使用する必要があります
* ユーザーとデータをシステムにバインドする必要があります

## プロトコル = オープンハイウェイ

* 好きなように実装できます
* Python、JavaScript、Java をすべてサポート
* ローカル展開とクラウド展開は相互運用可能
* プラットフォームのロックなし、技術的な依存関係なし、権限制限なし

HTTP により、Web ページのインターネットが可能になります。
SMTP はグローバル メール システムを可能にします。

**私たちは、ANP (Agent Network Protocol) が「インテリジェント エージェントのインターネット」を実現できることを願っています。 **

# ** ANP が他のプロトコルよりも優先されるのはなぜですか? **

ANP は、**インターネット コラボレーション** のために特別に設計された世界初のオープンソース プロトコルです。

**他のプロトコルとの最大の違いは「アイデンティティ」です。 **

当社では、**DID (分散アイデンティティ) ** テクノロジーを使用しています。これにより、エージェントには **Email** と同じ自由度が与えられます。
*   **壁を壊す**: 相手がどのサービスプロバイダーを使用していても、直接本人確認をして通信できます。
*   **相互接続**: アカウント登録を繰り返す必要がなく、ネットワーク全体で 1 つの ID を使用できます。

他のプロトコルのほとんどは、インテリジェントな身体とAPPの間のアイデンティティ共有の問題を本当に解決しないし、実際にそれらを聞かせます。**ネットショップ**。

もちろん、将来的にはMCP、A2A、ANPなど、あらゆる合意をサポートするインテリジェントな人物とのアクセスとコラボレーションをしたいと思っています。

# スマートネットワークへのアクセス方法

主にAPPとMCP-to-AMPブリッジの2つのアクセス方法を提供します。

**ANP の第一次アクセス**AMP SDK への直接アクセスは、双方向通信機能をサポートし、より機能的なサポートを実現します。

**MCP-to-ANPブリッジアクセス**: MCP を達成したスマートでは、MCP-to-AMP 用のブリッジプログラムを提供しています。スマートが MCP をサポートしている限り、コードを変更することなく 1 つのキーでスマートネットワークにアクセスすることができます。

![交通アクセス](../../../blogs/images/agent-network/integration.png)

## **ViNote ケース: 3 時間経過したアクセスの実例**

ViNote はビデオノートブックツールです。
ビデオの要約、字幕のダウンロード、マインドマップ、勉強カード...

従来のモードでは、独自のアプリユーザーのみが機能します。
しかし、ANPへのアクセス後、その1つになりました。**どのスマートボディによって適応することができるビデオ理解ノード、**。

たとえば:

* 個人的な助けは、Vicnoteがビデオをメモに変えることを可能にします。
* 教育インテリジェンスにより、VicNoteは構造化されたコンテンツを生成することができます。
* コンテンツ作成インテリジェンスにより、VicNote は記事から素材を抽出することができます。

**開発者は3時間でのみアクセスを完了します。**
ツールからネットワークノードへ。

これは、オープン合意の力です。**そこで、「Web全体にスマートにサービスを提供し、ネット全体に接続します」を取得できます。**

# そこで、スマートネットワークにアクセスしましょう。どうすればよいですか?

宅配便、列車のチケット、フライトチェック、ホテルの予約やアトラクション、マップ検索、ビデオバイビデオアクセスのためのツールなど、現在のネットワークで既に多くの機能が利用できます。

C 側のアプリケーションまたはエージェントを開発している場合は、エージェント ネットワークを使用してアプリケーションに上記の機能を提供できます。

同時に、サービス エージェントの開発者の場合は、サービスをエージェント ネットワークに接続して、より多くの C 側エージェントがサービスを呼び出すことができます。

# 開発者がエージェントネットワークでお金を稼ぐ方法

つながりやコラボレーションが最終的な目標ではなく、最終的な目標は価値を生み出すことです。

エージェント ネットワークを構築する際の私たちの目標は、ユーザーが収益を上げられるようにすることです。

したがって、AP2、X402、その他のプロトコルのサポートなど、インテリジェントな支払いインフラストラクチャを検討しています。

当社は、ネットワークに ANP+AP2 の組み合わせを実装しました。これは、ホテルの予約など、エージェント間の大規模なトランザクションに非常に適しています。

また、X402 プロトコルもサポートしています。これは、ビデオ ツール エージェントや金融サービス エージェントへの通話など、エージェント間の小規模なトランザクションに非常に適しています。

私たちは単にインテリジェント エージェント ネットワークを構築しているだけではなく、オープンなインテリジェント エージェント ビジネス エコシステムを構築しています。

# **未来は加速しています: 私たちは完全なインテリジェンスのインターネットを構築しています**

## **① スマートペイメント（AP2、X402プロトコル）**

エージェントは人間と同じように瞬時に相互に通信できます。

* あなたのアシスタントと友達のアシスタントがパーティーを自動的に調整します
* エンタープライズ カスタマー サービス エージェントのクロスプラットフォーム ハンドオーバー
* マルチエージェントチームが協力してタスクを完了します

将来的には、異なる会社のエージェントが相互に IM を送信し、グループ チャットを形成できるようになります。
