# 世界初のスマート決済実装: ANP、スマート ビジネス エコシステムの重要なステップとなる AP2 決済実装をリリース

2025 年 9 月、Google は AP2 (Agent Payment Protocol) プロトコルをリリースし、インテリジェントなエージェント支払いシナリオのための一連のオープン スタンダードを提供しました。しかし、この協定が発表されて以来、業界では成熟した導入事例はありません。

本日、私たちは正式に発表します: **ANP (エージェント ネットワーク プロトコル) オープン ソース コミュニティと杭州ベクトル コンセンサスが、AP2 プロトコル ** の最初の実装を完了し、インテリジェント ビジネス エコシステムに使用可能な支払いインフラストラクチャを提供しました。

これは、AP2 をサポートするように作成した製品の例です。

AP2 プロトコルによって解決される最大の問題は、インテリジェント エージェントのトランザクション プロセスにおける信頼の問題です。アリババが電子商取引における信頼の問題を初めて解決し、ユーザーがコンピュータ上で見慣れない販売者にあえて支払うことを可能にしたのと同じです。 AP2 が解決したいのは、AI に安心して買い物を任せられるようにすることです。何か問題が発生した場合は、適切な責任者を見つけることもできるため、信頼を構築し、取引の摩擦コストを削減できます。

私たちは、AP2 が過小評価されているプロトコルであり、将来ビジネス リンク全体を再構築する可能性があると考えています。そのため、ANP で AP2 をサポートしています。

下位レベルのプロトコルとして、ANP はエージェント ID スキームとして DID を使用します。これは当然、AP2 の公開キー配布問題を完全にサポートします。 ANP で AP2 を実行することは、A2A で AP2 を実行するよりもはるかに簡単です。

非常に初期のプロトコルである AP2 にも多くの不完全性があります。 ANP に基づいて、中国の決済インフラストラクチャのサポート、パフォーマンス バウチャーの追加、タイムスタンプ検証の改善など、AP2 にいくつかの改善を加えました。これは、インテリジェント エージェント ビジネス エコシステムの重要なステップである「会話できる」エージェントから「取引できる」エージェントへの進化を促進する、業界への当社の探索と貢献の一部とみなすことができます。

この記事では、インテリジェントな支払い、AP2 プロトコル設計、および ANP ベースの実装ソリューションの中核となる概念を詳細に分析します。最後に、x402 のサポートやスマート ペイメントのさらなる探求の計画など、将来の計画を紹介します。

AMP オープンソースコミュニティと杭州ベクトル合意、スマートインターネットのアクティブなエクスプローラは、スマートボディプロトコルに基づくグローバルベースで先週(参照記事)に最初のオープンインテリジェントなボディネットワークを立ち上げました [世界で初めてオープンしたスマートボディネットワーク](07-3-全球首个开放智能体网络.md)オープンソースのスマートビジネスインフラをさらに改良。オープンなスマートボディネットワークをベースにした。

スマートボディの開発、スマート人材の支払い、スマートビジネスの活用に興味を持つ方全員が参加できます。今後はさらなる機能を追加し、スマートボディのハッキングも行います。

## スマートペイとは?

### 伝統の支払いとの違いの性質

スマートペイについて話すとき、それは「AIがあなたに支払う」だけでなく、取引パラダイムの根本的なシフトを表しています。

**オートメーションの異なる程度**従来の支払いは、商品の選択、注文の確認、パスワードの記入項目、および支払の各点で手動介入を必要とします。スマートボディ決済は、重要なポイント(例えば大規模な支払い)がまだ明確な人間の許可を必要としているにもかかわらず、インテリジェントな人々によってプロセスの大部分を遂行することができます。

**取引は粒度が異なります。**従来の決済システムは「人」のために設計され、最小取引ユニットは通常数セントです。しかし、インテリジェントな世界はより細かい穀物でマイクロペイメントシナリオをサポートする必要があります - サブコールAPI、自分のレートでリソースを購入する、秒単位でサービスを購入します。

**信頼のメカニズムは異なります。**従来の決済は、ユーザーとトレーダーがトランザクション全体を完了する単一のプラットフォーム(ブレッド、JD、およびアメリカングループ)からの承認に依存します。 しかし、スマートボディネットワークでは、ユーザーの知能やビジネスインテリジェンスは異なる企業にオープンし、クロスドメインの信頼メカニズムを必要とするかもしれません。

**相互モードは別のです**従来の支払いは、人的エンジンの相互作用であり、人々は主要な意思決定者です。スマートペイは機械に-エージェントされ、2つのスマートは人工介入なしで信頼できる価値交換を行う必要があります。

### スマートベースの決済のコア課題

ユーザーがビジネスインテリジェンスで製品を買いるためにショッピングインテリジェンスを使用する特定のプロセスに戻り、スマートペイのコア課題は次のとおりです。

- 人が買い物の知能を信頼して、自分の意思の100%を行うにはどうすればよいですか?
- ショッピングインテリジェンスがビジネスインテリジェンスを信頼する方法は?
- 商人の知能が、人々の意志を表すショッピングインテリジェンスを信頼する方法は?

AP2の合意は、これらの課題に取り組むために作成されました。

営業部**スマートコマース**AI の電気事業者よりも、よりネイティブなコンセプトです。E コマース + AI だけでなく、AI による電子商取引は電力を有効化しますが、スマート・ウェイトベースのビジネス取引リンクではなく、

ビジネスは、基本的に価値交換です。信頼を優先します。 アリの eコマースへの最大の貢献は、人々が画面の後ろに商人を信頼し、請求書を支払いたいという問題を解決することです。

スマートボディビジネスの時代には、信頼はまだ問題です。スマートでスマートな信頼とどのように賢い信頼をスマートに信頼する方法。

しかし、GoogleAP2プロトコルは、スマート取引における信頼の問題に対処するように設計されています。

## AAP2プロトコルの解像度

### AP2とは?

AP2(エージェント決済プロトコル)は、スマートボディの支払いを目的として設計された、9月2025日にGoogleが発行するオープンドア契約です。[https://ap2-protocol.org/](https://ap2-protocol.org/)

以下は、当社の特別カバレッジグローバルボイスオンラインの一部です。[Googleスマートペイ契約AP2の深さ解釈: 厳重に根本的な合意](04-深度解读谷歌最新发布的AP2.md)

AP2のコア目的は明確です。**スマートディーリングにおける信頼の確保**。

### AP2の4つのコアロール

AP2は、支払いシナリオで4つのコアロールを定義します。

**買い物客エージェント (SA) **: 購入者/消費者を表します。ユーザーと対話し、注文情報を表示し、ユーザーの支払い承認を取得し、ユーザーに代わって取引を完了する責任があります。

**Merchant Agent (MA) **: 販売者/サービスプロバイダーを表します。ショッピング カート情報の生成、注文の作成、支払いの処理、そして最終的に配送伝票の発行を担当します。

**認証情報プロバイダー (CP) **: ユーザー ID 認証情報を提供します。ユーザー ID 認証と認可署名の生成を担当し、支払い操作がユーザーによって真に認可されていることを確認します。

**Payment Processor (PP) **: 実際の支払い操作を処理します。基礎となる支払いチャネル (Alipay、WeChat Pay、銀行カードなど) に接続して、実際の資金移動を完了します。

最小限の実装では、買い物客エージェントが CP と PP の機能を同時に引き受けることができ、システム アーキテクチャが簡素化されます。

### AP2 の 2 つの主要な認証情報

AP2 の微妙な点は、完全な信頼チェーンを形成するために 2 つの主要な認証情報を定義していることです。

**CartMandate (ショッピングカートの承認) **: 販売代理店によって生成され、注文の詳細、製品情報、合計金額、支払い方法が含まれます。販売者は、注文情報の整合性を確保するために独自の秘密鍵で署名します。これは商人が発行する「見積書」のようなもので、「この商品とこの価格を受け入れます」と約束するものです。

**PaymentMandate (支払い承認) **: 買い物客エージェントによって生成され、特定の注文に対するユーザーの支払い承認が含まれます。ユーザーは自分の秘密キーを使用して署名し、認可の信頼性を保証します。重要なのは、以前の CartMandate のハッシュ値が含まれており、ハッシュ チェーンを形成していることです。この承認は、その見積を明確に示しており、他のトランザクションに悪用されることはありません。

## ANP は AP2 をどのようにサポートしますか?

AP2 プロトコルをサポートする過程で、次の 3 つの興味深いことがわかりました。
- AP2 自体はまだ初期段階にあり、タイムスタンプ検証メカニズムなどのプロトコル設計はまだ完成していません。
-  実行できる完全なコードはありません。コードとプロトコルの間にはいくつかの不一致があります。
- 検証可能な資格情報は AP2 の中核ですが、署名秘密鍵に対応する公開鍵をどのように配布するかは AP2 が答えていない問題です。

### 重要な変更点

AAP2 の課題を、ANP に基づく現状で解決するコアな変更をいくつか行なっています。

- ANP インタラクティブなプロセスで AP2 をサポートし、複数のメッセージで ap2 として送信された証明書を使用するように設計しました。

- 宝物やマイクロトラストの支払いなど、中国での決済インフラをサポート。現在、プラットフォーム間で支払う最も便利な方法である2次元決済のサポートの最前線にいます。

- ARPベースのスマート・アイデンティティ・プログラム(DD)は、AP2の検証可能な文書の配布のための公開鍵です。AP2はAIPインターネットの考え方と一貫しており、将来の知能機関が接続および取引できると信じています。しかし、A2Aは、AMPのDIDプログラムがAP2を配信するための非常に便利な公共キーである一方で、インテリジェントな相互運用性の問題は解決しません。

- タイムスタンプ、支払い、証明書の配送などAP2で考慮されないポイントの改善。

これらの修正は、AP2 が APP 合意に上陸させることを可能にします。

### 取引プロセス

ANP/AP2 の完全トランザクション処理は、4 つのフェーズに分けられます。

[Anp-ap2 フローチャート](../../../blogs/images/anp-ap2/ap2flow.png)

**フェーズI:注文の作成**

ショッピングスマート(SA)とSA(SA)による購入リクエストの開始、ビジネススマート(MA)への送信`create_cart_mandate`リクエスト。 MAは注文を作成し、合計価格を計算し、2-Dコードを支払い、そしてCartMandateを返すために独自の秘密鍵で署名します(2-Dコードを含む)。

このステップのキーは...**業務上のこだわり**カルトマンデテは、事業によって署名された、法的に有効なオファーであり、その後、ビジネスが拒否できない。

**第II相:支払いの承認**

SAは、注文情報とビジネスの決済コード2Dでユーザーを表示します。一方、SAはPaymentMandate(ユーザ認証署名とフロントラインカートマンデートによる橋値カート)を生成します。_ハッシュ)、MAに送信され、MAは確認します。

決済完了後、Payer(PP)はコールバックによる支払い結果MAを通知します。

このステップの鍵は、**二重結合**: PaymentMandate は、ハッシュ チェーンを通じて特定の CartMandate を明確にポイントしています。ユーザーのスキャン コード支払いアクションはユーザー自身によって完了され、エージェントはユーザーの支払いパスワードに触れません。

**フェーズ 3: 配送伝票**

MA は支払い成功通知を受信すると、支払い確認伝票 (PaymentReceipt) を SA に送信します。 SAは決済結果を利用者に通知します。

その後、MA は注文の履行 (配送) を完了し、物流状況伝票 (FulfillmentReceipt) を SA に送信します。 SAは物流状況をユーザーに通知します。

このステップの鍵は、**伝票のアーカイブ** です。完全な伝票チェーンは、起こり得る紛争に対する証拠のサポートを提供します。支払い伝票とパフォーマンス伝票の両方に、事前注文の PaymentMandate のハッシュ値が含まれており、完全なトレーサビリティ チェーンを形成します。

**特別な説明は**: 配送伝票部分は、AP2 プロトコルに基づいて追加された伝票です。ネイティブ AP2 プロトコルは支払いプロセスのみを処理し、支払い確認やパフォーマンス確認などのトランザクション プロセス全体をカバーしません。

これにより、後続のプロセスを効果的に追跡および検証できなくなります。たとえば、支払いが成功した後、販売者が注文に従って商品を配送したかどうか、または契約の履行後にユーザーが商品の受領を確認したかどうかなどです。これらの主要ノードは引き続きバウチャーによって確認する必要があります。


### ハッシュチェーンデザイン

ANP/AP2 のセキュリティ基盤はハッシュ チェーンです。

```
CartMandate(cart_hash) → PaymentMandate(pmt_hash) → Receipt(cred_hash)
```

各ステップには前の伝票のハッシュ値が含まれており、トランザクション伝票の完全なチェーンを形成します。改ざんが行われるとハッシュ チェーンが破壊され、トランザクションを追跡して検証できるようになります。

この設計はブロックチェーンのアイデアを利用していますが、より軽量です - ** はネットワーク全体の合意を必要とせず、トランザクションの両当事者による検証のみを必要とします。 **

### 残りの問題

技術的には、AP2 プロトコルは、暗号化署名とハッシュ チェーンを通じてエージェント トランザクションの信頼性の問題を解決します。しかし、現実の世界では、検討する必要のある問題がまだいくつかあります。

**法的有効性の問題 **。取引紛争で仲裁が必要な場合、AP2 の証明書チェーンは有効な法的根拠として裁判所または仲裁機関に採用されますか?現在、電子署名に対する法的な認識は国によって異なります。 AP2のデジタル署名に法的効果があるかどうかについては、業界や法曹界で議論する必要がある。

**責任問題**。エージェントがトランザクション中にエラーを犯した場合（ユーザーの意図を誤解したり、間違った製品を選択したりするなど）、その責任はユーザー、エージェントの開発者、またはエージェントのオペレーティングプラットフォームにあるのでしょうか?既存の法的枠組みでは、「AIエージェントの行動」に対する責任の範囲が明確に定義されていない。

これらの質問に対する答えを得るには、技術コミュニティ、法律コミュニティ、規制当局による共同の調査が必要です。

しかし、インテリジェントなビジネスの発展に伴い、対応する法律、規制、業界標準も徐々に向上していくと考えています。

## x402 プロトコルの見通し

### x402プロトコルとは

x402 は、HTTP 402 ステータス コードに基づいて設計されたもう 1 つの注目すべきスマート ペイメント プロトコルです。

HTTP 402 Payment Required は、HTTP プロトコルの誕生以来存在する「予約済み」ステータス コードですが、広く使用されていません。 x402 プロトコルは、それに新たな命を与えます。エージェントが支払いを必要とする API にアクセスすると、サーバーは 402 ステータス コードと支払い情報を返します。エージェントは支払いを完了すると、サービスを再リクエストして取得します。

これは、マシンツーマシン (M2M) シナリオ向けに特別に設計された**インスタント マイクロペイメント**モードです。

### x402 をサポートする理由

AP2 は、ユーザーの確認が必要な明確な製品、数量、価格を伴う **注文タイプのトランザクション ** に適しています。しかし、エージェントの世界には依然として多数の **インスタント コール トランザクション** が存在しており、API を 1 回呼び出し、コンテンツにアクセスし、数秒間のコンピューティング リソースを使用します。

このタイプのシナリオの特徴は、少量、高頻度、即時対応の必要性です。ユーザーに毎回確認を求めるのは明らかに非現実的ですが、エージェントに完全に独自の判断をさせることはできません（リスクが高すぎます）。

x402 のソリューションは、支払い機能を HTTP プロトコル層に統合し、支払いを API 呼び出しの自然な部分にすることです。エージェントは、事前に設定された制限内でマイクロペイメントを独自に完了し、制限を超えた場合にユーザーの承認を要求できます。

私たちは、マイクロペイメントによって手動介入が大幅に削減され、支払いがよりきめ細かくなるため、エージェントのコラボレーションのコストが大幅に削減され、エージェントのコラボレーションの効率が向上すると考えています。

### 予想される実装計画

私たちは x402 サポートを ANP の HTTP トランスポート層に統合する予定ですが、これにはいくつかの大きな変更が必要です。

1 AP2バウチャーと同様のサポートを追加

402 合意の AAD 2 様の設計がない場合、特にポストセールスの問題が対処する必要がある場合は、取引を追跡し、検証することは困難になります。そのため、この問題を解決するために、AP2 文書を直接 402 で使用することを好む。

2. 支持の中国'sの支払インフラ

X402はもともと安定化通貨をサポートしましたが、国内のコンプライアンスでは利用できず、中国での決済インフラに変化する必要がありました。この作品を探求しています。良いアイデアや一緒に働く可能性があれば、弊社に連絡することができます。

## 未来展望

ANP/AP2 は、今後急速に進化する計画です。

**「人ではなくプレゼント」シーンを応援。**ユーザーが自分の買い物の意思や予算をプリセットし、自分の義務の制限内でビジネスを行うためにスマートにすることができます。 これは本当の「エージェントショッピング」です。

**プライバシーの強化**取引を完了するために必要な最低限の情報のみを取得することができる。

**支払の延長**宝物・マイクロ知性への支払いに加えて、さまざまなシナリオのニーズを満たすためにデジタルレンミニビなどの新しい決済方法を探ります。

**標準的な直線**. W3C VC規格と同等して、より広い相互運用性を実現。ANP/AP2 がシームレスにグローバル・インテリジェントに接続できるようにする。

## とりあえず...

今後はスマートビジネスではなく、変化が続く。

スマートボディが、安全に当社の代わりに支払いをすることができるとき、それはもはや単なるチャットロボットではなく、実際のデジタルエージェントであり、デジタル世界で価値を行動し、取引し、作成することができます。

ANP/AP2 のリリースは、「can Talk」から「can Trade」までのインテリジェンスの重要な飛躍をマークしました。

最初は、一緒にやりたい。
