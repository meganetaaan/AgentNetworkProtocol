# ANP プロトコルが生まれた年、コミュニティに感謝します: web3、Agora プロトコル、WebAgents、did:web

ANP オープンソース プロジェクトが構想され、開発されてからほぼ 1 年が経過しました。今年、私はエネルギーのほとんどをこのオープンソース プロジェクトに集中させました。昨年、私はアリババを退職し、フルタイムで専念しました。

ビジネスを始めるのは簡単ではありませんが、資金調達環境が非常に悪く、資金が得られない場合、オープンソース プロジェクトに固執するのはさらに困難です。ここで自分自身を褒めさせてください。 ** は 1 年前に未来を事前に見て、耐えることができました。 **

もちろん、私が耐えることができたのは、私に粘り強さがあったからではなく、その過程が楽しかったからです。それ自体は興味深いもので、オープンソース コミュニティの雰囲気や世界中の開発者とのコミュニケーションも相まって、この 1 年間の私の心身の状態は、アリババにいたときよりも良くなりました。 （財布だけが不満）

**興味のあることをやれば、それ自体があなたの体と心に栄養を与えてくれます。 **

今日は主に、ANP の誕生の全プロセスと、この過程で感謝したいコミュニティについて共有します。

最近、私たちが見ているインターネットの将来像が、ますます多くの人々に認識されつつあることがますます明らかになってきています。また、ますます肯定的なフィードバックを受け取るようになり、ますます多くのオープンソース愛好家や同業者がオープンソース コミュニティに参加してきました。

ANP は現時点では完璧とは言えません。私にはまだ完成して実行されるのを待っているアイデアや計画がたくさんあります。しかし、これはすでにインテリジェント エージェントの通信プロトコルにおいて重要な要素となっています。私たち ** は、技術的なルート (エージェント Web + 分散化 + セマンティック Web) ** を表しており、この技術的なルートでは、当社の探求は業界の最前線に立っています。

## 原点

ANP は、非常に小さな疑問から始まりました (私の元々の仕事はオーディオとビデオに密接に関連していました): ** の人々は、ビデオ会議にパーソナル アシスタントをどのように使用していますか? ** この疑問が頭の中にずっと残り、抑えられなかった時期がありました。

綿密な調査の結果、業界インテリジェンスの接続とコラボレーションには依然として大きな技術的ギャップがあることがわかりました。現在のテクノロジーでは、よりネイティブな接続方法を必要とするエージェントのニーズを満たすことができません。すべてのエージェントは相互接続でき、基礎となるデータと直接対話できます。

この方針に沿った正式な考え方と設計を経て、ANP プロトコルが誕生しました。

設計プロセス全体を通じて、ANP は大規模な再構築も行われ、他のコミュニティから優れたアイデアを吸収しました。

## web3

ANP に対する最初の大きな影響は、web3 コミュニティでした。

私は 2022 年に生きていました。私は個人データ主権の概念に強く同意していたので、空いた時間に Web3 を勉強し、多くの Web3 実践者と深く交流しました。

私は web3 コミュニティでブロックチェーン技術について学び、分散化の背後にある概念と技術について学び、その後 DID の概念と W3C の DID 標準に触れました。 Nostr、AT プロトコル、Lens プロトコルなど、非常に興味深いプロトコルも多数あります。

分散化は ANP の中核概念でもあります。私たちが追求しているのは、ブロックチェーンのような完全な分散化ではなく、インテリジェントなエージェント ID の相互運用性のための全体的な分散化と部分的な集中化のアイデアです。

W3C DID は、当社のエージェント ID の最下位レベルのテクノロジーでもあり、現時点でエージェント ID に最も適していると当社が考えるテクノロジーでもあります。

最後に、Web3 コミュニティについて話しましょう。

web3はお金に近く、ユーザーからは少し遠いですが、web2（従来のインターネット）とは全く異なる価値観、世界観、技術体系を持っており、そこがとても面白いです。

同時に、Web3 コミュニティの雰囲気も非常にオープンです。私は web3 のビルダー文化がとても好きです。 DAOの組織方法やトークンのインセンティブの仕組みもあります。これらは非常に興味深いもので、私の ANP の設計に多くの影響とインスピレーションを与えてくれます。

## アゴラプロトコル

2 番目に感謝したいのは、Agora Protocol です。

Agora Protocol は、オックスフォード大学と Camel AI のチームによって開発されたメタプロトコル テクノロジであり、エージェント間の合意の交渉に使用できます。

私は契約関連の仕事に携わっていたので、AIが契約交渉や共同デバッグに与える影響については以前から知っていましたが、体系的に研究したことはありませんでした。

Agora プロトコルに触発され、さらに深く考えた結果、アイデンティティと暗号化層、メタプロトコル層、アプリケーション プロトコル層という ANP の 3 層アーキテクチャ設計を正式に形成しました。

この 3 層アーキテクチャは今日まで使用されており、常に補足および改善されています。

メタプロトコル層の実装に関する主な参考資料は Agora プロトコルの論文であり、通信プロトコルの経験に基づいてエンジニアリングの最適化を行っています。

その後、アゴラ プロトコルの著者であるオックスフォード大学のスマーロ氏と、キャメル AI の創設者である李国豪氏と、インテリジェント エージェントの通信プロトコルに関する技術交流を行いました。最近、smarro はインテリジェント エージェント通信プロトコルの標準化に特化したワーキング グループの設立を主導し、私たちは主要な参加者の 1 つです。

## Webエージェント

3 人目に感謝すべき人は WebAgents です。

WebAgents は、コミュニティの海外クラスメートである James から勧められました。

WebAgents は、主にセマンティック Web テクノロジーに基づいて、Web ベースのマルチエージェント システム (MAS) を構築します。私は WebAgents コミュニティに関する多くの情報、特に会議議事録を読み、セマンティック Web について多くのヒントを得ました。

次に、セマンティック Web の起源、特に World Wide Web の発明者ティム バーナーズ リーによるセマンティック Web に関する記事と、json-ld、rdf、owl などのセマンティック Web に関連する標準を体系的に学びました。

セマンティック Web は非常に興味深い概念です。 2001 年に Scientific American に掲載されたセマンティック Web に関する Tim Berners-Lee の記事を読んだことがある人なら、彼が非常に先見の明のある人であると間違いなく感じるでしょう。そこに描かれている光景は、まさに現在、知的エージェントの普及後に私たちが思い描く光景そのものだ。

しかし、セマンティック Web は、以前の AI の技術レベルの制限により、データ アノテーションという技術的な道を選択しており、セマンティック Web が思い描く美しいシナリオを真に実現できない運命にあります。その後、インターネットはよりクローズドなモバイル インターネット時代に移行しました。

しかし、セマンティック Web から残された技術は、エージェント間のコミュニケーションに非常にうまく使用できると思います。これにより、さまざまなエージェントが事前定義されたセマンティクスを通じてデータを一貫して理解できるようになります。これにより、自然言語コミュニケーションを使用するエージェントのあいまいさの問題を十分に解決できます。

これは、エージェント記述プロトコルにおけるコアテクノロジーの選択でもあります。

## やった:ウェブ

4人目に感謝したいのはdid:webさんです。

Did:web は、W3C の DID のメソッド実装です。 Web テクノロジーを使用して分散型 ID を実現します。テクノロジー全体は電子メールと同様の効果を達成できます。つまり、グローバルに分散され、強力な相互運用性があり、内部的に集中化され、数十億のユーザーをサポートできます。

私たちが採用した最も初期の DID メソッドは、ビットコイン アドレスに似た自己検証型 DID メソッドである Did:all でした。これも Web ベースで実装されていますが、この方法には、DID に対応する秘密鍵を紛失した後に回復するという致命的な問題があり、十分に解決されていません。興味のある学生は、放棄された文書のバックアップを確認してください。

その後、DID 秘密鍵を紛失した後に回復するという問題を解決した Did:web の設計に出会いました。全体的な設計思想は私たちのものと非常によく似ていました。

そこで、did:web ソリューションに切り替え、エージェントの説明の追加、エージェント ID のプライバシー保護、エージェント ID の人による認証などのエージェントのサポートを追加しました。新しいメソッド Did:wba (Web ベースのエージェント) を提案しました。

Did:web の作者とも Twitter でやりとりしました。将来的には、2 つの方法が統合されることを期待しています。

## オープンソースとコミュニティ

ANP プロトコルとキー コードの実装はすべて MIT ライセンスの下にあり、今後も常に MIT ライセンスの下に残ります。

ANP の設計プロセス中に、私たちはオープンソース コミュニティから多くの優れた成果を吸収しました。また、オープンソース コミュニティに恩返ししたいと考えています。

私たちは、**クローズドなプロトコルには未来がなく、付加価値のないオープンソースには意味がないと考えています。 **

オープンソースとコミュニティ構築に参加する過程で、私はオープンソースの力と価値を目の当たりにしてきました。また、より多くの開発者、コミュニティ、企業が ANP コミュニティの構築に参加できることを強く望んでいます。

## 連絡先情報

AgentNetworkProtocol の目標は、インテリジェント インターネット時代の HTTP プロトコルになることです。

私たちのビジョンは、エージェントの接続方法を定義し、数十億のエージェントのためのオープンで安全かつ効率的なコラボレーション ネットワークを構築することです。

エージェントの通信プロトコルに興味がある場合は、オープン ソース コミュニティに参加して、エージェント間の接続方法を共同で定義し、エージェントティック Web の将来を探索してください。
