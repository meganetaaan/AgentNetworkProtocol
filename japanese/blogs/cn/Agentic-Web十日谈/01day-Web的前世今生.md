# Agentic Web Decameron · 1 日目: World Wide Web からスーパー プラットフォームへ — クローズド Web の歴史的必然性

> **核心的な質問**: 「接続」のために生まれたネットワークが、必然的にプラットフォームベースで閉鎖的なものになるのはなぜですか?

1989 年、CERN に勤務する英国の科学者ティム バーナーズ リーは、「情報管理: 提案」という一見平凡な提案を提出しました。彼の上司はその提案を「漠然としているが刺激的だった」と述べた。

この「あいまいな」提案は、最終的に世界全体を変えました。これは、今日ワールドワイドウェブと呼ばれるものの原型でした。

30 年以上経った今日、この時代の歴史を振り返ると、混乱を招くパラドックスに気づくでしょう。**「接続」のために生まれたオープン ネットワークが、最終的にはプラットフォームの独占とデータ アイランドになったのはなぜでしょうか。 **

これは道徳的な選択についての話ではなく、生産性の進化についての話です。この歴史を理解することは、なぜ AI 時代に新しいインターネットが必要なのかを理解するための前提条件です。

## この記事の要点

- **Web と呼ばれる理由**: ティム・バーナーズ・リーの当初の意図は「接続は力である」であり、誰もが自由に情報に接続し、他のユーザーと接続できるようにします
- **HTTP プロトコルが成功する理由**: シンプル、オープン、パーミッションレス、既存のインフラストラクチャに基づく - これら 4 つの原則がインターネット革命を可能にしました
- ** Web 2.0 の転換点**: オープンからクローズへ、それは裏切りではなく、人間の注意力と運用能力を最適化した必然の結果です
- **セマンティック Web が失敗した理由**: 手動アノテーションのコストが高すぎる、商業的な原動力が欠如している、技術スタックが複雑すぎる - 3 つの山が美しいビジョンを打ち砕いた
- **Web3 の限界**: 「信頼の問題」を「オンチェーンの問題」に単純化し、ユーザー エクスペリエンスと生産性の現実を無視する
- **重要な判断**: 閉鎖は陰謀ではなく、古い生産性条件下での最適な解決策である - 規模効果がプラットフォーム独占の形成を促進する

## 1. World Wide Web の本来の目的: 接続は力です

多くの人は、初めて「World Wide Web」という名前を聞くと、なぜ「Web」と呼ばれるのかと疑問に思うでしょう。

Tim Berners-Lee の答えは簡単です: **情報はツリー状ではなく、メッシュ状である必要があるからです **。

Web が登場する以前、情報システムはほとんどが階層構造でした。たとえば、図書館の分類やファイル システムのディレクトリ ツリーのようなものでした。しかし、現実世界の情報はこのように整理されることはありません。論文には同時に複数の専門分野が含まれる場合があり、1 人が同時に複数の役割を果たす場合もあります。情報間の関係は、むしろ複雑な網のようなものです。

** ハイパーリンク ** は、Tim Berners-Lee から渡された答えです。 URL と HTML を使用すると、誰でも Web ページを作成し、インターネット上の他の Web ページにリンクできます。情報はもはやサイロに閉じ込められることはなく、リンクを通じて自由に流れます。

その背後にある考え方は、**「Connection is Power」**（つながりは力）です。

### つながりの本来の意味は力

Web が誕生した時代、「つながりは力」には次の 3 つの意味がありました。

1. ** 接続できる人は誰でも見ることができます **: Web ページがインターネット上にある限り、世界中の誰でもアクセスできます。
2. **つながりを作る人は誰でも知識を整理できます **: ハイパーリンクを通じて、誰でも独自の知識ネットワークを構築できます
3. **自由に接続できる人に自律性があります **: 仲介者も許可も必要ありません

このアイデアは今では時代遅れに聞こえるかもしれませんが、30 年以上前には革命的でした。

重要なのは、Webが初めてでした。**インフラ、プラットフォームではなく**社内では管理されていない機関で、誰でも自由に利用できます。

**オープニングはスローガンではなく出発点です。 **

## 2. Web 1.0: HTTP はなぜ成功するのでしょうか?

ハイパーリンクが Web の魂であるなら、HTTP プロトコルは Web の骨格です。

なぜHTTPは成功するのでしょうか? 30 年以上経った今でもインターネットの基礎となっているのはなぜでしょうか?

その答えは、次の 4 つの主要な条件に要約できます。

### 1. シンプルさ

HTTP のコアコンセプトは非常に簡単です。クライアントはリクエストを送信します。サーバーは応答に戻ります。それはそれと同じくらい簡単です。

最初期の HTTP/ 0.9 プロトコルは、全ノルムのみ 1 ページです。1 行だけリクエストしてください:`GET /index.html`、応答は直接HTML文書に戻ることです。ヘッドリクエスト、ステートコードなし、複雑なハンスケーク処理はありません。

これは、誰もが簡単にHTTPを理解し、実現することができる非常に単純アプローチです。 医者さんを必要としない、高価な機器を必要としません、あなたは専門的な訓練を必要としさえありません - あなたがそれをプログラムする方法を知っているならば、Webサーバーを構築することができます。

**単純に、しきい値が低下します。低さ、関与する人が増えます。そして参加者の数は多岐に渡ります。**

### 2. 営業部

Tim Berners-Lee は重要な決定を下しました。Web テクノロジーの特許を行わないだけでなく、標準組織を閉じています。代わりに、HTTP、HTML、URL を自由に使用、変更、拡張機能として開くことができます。

当時は稀になかった。1990年代には、多くの企業が独自の「情報高速道路」を建設しようとしていたが、主にクローズドで、専門クライアントが必要な有料システムであった。

大会のWebがオープンしています。**単一のポイント制御、家賃なし、アクセスしきい値を意味し、オープン**誰でもウェブサイトを設定でき、誰がアクセスできず、中人には価格差を稼ぐことはできません。

### 3. 許可なし(許可)

これは、Webの最も強力な機能の一つです。**誰の承認もウェブサイトを作成したり、コンテンツを投稿したり、別のサイトにリンクしたりする必要はありません。**。

クリアランスなし、アクセスなし、 "最初に支払う" とオンラインに行きます。 サーバー、ドメイン名、グローバルネットワークに参加するだけです。

この「ノー・パーミット」機能は、膨大なイノベーションを解明しました。個人ブログから Wikipedia、GitHubからYouTubeまで、誰もが承認を必要としないウェブサイトで数えきれない素晴らしい革新が始まりました。

**許可がないと、イノベーションのペースが承認プロセスに制限されていないことを意味しますが、作成者の想像力だけ。**

### 4. 既存インフラに基づく

HTTP は、ホイールを再作成しようとしません。ドメインネーム解析用の DNS を使用して、TCP/IP に基づいており、既存のインターネットインフラに依存しています。

これは、Webは日々のグローバルで機能することができるようになります。新しいネットワークプロトコルがデプロイされるのを待ちつからなければならなくても、新しいハードウェアが作成されるのを待つ必要はありません。承認されるべき新しい基準を待つ必要はありません。オンラインで入手できる限り、Webにアクセスすることができます。

**既存のインフラに基づき、導入コストを大幅に削減し、アクセス率が加速しました。**

### 重要判断:情報制作・流通の推進

ウェブ 1.0 コアの達成, はい**情報発信・配信の能力を解放**。

出版プレス、印刷プレス、流通チャネルが必要です。Webでは誰でも情報発信者になることができます。

しかし、この時代の重要な特徴は一つあります。**人々は、メインの「通訳者」と「実行者」です。**。

ウェブページは、ハイパーリンクが見えるようになり、情報を読みます。Webデザイン全体が人間認知と運用能力を巻き起こします。

**生産性の主観は人間を守っていません。**

プラットフォームのその後の変換につながっています。

## Web 2.0: プラットフォーム化は裏切りではなく、効率性オプションです。

Web 1.0が「オープン」と「接続」の場合、Web 2.0は「プラットフォーム」と「ユーザー生成コンテンツ」です。

2000年代初頭にブロードバンドの普及と技術の発展に伴い、インターネットは「読み取り専用」から「読み取り・書き込み」へと移行し始めました。ブログやフォーラム、ソーシャルネットワークが出現し、ユーザーは情報ではなくアクティブなコンテンツクリエイターの受動的な消費者をいません。

とても良いことです。しかし、パワーの深い転送に続いています。

### なぜプラットフォームが立ち上がったのですか?

商取引の挨拶や道徳的な腐敗のためのプラットフォームの上昇を非難する多くのが、この解釈はあまりにも簡単です。

プラットフォームは3つの問題から出現しました。

#### 1. 情報積み過ぎ

Web 1.0は、情報の発信の問題を解決しましたが、また新しい問題を作成しました:あまりにも多くの情報。

数億ページがインターネット上で利用可能になると、人間は単に必要な情報を見つけることができません。検索エンジンはこの問題を解決するだけです。

基本的に「接続」による情報の価値を測定するGoogleのPageRankアルゴリズムは、ページがより高品質のWebページへのリンクを張っているときよりも価値が高いです。

**これは「接続はパワー」が異人種化されているのが初めてです。それはもはや等しくありませんが、重量を量る権利です。**

#### 2. 関係管理コストが飛躍的に上昇

Web 1.0 時代では、RSS を購読するブログの数十に興味があるかもしれません。しかし、連絡先が数百万人に達した場合は、手動で関係を管理することは不可能になります。

ソーシャルネットワーキングは、この問題を解決するのにちょうど関係を管理するのに役立ちます。 Facebook、Twitter、Twitterはすべて、あなたが誰があなたの友人であり、あなたはあなたがどこにいるかに興味を持っている人、誰がラインにいるのかを管理するのに役立ちます。

**プラットフォームは、関係の主催者とブローカーになりました。**

#### 3. トレードの複雑さ。

eコマースの上昇は、新しい要求をもたらしました。買い手が売り手を見つける方法、取引のセキュリティと紛争解決方法を確実にする方法?

バケツ、アマゾン、eBayの出現はこれらの問題に対する解決です。それらは調査、支払、兵站学、評価および売り上げ後のサービスのようなフル レンジを提供します。

**プラットフォームは取引のためのブローカーと信頼ブローカーになりました。**

### プラットフォーム化の内的ロジック

最終的に、プラットフォームの出現は3つのコアの問題を解決しました。

1. **コンテンツフィルタ**(研究・推奨)
2. **関係団体**(社会仕様)
3. **ディーリング。**(電気・プロデューサー、広告)

これらの3つの問題の一般的な特徴は次のとおりです。**人間に注目し、業務上の卓越性を発揮します。**。

業務能力が限られているため、人的注意が限られています。人件数よりも情報や関係が大きい場合、画面のヘルプ、整理、メディアの処理に役立ちます。

**プラットフォームは、中盤です。**

人体が生産性を重視する時代、プラットフォーム化は必然的な選択です。

## IV. 閉鎖および独占の根本的な運転者

プラットフォームの出現は問題ではありません。 質問は、なぜそれが閉鎖され、単性になるつもりですか?

回答はソフトウェアの経済性です。

### ソフトウェアの限界コストはゼロに近いです。

従来の製造では、原料、労働および装置をプロダクトを作り出すために取ります。

ソフトウェアの開発コストは異なります。 コピーするのは少しかかります。 100ユーザーと100万人のサービス利用者の費用差は1万回以上です。

**つまり、ソフトウェアは自然なスケール効果をもたらすということです。**

### 大きいほど、値が高くなります。

プラットフォームソフトウェアの場合、スケール効果はより明らかです。

- **より多くのユーザー** ～ より多くのデータを生成
- **より多くのデータ** よく、より良いアルゴリズム。
- **より良いアルゴリズム。** ♪ より良い体験を提供
- **より良い経験。** ～ より多くのユーザーを引き寄せる

これは肯定的なフィードバックの車輪を作成します:

> **より多くのユーザー、より効率的な、よりロックされた、より大きいプラットホーム。**

そのため、インターネット業界は勝者全員の状況に陥っています。

### 閉鎖はスケール効果の避けられない結果です。

プラットフォームが優れているとき、閉鎖に向かって移動する正当な理由があります。

1. **データはコアアセットです。**: 開いたデータとは、競合他社がコア資産に無料でアクセスできることを意味します
2. **ユーザロックは、モアットです。**: ユーザが退去するのは、モノポリを維持するための鍵となる
3. **エコロジー制御は、電力の源です。**: 開発者のエコロジーを制御し、イノベーションの方向性をコントロール

ワイヤレスは、どのリンクが共有され、それができないかを判断することができます。 宝探しは、どの商品が推奨されているかを決定します。 App Storeは、ボード上にアプリケーションを置くかを決めることができます。

### 開放性の高いコスト

逆に、選択が開く場合、重要な費用圧力があります。

情報フィールドはオープンビジネスではありません。電子メール、電話、テキストメッセージ、これらは典型的なオープンインターネットアプリケーションです。彼らは1つの一般的な機能を共有します:**シンプル**。

1970年代から1980年代にかけて、Eメールプロトコル(SMTP/POPS3/IMAP)が誕生し、コア機能は「テキストメッセージの送信と受信」というシンプルなものです。

しかし、ビジネスが複雑になると、開業コストが大幅に増加します。

- 異なるメーカーの実現は互換性が必要です
- 契約のアップグレードは、参加者全員に調整が必要です
- コインシスと非vitability。
- デバッグ・メンテナンスコストが飛躍的に増加

友人、ビデオ番号、支払い、プログラムなどコミュニティを開く必要があったら、どのような基準が必要か想像してみてください。 相談はいくつありますか? テストのラウンドはどのくらいかかりますか?**防災・防災・防災・防災・防災・防災・防災・防災・防災・減災**。

**そのため、インターネットが複雑になり、開かせるにつれて、道徳的な選択ではなく、エンジニアリング現実です。**

### 重要な判断。

従来のソフトウェア時代には、基本的なロジックがあります。

> **一度、ソフトウェアはすべての機能に開発されます。より多くのユーザーはより効率的です。そして単価は無作為ではなく内部です。**

プラットフォーム単価ではなく、そのものです。**下部の技術が変更されていない場合、自動的に開くために戻りません。**。

意味のあるネットワークとWeb3の開発は、この証拠です。

## なぜ、セマンティックネットワークが壊れていないのですか?

Web 2.0 が閉じるつもりですが、別のルートがあります。 Semantic Web.

Tim Berners-Lee は 1998 年にセマンティックネットワークビジョンを発表しました。このマシンがウェブページの意味を理解できるようにするため、それらを表示するだけです。セマンティックラベルをデータに追加することで、機械は自動的に理由を出し、情報を統合し分析して、実際の「スマートネットワーク」を実現させます。

よく聞こえるの?AIのスマートボディが今日何をしているのか?

そして、ここはアメリカの科学のセマンティックネットワークに関するTim氏の記事を読むための提案です。これは、スマート ボディ ネットワークの具体的な説明が非常によくあります。

しかし、大規模な規模ではセマティクスは利用できません。なぜ?

最終解析では、次の3点を要約できます。**手動ラベリング、ビジネスドライブの欠如、あまりにも複雑な技術倉庫のコストが高い**。

Semanticネットワークは、RDF、OWLなどの言語でデータに匿名性を追加するようにウェブサイトの開発者を必要としますが、これは直接オペレータ、ユーザーがそれを見ることではなく、検索エンジンがランク付けしません。 重要なことに、テクノロジーのしきい値が高すぎた場合、商用会社プッシュなしで、エコロジーは形成できません、ネットワーク効果は開始できません。

意味のあるネットワークは、重要なインサイトを私たちに残しました。

> **人工ラベリングではなく、機械がデータの皮下を理解できるようにする正しい方向です, しかし、自動機械の理解によって.**

大きくなった言語モデルで、まさに革命的な変化が生まれます。

しかしAIが出現する前に、セマンティックネットワークは故障してしまった。その時、システムの生産性を「理想」に反してみたから。

## なぜWeb3がシールを破らなかったのですか?

Web3は、ブロックチェーンでプラットフォームの単価を解決しようとします。ユーザーのデータアップリンク、スマートコントラクトによるアプリケーション実行、NFTによって保護されたデジタルアセット。良いビジョンですが、それは機能しません。

問題は3つです:**課題の連鎖に信頼を簡素化**(パフォーマンスの信頼も執行、責任、紛争を含みます)**パフォーマンスボトルネックです。**(7 ビットコイン対. 100 千分の 1秒)**ユーザ体験が悪くない**(アストロフ、秘密鍵、ガス代は一般利用者に禁止します)

Web3の深い質問は、意味のあるもの:**「システムや技術の理想」で、時代の生産性を実感し直すことにしました。** 「人」の年齢では、プライベートキーの管理、ガス手数料の支払い、確認されるブロックの待ち合わせは、許容できないコストです。Web3は誰が行動するのかを問いかけません。人間は主要な実行者のままですが、人間の能力を維持し、まともなビジョンを維持することができません。

## 結論:Webの進化は間違いではなく、各世代に最適なソリューションです。

この記事の先頭に質問を返します。**なぜ「接続」のために作成されるネットワークがプラットフォーム化と閉鎖に向かって移動するのは避けられないのですか?**

回答は:**時代ごとに、時を刻むような条件で最も評価されている人を選ぶため。**

- ウェブ 1.0 無料の情報制作が、積み過ぎに持ち込まれる
- Web 2.0は大量の情報を整理するが、プラットフォーム単体を生成
- マシンがデータを理解できるようにするSemanticネットワーク試み, しかし、手動ラベリングに依存します, それはあまりにも高価です.
- Web3はブロックチェーンで一元化しようとしましたが、無視されたユーザーエクスペリエンスと効率性

**閉鎖は、人間の存在が主要な生産性であるとき、人間のスケールの効率性と経済性の必然的な結果ではありません。**
