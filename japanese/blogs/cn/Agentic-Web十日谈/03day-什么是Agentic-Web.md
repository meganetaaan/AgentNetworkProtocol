# Agentic Web Decameron · 3 日目: Agentic Web とは何ですか?エージェントがインターネットの最初の住民になるとき

> 最近忙しくて、前回の記事から今回の記事までかなり期間が空いてしまいました。しかし、私はそれを終わらせることに固執します。

> **主な質問**: Agentic Web とは正確には何ですか?

まだ非常に厳密な学術的な定義を与えることはできませんが、エージェントティック Web の 3 つの特徴、特に従来のインターネットとの違いがわかります。

最初の 2 つの記事では、Web 閉鎖の歴史をレビューし、AI の能力を最大限に引き出すために、新しい実行主体としてのエージェントがコンテキストとサービスを取得するためにオープンなインターネット環境を必要としていると推測しました。

今日私たちが主に議論しているのは、インターネットの主なユーザーが「人」ではなく「エージェント」になったら、このネットワークはどうなるのかということです。

「あなたが話している Agentic Web は、現在のインターネットと API のことですよね?」と多くの人が言うかもしれません。

**Agentic Web は、既存のインターネット上のパッチではありません。 ** モバイル インターネットが単なる「PC インターネット + 携帯電話」ではないのと同様に、位置情報サービス、常時接続、タッチ インタラクションなどの新しいパラダイムをもたらします。

同じことが Agentic Web にも当てはまり、3 つの根本的な変更がもたらされます。

---

## 1. Agentic Web の暫定的な定義

まず予備的な定義をしてみましょう。

> **Agentic Web は、エージェントを主体とし、標準プロトコルを核とし、オープンコラボレーションを基本形態とする新世代のインターネットです。 **

3 つのキーワード:

1.  **主語が変更されました**: 「人間」から「インテリジェント」に。
2.  **接続方法が**:「UI」から「プロトコル」に変更されました。
3.  **コラボレーションの形式が変更されました**: 「データアイランド」から「オープン接続」に。

以下、私の理解を一つずつ説明していきたいと思います。

## 3.変革 2: UI 主導からプロトコル主導へ

ユーザーは「人間」から「知能エージェント」へと変化しており、それに合わせて接続方法も変化する必要があります。

今日、あなたは食べ物の注文を手伝ってくれるインテリジェントなエージェントを必要としています。既存のソリューション (コンピューターの使用、ブラウザの使用) は依然として人間の操作をシミュレートしています。
1.  ブラウザを開く
2.  URLを入力してください
3.   ページが読み込まれるまで待ちます (広告を含む)
4.  どれが「予約」ボタンであるかを確認してください
5.  マウスクリックをシミュレートします

**このソリューションは遅くて壊れやすいです。 ** Web ページの改訂、ボタンの再配置、広告、UI の変更により、タスクが失敗する可能性があります。

** Agentic Web では、プロトコルが UI に代わってコアとなります。 **

サービス プロバイダーは、HTML Web ページを提供するだけでなく、標準の **Agent description Protocol** を提供するようになりました。
-    エージェントに「これは予約という赤いボタンです」と伝える代わりに、
-   同意書で直接伝えてください。`Function: book_table(time, pax, requirements)`。

UI は人々が見るものであり、視覚的なフィードバックと感情的なガイドが必要です。
プロトコルはマシン用であり、構造化データと決定論的ロジックを必要とします。

**将来のインターネットは 2 つの層に分かれます: **
1.  **サーフェス レイヤー (ヒューマン レイヤー) **: 人間のエンターテイメント、ソーシャル インタラクション、エクスペリエンスのための絶妙な UI を維持します。
2.  **エージェント層**: エージェントがデータを交換してタスクを実行するための、標準プロトコルに基づく機能ネットワーク。

**Agentic Web は形成中の「内層」です。 **

##  IV.変化 3: プラットフォームの閉鎖からオープンなコラボレーションへ

この移行が最も難しいです。

今日のインターネットは「プラットフォームベース」です。 Super App はすべてのサービスを自社の壁内に囲い込みたいと考えています。タクシーを呼びたいですか?私のものを使ってください。テイクアウトを注文したいですか？私のものを使ってください。映画を見たいですか？まだアプリ内にあります。

このモデルは人間用に肥大化していますが、ほとんど使用できません。インテリジェントエージェントの場合、それは明らかに制限されています。

**知能エージェントには当然「結合」する能力が必要です。 **

シナリオを想像してください: ** 「日本への旅行の計画を手伝ってください。」 **

閉じたネットワークでは、どのアプリもこのタスクを独立して完了することはできません。
-   旅行アプリはチケットを予約できますが、（カレンダーアプリ内の）あなたのスケジュールは知りません。
-    カレンダー アプリは時刻を知っていますが、(銀行アプリで) 支払うことができません。
-   銀行アプリは支払うことができますが、（ソーシャルアプリでの）戦略の好みを理解できません。

Agentic Web の接続フォームは**オープン コラボレーション**:

ユーザーの「パーソナル アシスタント エージェント」は、それ自体ですべての機能を備えている必要はありません。他の特殊なエージェントを動的に検出して接続できます。
1.   は、ホテルを予約するために ** ホテル エージェント ** に接続します。
2.   は、** アトラクション エージェント ** に接続して、アトラクションのチケットを予約します。
3.   は、航空券を予約するために、** 航空会社代理店 ** に接続します。
4.  最後に**支払いエージェント**に電話して決済を完了します。

これらのエージェントは、異なる会社や個人の開発者に属している場合もありますが、共通の **エージェント通信プロトコル** を通じて連携します。

** はもはや孤立した島ではなく、自由に組み立てることができる機能のネットワークです。 **

## V. これは、単なる技術アップグレードではありません。

上記3つの変更を理解すると、エイジニック・ウェブが「結合対象のリターン」と言います。

Tim Berners-Lee は、世界規模の Web を「接続」にしました。
-   Web 1.0 はドキュメントに接続します。
-   Web 2.0は人を接続します。
-   **エージェンシーウェブは、サービスや運用を繋ぎます。**

(a) スマートボディがプラットフォームの壁を横断できるときネットワークを介して流れます。
(b) サービスの容量が電気と同じである場合、標準プラグイン(合意)を介して差し込まれています。
小規模な開発者がプロトコルを通じて、グローバルインテリジェンスによって発見され、呼び出されることができるとき。

効率性が向上するよりも、私たちが見るものは何か。

## 偉大な頭はそう言うでしょう?

「音がいいけど、巨人はそう言ってる?」

エイジニック・ウェブのアイデアを聞いた人が多いと、これが最初の反応です。

確かに、既存のインターネットの巨人は、自分のエコロジーを閉じてたくさんのお金を稼ぐ。 それらが彼らのインターフェイスを開き、壁を壊すようにしてください。

**しかし、紛争はすでに始まりました。**

2024年後半と2025年初頭に、古い生産でインテリジェントな生産性の第一弾の暴力的衝突を目撃しました。ビーンバッグ電話アシスタントは殺されました。

単なる商用紛争ではありません。それは信号です。**新規の実装者が、古い生産関係を通る旅行しようとすると、それは必然的に炎から出ます。**
