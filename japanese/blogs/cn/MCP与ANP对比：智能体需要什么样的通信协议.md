# MCP と ANP の比較: エージェントにはどのような通信プロトコルが必要ですか?

核となるアイデア:
- 消費者向けのパーソナル アシスタントを構築することで、推論能力のボトルネックが急速に解決されています。現状ではまだコストと情報取得の2つのボトルネックが存在します。 AI にすべての情報を取得させる方法を解決するには、エージェント通信プロトコルが必要です。
- 業界エージェントや AI に関連する現在のオープンソース通信プロトコルは、Anthropic の MCP や当社が設計した ANP など、設計と実装において比較的完成しています。
- MCP と ANP には、プロトコル アーキテクチャ、ID 認証、情報構成という 3 つの側面で大きな違いがあります。
  - MCP は典型的な CS (クライアントサーバー) アーキテクチャであり、ANP は典型的な P2P (ポイントツーポイント) アーキテクチャです。
  - MCP ID 認証は Oauth 標準に基づいており、クライアントは現在のインターネット リソースに簡単にアクセスできます。 ANP ID 認証は W3C DID 標準に基づいており、すべてのエージェントが相互接続できるように、エージェント間のクロスプラットフォームの相互運用性の問題を解決することに重点を置いています。
  - MCP の情報組織は、本質的に API 呼び出しである JSON-RPC テクノロジーに基づいています。 ANP の情報組織はセマンティック Web のリンクデータ技術に基づいており、AI がアクセスして理解しやすいデータ ネットワークを構築することを目的としています。
- MCP と ANP の最大の違いは世界観の違いです。
  - MCP はモデル中心であり、インターネット全体がそのコンテキストおよびツールです。
  - ANP はエージェント中心です。各エージェントは同じステータスを持ち、分散型エージェント連携ネットワークを形成します。
-  エージェントがどのような通信プロトコルを必要とするかは、将来のエージェント インターネット (エージェント Web) の特性によって異なります。この点に関して、私たちはMCPとは異なる見解を持っており、ANPの研究開発にしっかりと継続的に投資していきます。

## エージェント通信プロトコルが重要なのはなぜですか?

Deepseek R1 の発売、OpenAI o3 Mini および Deep Research の発売により、明らかな傾向が見られます。インテリジェント エージェントの構築を妨げる中心的なボトルネック、つまり複雑なタスクの推論機能の制限が、加速度的に解消されつつあります。

Deep Research は、基本的にナレッジ ワーカーのパーソナル アシスタントと考えることができます。

消費者指向の知性を築くには2つのボトルネックがあります。 1つはコストであり、それは1つまたは2つの注文が2025年までに減少すると予想されます。 もう一つは情報です:消費者指向の個人情報アシスタントが十分な情報を得ることができますか?

知識労働者の情報は、オープンデータベースやウェブサイトに頻繁に保存され、AIは非常に簡単にアクセスを持っています。消費者指向情報は、現在のインターネットデータ島現象にはるかに複雑で、今非常にフラグメントされ、非常に開いている。

消費者が必要とする情報にアクセスするために、個人アシスタントを有効にする方法(ツール機能も1つのタイプの情報として理解することができます)スマートボディ通信プロトコルの問題です。

## MCPとANPの紹介

MCP(モデルコンテキストプロトコル):モデルコンテキストプロトコル(MCP)は、LMアプリケーションが外部のデータソースとツールとシームレスに統合できるオープンな合意です。AI主導のIDEを構築し、チャットインターフェイスを強化したり、カスタムAIワークフローを作成したりする場合でも、MCPは、必要なコンテキストにLMをリンクするための標準化された方法を提供します。https://spec.modelcontextprotocol.io/

AgentNetworkProtocol(ANP)は、スマートWeb用に設計されたオープンプロトコルのフレームワークです。 ANPには、任意の2つのインテリジェントなボディが接続できるように、集中識別があります。 また、より効率的なデータ交換とインテリジェントなボディ間のコラボレーションを可能にするインテリジェントな説明も設計しています。https://github.com/agent-network-protocol/AgentNetworkProtocol

スマートボディ通信プロトコルの現在の領域では、MCP以外のより完全なオープンソースプロジェクトが当社のデザインAMPである可能性があります。 ANPはおそらくインテリジェント向けにインターネット上で起動する最初のオープンソース通信プロトコルです。 最初に発行されたコードで、プロトコルは書籍文書を飛行し、githubに移行します。

オープンソースのプロジェクトがよくあると、紹介してもらえるのも良いでしょう。

AMP が P2P 構造を使用するために選択した主な理由は、インテリジェントな人が自分の取り組みで他のインテリジェントな身体に要求をし、いつでも他の人からリクエストを受け取ることを可能にすることです。

実際のP2Pアーキテクチャは、物理的接続だけでなく、P2PのコアであるP2Pではなく、その役割と位置決めはP2Pでなければなりません。

### 認証: Outlook VS DID

アイデンティティは、スマートボディ通信プロトコルの重要な部分であり、それはまた最も困難な部分です。 1つの問題があります:インテリジェントな身体間のクロスプラットフォームのアイデンティティを交差する方法。 唯一の方法は、他のすべてのスマートで動作します。

#### MCP の同一証明

初めてリリースされた時に認証をサポートできなかったため、リモートサーバとの接続が困難でした。クライアントとサーバー間での識別を既にサポートしているドラフトの最新バージョンです。

MCP 識別プログラムは、Oauth2 標準に技術的に集中しています。

OAuth はオープンな標準で、ユーザーリソースへのアクセスを承認する安全で簡単で柔軟な方法を提供することを目指しています。サードパーティのアプリケーションが、ユーザー名やパスワードなどの機密情報を取得することなく、別のサービスプロバイダに保存されたリソースにアクセスできるようにします。 Google および Microphone アカウントアクセスを使用した当社の一般的な 3 方法 アプリケーションは、OAuth 技術に基づいており、インターネット上でより広く使用されています。

MCP が発行するドラフト契約はコミュニティの第2版であり、最初のバージョンに関連して次の改善を表明しています。
- Outlook 2.1(フォームを書草案に置く)の使用は、合意と強化されたセキュリティを簡素化しました
- 認可サーバーをサポートすることで、OAuth 2.0 がサーバーメタデータプロトコルを認証するようになり、クライアントは承認されたエンドポイント、トークンピア、サポートされる認証された暗号化アルゴリズムの種類などの権限のあるサーバーの構成情報を自動検出し、アクセスすることができます。
- OAuth 2.0 の動的クライアントレジスタ (DCR、ダイナミックインテグレーション プロジェクト) をサポートし、サーバーへの事前登録を行なわずに自動的にサーバーに登録を開始できます。統合クライアントサーバのコストを簡素化します。

最近、W3C DIDの多くのアプリケーションは、火災ブルースキーとして知られており、その下合意ATプロトコルは、識別プログラムとしてW3C DIDを使用しています。

MCP と ANP の同一証明と比較して、いくつかの違いがあります。
- MCP 識別プログラムは、AI が元のインターネットに接続するための良いオプションであり、現在 Oouth をサポートする多くの大きなアプリケーションです。
- ANPが利用するDID技術は比較的新しい規範であり、一般に公開することはできません。
- Oauthの問題は、既存のインターネットアプリケーションでユーザーのリソースにアクセスするためのモデルを取得する方法です。 DID は、2 つの異なるプラットフォームのスマート間で認証する方法をアドレスします。

相互運用性だけでは、DIDベースのプログラムがOauthベースよりもシンプルで少ないインタラクティブです。
- OAuth プログラムは、クライアントがサービス終了時に ID を登録する必要があります。DID プログラムでは、それぞれに直接 ID を使用してやり取りし、登録プロセスと異なるサーバー生成された ID の管理コストを削減します。
- 同一証明プロセスは、IDと非対話的であり、0-RTT(ゼロラウンドタイム、すなわち最初のビジネスリクエストは認証情報)を可能にします。

根本原因は、オウトが特定するアイデンティティの相互運用性のために特別に設計されていないことです。 DIDは、より相互運用性が良好である、集中型アイデンティティ技術です。

スマートな人のアイデンティティは確かに非常に難しい問題です。 継続的に対処する必要がある多くの問題があります。
- ユーザーのプライバシーを侵害することなく、必要な識別情報にアクセスして、プラットフォーム間でIDが検証できるのはどうすればよいですか?
- ユーザーの粒子サイズをより細かく制御する方法は? IDとすべてのスマートとの通信の代わりに。
- インテリジェントな身体からのリクエストは、ユーザーの人工的な許可によって判断されることができますか? 一部の機密操作は、インテリジェントにそれ自体を始動させることはできません。
- プラットフォームで付与された特権を使用するのではなく、ユーザーは自分のアイデンティティを完全に所有権に与えることができますか?

これらの新しい問題は、W3C DIDに基づいて解決しやすくなります。 それらの多くは既に予備的な方法で解決され、後でゆっくりと洗練された公開されます。

### 情報組織: RPC VSのリンクされたデータ

MCP および ANP は、インテリジェントな外部出力情報の構成で異なる技術を使用します。

#### MCP情報組織

MCP は、JSON-RPC を使用して、サーバーの s リソースとツールの機能を読み、操作します。 JSON-RPC (JavaScript オブジェクトの表記 - Remote Project Call) は、JSON 形式に基づくリモート・プロセスコール(RPC)プロトコルです。これにより、クライアントがリモート・サーバーにアクセスし、JSON 結果が返された結果を受け取ることができます。

MCP を使用して、サーバーリストのすべてのリソースやツールを保有し、指定されたリソースを読み込み、または指定されたツールを呼び出すことができます。クライアントはリソースに購読でき、リソースの状態が変更されたときにサーバーは独自の取り組みのクライアントに通知できます。

リソースやツールの形式は、サーバーによってカスタマイズされ、モデルでは、これらのリソースとツールを読み取り、操作する方法を決定します。

MCP サーバーは、情報をエクスポートする方法で、エッセンスの特定の API として認識できます。

#### ANP情報機関

AMPは、ネットワーク、リンクされたデータ技術を用いて脳情報発信の組織に集中しています。

リンクされたデータ(識別データ)は、Web規格に基づくデータ共有と相互接続を構成するために使用される技術です(例えば、RDF、SARQL、URL)。これは、データを独自の識別子(URI)を介して異なるソースから接続することを目的としており、機械によって読みやすく、管理することができます。

これを実現するために、スマートボディの説明(A/CONF.191/CP/2)を定義しました。[エージェントの説明](../../chinese/07-ANP-智能体描述协议规范.md))インテリジェントな身体のアイデンティティ、能力、物理的情報、APIインターフェイスなどの記述のための。

スマートな記述文書はJSON-LDのフォーマットで、さまざまなデータをデータネットワークにリンクし、機械理解を容易にするJSONに基づく連結されたデータ(調整されたデータ)のフォーマットです。

例えば、コーヒーショップのスマートボディ説明文書は、コーヒーショップの名前、所有者、場所、労働時間などを説明しています。また、このドキュメントには、AIが製品のJONS-LDファイルにアクセスし、製品の詳細を取得できるように販売中の複数のURLも含まれています。同様に、製品詳細には、新しいJSON-LD URLが含まれる場合があります。

これにより、このインテリジェントなボディが露出しているすべてのパブリック情報にアクセスすることができます。これにより、JSON-LDリンクを使用する新しいデータネットワークを構築し、AIに簡単にアクセスできます。現在持っているWebベースのインターネットに対応しており、2つのネットワークで簡単にアクセスできます。人やAAIの他の1つ。

データ接続に加えて、リンクされたデータ技術には、一元的な理解があります。私たちが設計したJSON-LD文書は、現代のWebを記述するためのセマンティックモデルを定義するschema.orgに基づいており、2つのインテリジェントな体が同じフィールドの同じ理解を持っていることを可能にし、スマートボディ間の情報理解の正確さを高め、プロセス処理を容易にします。

リンクされたデータ技術を使用して、インテリジェントなボディのオープン情報は、ユーザーが素早くサービス可能なスマートユーザーを見つけ、文書を記述するインテリジェントなボディに従って、インテリジェンスとやり取りし、コラボレーションできるように、検索エンジンによって簡単にクロールすることができます。

### デザインコンセプトの違い

設計内容のMCPとAPPの違いです。

より抽象的な要約をとれば、MCPとAPPの最大の違いは、世界観に差があることです。
- MCP は、モデル・コンテクスト、インターネット全体が自分のコンテキストとツールである。
- AMPは、精神的な身体(エージェント・セントラル)に基づいており、それぞれが同じステータスを持ち、知的コラボレーションの集中型ネットワークを形成しています。

なぜ違うのですか?

MCPとANPは、それぞれ異なる目的を持つ。

MCPは、インテリジェントな身体の通信契約ではありません。また、モデルコンテキストプロトコルとしてその名前から見ることができ、現在のインターネットにアクセスしやすくなり、チャットボット製品が充実するコンテクスト機能を提供します。

自社製品ではなく、ANPを設計する際には、今後直接的確に、そして、アダリック・ウェブの未来への理解に基づいています。AIの機能を十分に解き放つことができるインテリジェントな身体の新しいネットワークを構築することを目指しています。

## どのような通信プロトコルがスマートに必要ですか?

MCPは、非常に良好な合意であり、現在のモデルがインターネットにアクセスするための最良のソリューションであり、コンピュータ使用プログラムよりもはるかに有効であると考えています。 Andtropicは、そのようなプログラムの利点を示すために、その影響を使用します。

しかし、MCPは移行の形態であり、インターネットを即時に利用できる最善の方法である可能性があると確信しています。その知性のためにインターネットが大幅に変化した場合、MCPは必ずしも最良の解決策ではありません。

そのため、インテリジェントなボディによってどのような通信プロトコルが必要かは、将来のスマートインターネットの特徴に依存します。 結論をあげるにはいくつかのポイントがあります(この記事について詳しく見る):[スマートインターネットの違いは何ですか?](智能体互联网有什么不同.md)）：
- スマートはインターネットの隅々まで浸透し、人や組織が機能する多くのインテリジェントな体があるかもしれません。
- AIの能力を解放するために必要な条件である、すべての知能が接続されます。
- パーソナルヘルパーは、インテリジェントな人やインテリジェントな体との間のはるかに多くの接続で、インターネットへの新しいアクセスになります。
- ネットワークは平坦化され、インテリジェンスは、それぞれに直接接続され、フリースペースで通信します。

ANPの設計のコア要素です。

もちろん、MCPは進化し進化させていくことができ、その中で私たちは幸せになれる。組織や個人が自分でこれを行うことができないし、そして、私たちは皆で働きたいと思っています。
