# エージェントによるインフラへの変更: 既存の接続インフラに対するエージェントの課題

## AI 接続のための特別な要件

LLM に基づいて構築されたエージェントがその機能を最大限に活用したい場合、接続方法に特別な要件があります。
-  AI は、人々や組織に対してよりインテリジェントな意思決定を行う前に、すべての情報にアクセスできる必要があります。そのためには、AI があらゆる情報と相互接続される必要があります。
- AI は、人や組織がタスクをより効率的に完了できるようにするために、すべてのツールを呼び出すことができなければなりません。そのためには、AI がすべてのツールと相互接続する必要があります。

現在のすべてのアプリ、ソフトウェア、Web サイトは人間によるアクセスを考慮して設計されています。 AI がアクセスしたい場合は、人間のアクセス方法を学習して模倣する必要があります。これにより、コンピュータ利用技術やブラウザ利用技術も誕生しました。

これら 2 つのテクノロジーは短期的には価値がありますが、当然の欠点もあります。たとえば、コンピュータの使用はより高価であり、画面ベースの視覚情報のためにユーザーのコンピュータ画面を占有する必要があります。ブラウザを使用すると Web Web サイトにのみアクセスできるため、ユーザーのログイン時にセキュリティ上の問題が発生します。

この目的を達成するには、AI がデジタル世界と対話し、エージェントがエージェントと対話するための、より AI ネイティブな方法が必要です。

## プロトコル: AIネイティブの接続およびコラボレーション方法

これにより、別の技術的なルートであるプロトコルが誕生しました。

- プロトコルを使用してデータを処理すると、より効率的になります。AI は、画面やブラウザではなく、最も直接的な基礎となるデータの処理に優れているためです。

-  標準化により接続コストを削減可能: プロトコルを標準化することで、標準プロトコルをサポートするすべてのソフトウェアまたはエージェントを相互接続できるため、接続コストを大幅に削減し、新しいエコシステムを形成できます。

- このプロトコルを使用すると、人間向けに設計された現在の画面ベース、ブラウザベースのインターネットから独立した、AI ネイティブで AI がアクセス可能なデータ ネットワークを構築できます。

これが最近 MCP が注目を集めている根本的な理由だと思います。 AI ネイティブの手法を使用して、現時点で最も重要な問題、つまりモデルがツールとリソースをどのように接続するかという問題を解決します。同時に、標準化されたアプローチにより、業界全体の接続コストが削減され、新しいエコシステムが形成されます。

OpenAI が MCP のサポートを発表した後、MCP は基本的に業界のデファクトスタンダードとみなされ、第 2 の MCP が登場する可能性は基本的に考えられません。将来的には、MCP と標準化団体が協力して MCP の標準化を推進する可能性が高くなります。

Protocol の技術的ルートの最大の問題は、元のソフトウェアを修正する必要があり、修正コストが高額であることです。ただし、このコストは AI によって急速に削減されています。
- AI はソフトウェア開発の方法を変えました。 AI を通じてコードを生成すると、ソフトウェア開発コストを大幅に削減できます。
- AI はソフトウェアの実行方法を変えました。 LLM を使用してソフトウェア操作を推進すると、LLM 内のソフトウェアの本質的な複雑さが解決され、大量の複雑なコードが不要になります。
- AI はソフトウェアの接続方法を変えました。 LLM を通じてリクエストを構築し、レスポンスを処理することにより、ソフトウェアのドッキングと共同デバッグのコストを大幅に削減できます。

## MCP の次のステップ: エージェントのコミュニケーションとコラボレーション

MCP を使用すると、より効率的なエージェントを構築できます。エージェントの数はますます増えていますが、エージェントはどのようにして相互に通信し、連携するのでしょうか?

MCP は、モデル間のリソースやツールの接続の問題を解決するように設計されており、エージェント間の通信やコラボレーションに直接使用することは困難です。主に次の 2 つの主要な問題があります (エージェント A がエージェント B にアクセスする場合を例に挙げます)。
-  ID の問題: MCP を使用するには、エージェント A がエージェント B に登録されたアカウントを持っている必要があります。エージェント A が、すべて異なる組織に属する多数のエージェントにアクセスしたい場合、A が多数のアカウントを管理する必要があり、非常にコストがかかります。
- プロトコル アーキテクチャ: MCP は典型的な CS アーキテクチャです。クライアントはサーバーにアクティブに接続し、クライアントとサーバーの役割は厳密に区別されます。エージェント ネットワークでは、エージェント間の関係はポイントツーポイントの関係になります。 CS アーキテクチャは、当然のことながら、特にエージェントの接続とコラボレーションの観点から、エージェントのポイントツーポイント通信には適していません。一方向の CS 接続では、一方が他方を見つけることができません。双方向 CS 接続はこの問題を解決できますが、全体的に非常に複雑です。

業界には、エージェント間の通信およびコラボレーションの問題を解決するために特別に設計されたプロトコルが多数あります。現在、設計と実装において最も完全なものは、ANP (エージェント ネットワーク プロトコル)、IBM によって開始された ACP (エージェント通信プロトコル)、および Cisco によって開始された ACP (エージェント接続プロトコル) です。

ANP を例に挙げると、エージェント ID、エージェントの説明、エージェントの検出など、インターネット上のエージェント間のコラボレーションの問題を解決することに焦点を当てています。その最大の特徴は、W3C DID (Decentralized Identity) を使用してエージェントを識別することで、エージェントが独自の ID ID を使用して他のエージェントと対話できることです。同時に、ANP のプロトコル アーキテクチャは P2P アーキテクチャであり、エージェント間のポイントツーポイント通信に当然適しています。

## インターネットの次のステップ: インテリジェンスのインターネット

インターネット上でインテリジェントなエージェントがますます増え、エージェント間の接続がますます増加するにつれて、既存のインターネットに重大な変化が生じることは避けられません。インターネットの進化については、次のような判断があります。
- パーソナル アシスタントはインターネットへの新たな入り口となり、人々はパーソナル アシスタントを通じてインターネットにアクセスします。
- 企業はまた、インテリジェント エージェントを使用してエンタープライズ ソフトウェアを置き換え、インテリジェント エージェントをインターネットに直接展開して消費者にサービスを提供することになります。
- パーソナル アシスタントとエンタープライズ エージェントが、インターネット プラットフォームではなくプロトコルを通じて直接接続できるようになります。消費者向けインターネットは産業用インターネットと深く統合されることになります。
- エージェント間の接続がインターネットの主要な接続方法となり、AI に特化して設計され、AI アクセスに便利なエージェント データ ネットワークが存在します。
- エージェント通信プロトコルは新しいインフラとなり、将来的には標準化されたエージェント通信プロトコルが登場するでしょう。
