#  人類学MCP 2025H1マイルストーン解釈

Anthropic MCP は 2025 年の最初の半分に Roadmap を解放しました。[https://modelcontextprotocol.io/development/roadmap#roadmap](https://modelcontextprotocol.io/development/roadmap#roadmap).

当社では、スマートボディコミュニケーションプロトコルを実践しており、MCPについても非常に懸念しています。また、コミュニティの提案も行っています。

今日、MCPの理解に関するスマートボディコミュニケーション協定を策定し、公式のマイルストーンとMCPのビューをいくつか読み上げました。

この紙の焦点は3点です。

- リモートサーバのサポート。これは非常に重要です。アイデンティティプログラムのサポートは、リモートサーバーサポートで最も重要なことです。
- 使いたいしきい値を下げます。MCPは、開発の大きなコンテキストで使用しても高すぎます。
- コミュニティと規格。MCPは、将来的に業界標準になるようにコミットします。


## マイルストーンの解釈

### リモートMCPサポート

先ほど記事にありました。[なぜ、Anthropic使用DIDが発行したMCP契約は特定すべきですか?](https://mp.weixin.qq.com/s/r6k1zSHnC8sKA819x8O91Q)前述のように、MCPは致命的な欠陥を持っているので、リモートデータアクセスをサポートしていません - 完全な識別プログラムはありません。

ご覧のとおり、コミュニティもこれを認識し、最初のマイルストーンはリモートMCP接続をサポートすることです。

識別のための提案は、既にレビューの下にあるOutlook 2.0を使用してプログラムを提出されています。 私たちはまた、コミュニティの擁護者と通信し、これは確かに現在の最も現実的なオプションです。結局のところ、Outlook 2.0の標準的なレベルとその広範囲なアプリケーションが優れています。

この提案に関する最善のことは、それは、Outlook 2.0 を標準プロセスとして使用することです, アイデンティティ認証プラグインを提案しながら. 他の識別プログラムが実験的なスキームとして規範に統合されることを可能にする. これは、規制の柔軟性と開放性を支援します.

また、本提案に基づくW3C DID認証プログラムを開発。https://github.com/agent-network-protocol/AgentNetworkProtocol/blob/main/03-did%3Awba%20Method%20Design%20Specification.md)，正在等待插件化的方案合入后，提交PR。关于W3C ID の識別プログラムと Outlook 2.0 の違いは、この記事で見ることができます:[最適なスマートボディ認証技術:OpenID Conect、APIキー、wba](https://mp.weixin.qq.com/s/LBQmw_azJkmQpXp8XmKYPw)

別のリモートMCP-サポートされる2つ:

- 一つはサービスの発見であり、それはまたサービスの記述を意味します。それらはMCPのクライアントが彼女の好まれるサーバーを見つけるために呼ぶことができるOpenAI GPTsのようなプロダクトを作るかもしれません。
- サーバ開発の可用性を削減する、ステータス操作は不要。

### 流通・ディスカバリー

第三ですが、第二よりも重要だと思う。

MCP の最大の問題は、ユーザーフレンドリーが非常に悪いことです。OpenAI の GPS を比較するための MCP の機能は、強力なツールと LLM 相互作用を持つ開発者に説明することができます。しかし、使用の容易さは GPTs よりもはるかに悪くなります。ユーザーは、開発やコンピュータースキルをいくつか持っているために今大幅必要であり、ソフトウェアおよびサービス自体の全範囲をインストールできます。

このマイルストーンの4要素、パッケージ管理、インストールツール、サンドボックス、サーバー登録は、MCPユーザーをシンプルにすることができます。

自分のビジョンでは、MCPはユニバーサルである場合、使用のしきい値を下げる必要があります。また、コミュニティベースの環境インターフェイスを持ち、異なるMCPサーバーを簡単にロードできるブラウザプラグインのようなメカニズムを必要とします。 これらの4つの取り組みもこの目標に向かって前進する必要があります。

また、使いやすさを向上させるためには、リモートMCPサーバの重みが増加しなければなりません。リモートで行うことができれば、ローカルにはならずにローカルにしないようにしましょう。そのためリモートサーバーが重要であるのです。

### スマートサポート

そこでは3つあります。 戦略的な知能システム、インタラクティブなワークフロー、流体結果。 これは、コミュニティの議論の比較的小さな領域であり、最後の1を除いて他の2つの多くを理解していません。 この1の理解が良好で、メッセージを残すことを歓迎している場合は、見続けます。

### より公式なエコシステム

MCP は、メインメンテナが Anthropic 開発者であるにもかかわらず、コミュニティ主導の標準的な設定を期待しています。彼らは共同エコシステムを育てたいと願っています。すべての AI プロバイダーは、MCP をオープンな基準に同じ参加と共有されたガバナンスで形成し、さまざまなAI アプリケーションや例のニーズを満たしているようにすることができます。

これは良い考えであり、業界標準を構築するための一般的な慣行です。 MCP コミュニティは現在、提案のレビューを含む Anthropic 焦点を持っています。

## 今後はどのような取引が必要か?

インテリジェントの未来は通信のための標準的なプロトコルではなく、議論がない場合もあるようです。 あなたはゆっくりとその必要性を見てきましたが、あなたは既に以前の日、技術AI(北に送られた)の将来に関する記事を入手することができてきました。[電話 アイはコーヒーを注文します。 App は同意しましたか?](https://mp.weixin.qq.com/s/vRSn0jKRwGa-Ut6G5keD8w)というと、業界とのコミュニケーションが、徐々にコンセンサスになる。

将来、そして業界が受け入れることを可能にするパスを通じて、私たちが必要とするどのような合意が今あるかは、確信できないかもしれません。

今後の合意の輪郭について、私たちは考えています。[スマートWebの違いは何ですか?](https://mp.weixin.qq.com/s/wBgelNViCLyXm5Ha6igzbw)また、理想的なスマートボディ通信プロトコル、AgentNetworkProtocol(ANP)の設計も行っています。[https://github.com/agent-network-protocol/AgentNetworkProtocol](https://github.com/agent-network-protocol/AgentNetworkProtocol)。

未来の知的は、基礎的なデータとインターネットの間に対称的な存在であるべきだと私たちは考えています。これはANPの設計の核原則です。

MCP に戻って、AMP と MCP の最大の違いは、世界観の違いです。
- MCPはモデルをベースに、インターネットは自分のコンテキストとツールです。
- インテリジェントなコラボレーションのネットワークとして、集中的なインテリジェンスを持つ(エージェント・ネットワーク・プロトコル)。

MCP と同じではなく、それを通して得られるか否かを、業界に1つの可能性を探求できるようにするパスをとっています。

最後に、当社の合意に興味を持たれたら、連絡を取りたいと思います。特に、AI電話やアシスタント、スマートボディフレームワークや開発者の製品などであれば、今後の展望にご協力ください。
