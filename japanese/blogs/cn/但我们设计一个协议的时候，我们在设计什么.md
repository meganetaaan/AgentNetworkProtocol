# プロトコルを設計するとき、何を設計するのでしょうか?

## 合意は世界観の表現です

プロトコルを設計するとき、何を設計するのでしょうか?この質問は、複数のレベルで詳しく調べることができます。

プロトコルの設計は、単なる技術的な詳細の積み重ねではなく、全世界の運用法則の認識と理解、さらには将来の開発傾向の判断でもあります。この議定書には世界モデルが記述されており、世界がどのように運営されるかというルールと将来の発展の方向性が記述されています。どのキャラクターがこの世界モデルに含まれるのか、また異なるキャラクターがどのように相互作用するのかを設計する必要があります。

歴史上成功したすべての合意には、設計者が当時の技術環境と将来の傾向を正確に把握していたことが反映されています。たとえば、HTTP プロトコルの設計には、World Wide Web の創設者ティム バーナーズ リーの情報共有とハイパーテキスト システムに対する理解が反映されています。これは、クライアントとサーバーの役割と、それらが単純な要求と応答のパターンを通じてどのように対話するかを定義します。このシンプルで柔軟な設計により、HTTP はインターネットの基本プロトコルの 1 つとなります。

## エージェントプロトコルの世界観の違い

インテリジェント通信プロトコルの分野では、さまざまなプロトコルの背後に世界観の違いが反映されていることがわかります。現在よく知られている 3 つのプロトコル、MCP、ANP、Agora プロトコルを例に挙げます。

### MCP: モデル中心の世界観

MCP (Model Context Protocol) の世界観はモデル中心であり、インターネット全体がそのコンテキストです。 MCP は、典型的なクライアント/サーバー アーキテクチャです。クライアントは MCP プロトコルを使用して MCP サーバーに接続し、サーバーのさまざまな情報やツール機能にアクセスします。

この設計コンセプトは現在のインターネット環境に非常に適しています。これにより、AI モデルが既存のインターネット リソースに簡単にアクセスできるようになり、チャットボット製品の機能が強化されます。ある程度、MCP はモデルを中心として扱い、インターネット全体をモデルの延長として扱います。

MCP は、インターネットで広く使用されている標準である OAuth ベースの ID 認証スキームを使用し、このモデルが既存のインターネット アプリケーション上のユーザーのリソースにアクセスできるようにします。情報編成の観点から見ると、MCP は JSON-RPC を使用してサーバーのリソースとツール機能を読み取り/操作します。これは基本的に特別な API 呼び出しとして理解できます。

(注: この段落では、MCP 用カーソルなどの最近の AI プログラミング ツールのサポートについて説明します。情報はこちらで確認できます)

### ANP: エージェントネットワークに関する分散型の視点

ANP (Agent Network Protocol) はまったく異なる世界観を持っています。分散型であり、エージェントは相互に平等に接続されています。 ANP は、典型的な P2P (ポイントツーポイント) アーキテクチャです。どのエージェントも ANP を使用して別のエージェントに接続できます。集中型のサービス ノードはありません。

ANP の ID 認証は W3C DID 標準に基づいており、すべてのエージェントが相互接続できるようにエージェント間のクロスプラットフォームの相互運用性の問題を解決することに重点を置いています。情報組織の面では、ANP はセマンティック Web の Linked Data テクノロジーを中核としており、AI がアクセスし理解しやすいデータ ネットワークの構築を目指しています。

この設計コンセプトは、それぞれが同等のステータスを持ち、自由に接続および対話できる無数のインテリジェント エージェントで構成されるネットワークを予見するインテリジェント インターネットの発展の次の段階により適しています。

### Agora: 自然言語インタラクションの未来

Agora プロトコルはさらなる可能性を示しており、将来的にはエージェントが自然言語を使用して直接対話できるようになると考えられています。 AI テクノロジーの発展により、エージェントが独自の言語形式を進化させる可能性さえあり、自然言語は単なる過渡期である可能性があるため、この考えは将来的に可能です。

これら 3 つのプロトコルは、インテリジェント エージェント開発の 3 つの異なる段階を表しています。MCP は現在の問題を解決し、ANP は次のステップの問題を解決し、Agora はさらに将来の可能性を探ります。その背後には、各デザイナーの現在に対する判断、未来の予測、全世界の法則の理解、そしてその背後にあるデザインコンセプトが反映されています。

## 協定の成功の決定要因

最終的にどの協定が勝利するでしょうか?エコロジー、テクノロジー、能力はどれもとても大切ですが、最も根本的なものは何でしょうか？最も重要なことは、協定が業界の将来の発展方向と一致しているかどうかです。言い換えれば、プロトコル設計者が舞台裏で世界モデル全体を理解し、将来の開発について判断するかどうかによって、そのプロトコルが将来的に十分な活力を持つかどうかが決まります。

インターネットの進化を推進する最も重要な問題は、新しいテクノロジーの機能を最大限に活用する方法です。 PC インターネット時代には、Web テクノロジーによりオープン インターネットのアクセス機能が解放されました。モバイル インターネット時代、APP はモバイル デバイスの可能性を最大限に引き出しました。現在および今後 10 年間の新しいテクノロジーは、間違いなく、生成人工知能、大規模言語モデル、エージェントに代表される AI テクノロジーです。 AIの力をいかに解き放つかが、今後のインターネットの進化の方向性を決定する。

たとえば、従来のインターネットに基づいて設計されたドイツテレコムのプロトコルと、インテリジェントエージェントに基づいて設計された当社のプロトコルでは、どちらがより実現可能でしょうか?将来、インテリジェント エージェントがモノのインターネット上でも実行できるようになり、インテリジェント エージェントがモノのインターネット デバイスと非常に深く通信する必要がある場合、前者のルートがより現実的になる可能性があります。

## 歴史的経験: SIP と H.323 のケース

過去の事例は参考になります。 SIP と H.323 を例に挙げます。 SIP はプレーンテキストベースのプロトコルです。初期の頃は処理効率があまり高くありませんでした。 H.323 はバイナリ プロトコルで、非常にコンパクトで帯域幅を非常に節約します。しかし、最終的に勝ったのは H.323 ではなく SIP でした。これはなぜでしょうか?

答えは技術開発の一般的な傾向にあります。コンピューティング能力が向上し続け、コンピューティング能力がますます強力になるにつれて、文字列処理の効率はもはや根本的な問題ではなくなりました。 SIP のテキストベースの性質により、SIP はより柔軟でスケーラブルになり、デバッグと実装が容易になります。これらの利点は、短期的な効率性の利点よりも長期的にははるかに重要です。

この事例は、プロトコル設計が現在の技術条件下での最適化にあまり焦点を当てるべきではなく、長期的な技術開発の傾向や、使いやすさや柔軟性などの要素に焦点を当てるべきであることを示しています。

## プロトコルの未来: 自然言語への進化?

将来に目を向けると、プロトコルがすべて自然言語に進化する可能性はあるでしょうか?これは、特に制御層プロトコルで発生する可能性が非常に高くなります。伝送メディア層のプロトコルに関しては、効率と精度を考慮して、現在のバイナリ形式のままである可​​能性があります。しかし、制御プロトコルが自然言語形式に進化する可能性は十分にあり、その可能性は高いと思います。

大規模な言語モデルの機能が向上し続けるにつれて、自然言語は人間とコンピューターの対話やマシン間の対話の媒体としてますます自然なものになるでしょう。コントロール プレーン プロトコルに自然言語を使用することには、いくつかの利点があります。

1. **開発の閾値を下げる**: 自然言語を使用して要件と機能を説明すると、より多くの非技術者がプロトコルの設計と使用に参加できるようになります。
2. **柔軟性の向上**: 自然言語は、厳密にフォーマットされたプロトコルよりも柔軟性があり、より多くのあいまいさや不確実性を処理できます。
3. **シームレスな統合 **: AI の普及に伴い、自然言語は人間と AI の間、および AI と AI の間の最も自然なコミュニケーション方法になります。

## ブロックチェーンプロトコル: 別の世界観の具現化

最後に、異なる世界観のもう 1 つの重要な例として、ビットコイン プロトコルについて言及する価値があります。ビットコイン プロトコルは、分散化、不変性、コンセンサス メカニズムなど、ブロックチェーンと Web3 の背後にある中心的なアイデアを具体化しています。

ビットコイン プロトコルは、中央ノードを持たず、数学的および暗号学的原理に基づいて価値伝送システムを設計します。中央機関や信頼できる第三者には依存しません。この設計の背後には、伝統的な金融システムに対する不信感と、よりオープンで透明性のあるトラストレスな経済システムへの切望があります。

## インテリジェントなインターネットのビジョン

将来のスマートインターネットはどのような特徴を持つのでしょうか?私たちの調査によると、インテリジェント インターネットには次のような特徴があると考えられます。

1. **エージェントはインターネットの隅々まで侵入します **: 1 つの個人または組織に複数のエージェントがサービスを提供している場合があります。
2. **すべてのインテリジェント エージェントは相互接続および相互運用可能です。**: これは AI 機能を解放するために必要な条件です。
3. **パーソナル アシスタントはインターネットへの新しい入り口になりました **: インテリジェント エージェント間のつながりは、人間とインテリジェント エージェント間のつながりよりもはるかに大きいです。
4. ** ネットワークがよりフラットになりました **: エージェントは、サードパーティのプラットフォームを介さずに直接接続できます。

この文脈において、どのような合意が勝利を収めることができるでしょうか?私たちは、最終的に勝利したプロトコルは、エージェント間のシームレスな接続とコラボレーションをサポートでき、将来の AI テクノロジーの急速な発展に適応できる十分な柔軟性を備え、さらにスケーラブルで安全でなければならないと考えています。

## 結論

プロトコルの設計は世界を理解し、形作ることです。私たちがプロトコルを設計するときは、技術的な詳細を設計するだけでなく、頭の中で世界の運用モデルや将来の期待や予測も記述します。

合意が成功するかどうかは、その技術的利点だけでなく、それが技術開発の一般的な傾向に適合しているかどうか、また新技術の能力を最大限に発揮できるかどうかにも依存します。インテリジェントエージェントの時代には、人間にとってより多くの価値を生み出しながら、エージェント間の無料接続と効率的なコラボレーションをサポートできるプロトコルが必要です。

MCP、ANP、その他のプロトコルのいずれであっても、それらはすべて将来のインテリジェント インターネットの青写真を描こうとしています。技術開発のトレンドを真に理解し、将来のニーズに適応できるプロトコルだけが、長い歴史に名を残すことができます。
