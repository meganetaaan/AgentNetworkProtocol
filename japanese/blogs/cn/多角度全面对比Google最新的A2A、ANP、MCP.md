#  Googleの最新A2A、ANP、MCPを多角的に総合比較

Google は、新しいエージェント通信プロトコル A2A (Agent to Agent) をリリースしました。この記事では、A2A、ANP、MCPを多面的に徹底比較していきます。

## 問題は解決しました

ANP と A2A はどちらもエージェント間の通信の問題を解決するように設計されており、どちらもエージェントの通信における MCP の限界を認識しています。つまり、MCP はモデルをツールやリソースに接続することに優れています。

同時に、ANP と A2A は両方とも MCP を補完すると信じています。 ANP と A2A にはある程度の重複があります。 「一定の重複」がある理由は、A2A が企業内のインテリジェント エージェントのコラボレーションの問題を解決したいと考えているためです。公式サイトには明記されていませんが、デザイン、特にタスクのデザインからそれを感じます。

## 設計原則

設計原則の観点から見ると、ANP は A2A と多くの類似点があります。
- シンプルさと既存プロトコルの再利用を重視。
- アイデンティティの強調。エージェント ID は ANP のコア モジュールです。
- 分離 (不透明): エージェントは思考プロセス、計画、ツールを共有する必要がありません。これは、ANP、A2A、MCP の設計詳細における最大の違いです。

A2A も MCP の複雑さを認識し、中心概念としてタスクを使用することを選択する必要がありました。実際、タスクはツールやリソースよりも抽象的で高レベルの概念です。

MCP のツールとリソースも MCP のコンセプトに非常に適していますが、サンプリングとルートの設計を考慮する必要があると思います。

## プロトコルアーキテクチャ

ANP と A2A はどちらも、プロトコル アーキテクチャの観点からは P2P アーキテクチャとみなすことができます。 MCP は、接続だけでなく、プロトコルの概念やロール設定の点でも典型的な C/S アーキテクチャです。

P2P アーキテクチャがインテリジェント エージェント ネットワークにより適していることは疑いの余地がありません。

## トランスポート層

どちらも HTTP をサポートしています。さらに、MCP はローカル リソースにアクセスする必要があるため、便宜上 stdio もサポートしています。

## コアコンセプト

MCP の中心となる概念は、ツール、リソース、サンプリング、ルート、プロンプトです。

A2A の中核となる概念は、タスク、アーティファクト、メッセージ、パートです。

ANP の中心概念はインターフェイスです。これには、NaturalLanguageInterface (自然言語インターフェイス) と StructuredInterface (構造化インターフェイス) が含まれます。

ANP は、エージェント対話メソッドの定義をインターフェイスに分散化します。たとえば、インターフェイスはホテルを予約するための API であり、この API は結果を直接返します。 A2A と同様のタスクにすることもでき、タスクのステータスはインターフェイスで定義されます。ただし、プロトコル層では、タスクとステータスを直接かつ明示的に定義しません。

不透明度を見ると、次のようになります。
- MCPは相手の内部ファイル、ツール、リソース、その他の情報を閲覧できるホワイトボックスです
- A2A はグレーのボックスです。エージェントの思考プロセス、計画、ツールは共有しませんが、エージェント間のタスクやタスクのステータスなどを定義します。
- ANP はブラックボックスであり、2 つのエージェントは完全に不透明で、最終結果のみを提供します。柔軟性を保ちながら。

## エージェント ID

ここの違いは非常に大きいです。

**ANP**

プロトコル自体は ID 情報と認証情報を伝送します。現在、主に W3C の DID ソリューションが使用されています。エージェントは、他のエージェント プラットフォームでアカウントを申請することなく、独自の ID 情報を使用して他のすべてのエージェントと対話できます。

私たちは、DID が、特にインターネットのシナリオにおいて、インテリジェント エージェントに最も適した ID ソリューションであると信じています。もちろん、他の本人認証方法も拡張できます。

**A2A**

A2A は、HTTP 認証 (Basic、Bearer など)、API キー (リクエスト ヘッダー、クエリ パラメータ、または Cookie に配置可能)、Cookie 認証、OAuth 2.0、OpenID Connect など、OpenAPI でサポートされている認証方法を使用します。

A2A プロトコル自体は ID 情報を伝送せず、ID 検証情報のみを伝送します。 ID 検証情報は、アウトオブバンド、つまり、Oauth など、A2A プロトコルの外部の他の手段を通じて取得されます。

A2A は、企業の既存の ID システムを活用するように設計されています。ただし、エージェントのインターネットのシナリオでは、任意のエージェント間の接続を実現したい場合、A2A を使用するのはさらに面倒になります。

**MCP**

MCP は認証に Oauth を使用します。これも一元化されたソリューションであり、ツールとリソースを接続するシナリオに適しています。

## エージェントの説明

ANP は A2A に似ており、どちらも JSON を使用します。

A2A のエージェント記述ドキュメントは Agent Card という名前で、本質的には json ドキュメントです。

ANP のエージェント記述は、JSON-LD とセマンティック Web の技術である schema.org に基づいています。目的は、2 人のエージェントによる情報の理解の一貫性を向上させることです。

## エージェントの検出

MCP の検出仕様はまだ明らかになっていませんが、ANP や A2A と同様の検出メカニズムが使用される可能性があります。

ANP と A2A は両方とも RFC 8615 に基づいており、これはドメイン名の .well-known ディレクトリにメタデータ ドキュメントを追加するのと同等です。 A2Aのファイル名はagent.json、ANPのファイル名はagent-descriptionsです。

このソリューションを使用すると、検索エンジンによって簡単にクロールできるようになります。

## エージェント情報の組織

エージェントまたは MCP サーバーの外部情報の組織化には、A2A と MCP の両方で、リモート呼び出しテクノロジーに似た JSON-RPC が使用されます。

ANP はここでユニークです。 ANP は、セマンティック Web の Linked Data テクノロジーを使用します。目標は、AI がアクセスして理解しやすい AI ネイティブのデータ ネットワークを構築することです。

![](../../../blogs/images/ai-native-network.png)

この観点から見ると、ANP の技術的ルートは Web に近いと言えます。私たちは、将来のインテリジェント インターネットは非常にオープンなネットワークになると信じています。この方法によってのみ、情報が自由に流れ、AI の力を解放することができます。


## オープンソースライセンス

ANPのライセンスはMIT、Google-A2AのライセンスはApache 2.0です。

よくよく調べてみると、大手メーカーに売り込み、標準化に参加し、国際的なルートをとろうとする場合、企業法務部門が優先するプロトコルはApache 2.0になることが分かりました。 MIT はシンプルですが、貴社のような潜在的な特許リスクや商業化の経路を伴うプロトコル プロジェクトでは、企業の法務チームが立ち往生しがちです。

ANP は、オープンソース ライセンスの Apache 2.0 に変更されます。

## トレンド

A2A は MCP を補完すると主張していますが、ドキュメントを読む過程で、私は漠然とその可能性を感じました: ** このツールはエージェント ベースであり、エージェント ツールは ** です。

既存のツールをエージェントに進化させることはできますか?将来のエージェントもツールになるのでしょうか？

この観点から見ると、MCP と ANP を含む A2A の間にはいくつかの重複があるはずです。

## 業界エージェントプロトコルへの影響

MCP はモデル接続ツールとリソースの事実上の標準となっており、A2A を短期的に揺るがすのは難しいでしょう。しかし、それはANPに大きな影響を与えます。

良い影響は、インテリジェントなコミュニケーションとコラボレーションがより多くの人に見えるようになるということです。以前 MCP が流行ったとき、ANP について話しても、理解できない人が多かったです。これで、エージェントのコミュニケーションと協力の重要性を強調する必要はなくなりました。

悪い影響は、A2A と ANP の機能のほとんどが重複していることです。 A2A は Google に依存しており、その影響力は非常に大きいです。 ANP は主にオープンソース コミュニティに依存しており、その影響力は比類のないものです。これは ANP の発達に有害です。

ANP の最も価値のある部分は、実際には、将来のインテリジェント インターネットに対するコミュニティのビジョン、コミュニティの独自のインターネット概念 (接続は力です)、および DID+セマンティック Web の技術的ルートです。
