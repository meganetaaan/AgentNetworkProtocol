# エージェントインターネットの三つの大きな傾向：接続のあり方が、根本から変わる

私が好む、初期のインターネットの理念は、**接続は力である**、というものです。情報、人、ツールに自由につながれば、世界を変える力を持てます。

エージェントインターネットは、現在の接続のあり方を作り直し、プラットフォームから、つながりへと戻すでしょう。

以前の[Agentic Webは何が違うのか](智能体互联网有什么不同.md)に続き、今回は、ANP設計の土台である、三つの傾向を掘り下げます。

細部や経路を離れ、本質を見ると、微視的な予測より、全体の判断は容易なことがあります。考え方の土台は、二つです。
- **社会全体の運営コストを下げること。**
- **新技術であるAIの能力を、より引き出すこと。**

主な見方は、次のとおりです。
- 三つの中心的な判断があります。
  - **既存のソフトウェアを置き換える**。
    - **個人アシスタントが新しい入り口**となり、多くのアプリを置き換え、複合的な用途で、10倍よい体験を提供する。
    - **企業向けソフトウェアを置き換え**、企業が直接公開し、利用者にサービスを届ける。
    - **個人アシスタントと企業、エージェント同士が直接つながり**、第三者のプラットフォームを経由しない。
  - **任意のエージェント同士が相互接続**し、情報の孤立を破る。
    - 完全なコンテキストで、より賢い意思決定を助ける。
    - すべてのツールを使い、複雑な作業を完了する。
    - **エージェント間の接続の割合が増え**、主要な形になる。
  - **プロトコルによる、AIに自然な接続**を使う。
    - **Computer Use／Browser Useは過渡的**で、人の模倣では、能力を十分に引き出せない。
    - **プロトコルが最も効率的**で、人向けのUIやHTMLより、元のデータを直接扱える。
    - HTTPのような標準が現れ、**AI専用で、アクセスしやすいデータネットワーク**が生まれる。
- AIは先進的な生産力、インターネットは、その直接の生産関係です。最大の障害であるデータの孤立など、既存の構造は変わります。
- 低コストで、よい体験の方法があれば、大手がしなくても、スタートアップが実行します。
- 私たちは、初期の精神とAIによる再構築を組み合わせ、**「接続は力である」という未来像へ戻り、開放的で、活力と創造性のあるインターネットを作りたい**と考えています。
- **プラットフォームが力を持つ**形から、**接続が力を持つ**形に変わります。

実際の行動でも探っています。**エージェント時代のHTTP**を目指すANPです：https://github.com/agent-network-protocol/AgentNetworkProtocol。

コミュニティへの参加も歓迎します。合言葉は、**オープンソースで、接続と協働を定義する**ことです。

以下、本題に入ります。

## 1. 既存のソフトウェアを置き換える

### 1.1 個人アシスタントが、新しい入り口になる

多くのアプリは消えるでしょう。正確には、端末の画面を提供せず、アシスタントにデータとサービスを渡し、アシスタントが、個人に合わせたUIを作るようになります。

![](../../../blogs/images/human-ai-agent.png)

ホテル予約だけのような単一用途では、今のアプリより、格段によいとは限りません。

しかし、旅行計画、特に複数人の旅行のような複合用途では、全情報へのアクセスを認可されたアシスタントが、すべてのツールで計画し、**現在を大きく上回る体験**を提供できます。

最初は翻訳などのツール、次にニュース、買い物、SNSが置き換わりそうです。感情的な価値があり、端末の描画も複雑なゲームは、短期には残るかもしれません。

### 1.2 企業向けのソフトウェアを置き換える

顧客対応、販促、ERP、CRM、通信ツールなども、置き換わるでしょう。すでに多くの企業が取り組んでいます。

大きな企業も小さな商店も、外部向けのエージェントを公開すれば、消費者とのつながり方が変わるかもしれません。

### 1.3 個人アシスタントが、直接つながる

現在、人と商店は、プラットフォームを通じて接続します。双方にエージェントがあるなら、直接つながってはどうでしょうか。

なぜ以前は難しく、今は可能なのでしょうか。

以前、各企業が個別のサイトやアプリを作れば、人は多数にログインして使い、企業も開発・保守するため、双方にコストがかかりました。プラットフォームなら、一度作ったソフトウェアの限界費用が極めて低く、多数に提供でき、人も少数のアプリで済みました。

今は、三つが変わります。
1. 開発費が下がり、実行時の計算費が上がって、コストの優位は、より規模の効果に依存します。将来、プラットフォームを使うことと、自社または購入したソフトウェアにクラウドの計算力を加えることの、費用差は小さくなるかもしれません。
2. 個人アシスタントが、人に代わり、企業のエージェントを直接使うため、人の利用コストが減ります。
3. AIが、プロトコルの調整、テスト、更新などの接続コストを解決します。

直接接続の技術と費用の障壁は、小さくなります。

商業的には、電子商取引プラットフォームの収益化率は、約3～5%です。100元の取引で、3～5元を得ます。不当な利益という意味ではなく、この運営形態のコストが高いのです。

直接接続で、取引コストを総GMVの3%以内にできれば、競争力が高まります。

もちろん、購入後のサポートや取引の安全など、未解決の問題も多くあります。

## 2. 相互接続が必要――データの孤立が、AIの可能性を抑えている

現在の最大の障害は、データの孤立だと考えます。

### 2.1 完全なコンテキストを得る

相互接続によって初めて、個人や企業の判断を、より賢くできます。

交友の情報はWeChat、買い物はTaobao、JD、Pinduoduo、娯楽は抖音や快手など、別々です。Manusのような汎用エージェントが、公開情報で、ごく一部の作業しか行えない理由です。

これは、AIが最初に解くべき問題でもあります。

相互接続で、自由に情報が流れ、個人アシスタントに集まれば、完全なコンテキストを得られます。

### 2.2 すべてのツールを使う

ほかのエージェントの全機能を使えて初めて、より多く、複雑な仕事を行えます。

ホテル、航空会社、観光地のエージェントに、個人アシスタントからつながり、宿泊、航空券、入場券を予約します。

すべての情報へのアクセスを認可し、インターネットの全ツールを使えるなら、Manusのようなものは、現在のどのアプリにもない体験を実現できます。

### 2.3 エージェント同士の接続の割合が高まる

cozeやdifyなど、現在の多くは人向けです。将来は、個人アシスタント以外の大部分は、人へ直接ではなく、ほかのエージェントにサービスを提供するでしょう。

人から受けたタスクを分割し、何度も相手と協働するため、その接続回数は、人とのものを上回ります。

これが、将来の主要な接続になります。

## 3. プロトコルで接続する――AIに自然な方法

### 3.1 Computer Use／Browser Useは、過渡的である

以前からのComputer Useも、最近Manusが使うBrowser Useも、人のやり方を学ぶ、過渡的なものだと考えます。

すぐに情報とツールへ接続できる利点はありますが、問題もあります。
- Computer Useは、多くの情報を得ても、高価で、端末を占有します。
- Browser Useは、より安くても、アプリの情報にアクセスできず、クラウドのログインに安全上の問題があり得ます。

もっと自然な方法が必要です。

### 3.2 最も効率的なのは、プロトコルである

AIは、人向けのUIやHTMLより、直接のデータを扱う方が得意です。MCPとANPは、この点では同じ技術的な方向にあります。

また、公開情報を、**人向けの画面のリンクの網とは別の、AI専用で、アクセスしやすいデータネットワーク**にできます。

### 3.3 標準が現れる

HTTPのような共通の標準があって初めて、業界全体が相互接続し、本物のエージェントインターネットになります。

多くの標準化団体やコミュニティが研究し、ANPのほか、Agora Protocol、ACP、Agentsjsonなども現れています。

## 4. 三つの判断は、実現するか

生産力と生産関係から考えられます。

**AIは最も先進的な生産力であり、インターネットは、それに最も関わる生産関係です。**データの孤立などの障害は、必然的に変わるでしょう。不確かなのは、その経路です。

**既存のスーパーアプリとプラットフォームは強大**で、利用者、データ、成熟した収益モデルがあり、現在を維持する動機があります。

それでも、よい解決策があれば、TがしなくてもB、BがしなくてもAが取り組みます。BAT（Baidu、Alibaba、Tencent）がしなくても、スタートアップが行うでしょう。**スタートアップとオープンソースは、この技術革命の重要な力です。**

## 5. 私たちの理念：初期の精神と、AIによる再構築

まとめれば、この二つの考え方です。

1. **初期のインターネットの精神**

Web 1.0の開放性に戻り、AIを使って、**プラットフォームが力を持つ**現在から、**接続は力である**という、初期の構想に戻るべきです。

2. **AIに自然な再構築（Agent-Native Web）**

単なる懐古ではなく、新しい技術の要素で、秩序と基盤を作り直します。

人のUIではなく、エージェントのための、プロトコルとデータのインターフェースを設計します。

ページの網に適応させるのではなく、AI専用で、アクセスしやすいデータの網を作ります。
