# エージェント通信プロトコルの概要

以下は、現在の主流のエージェント通信プロトコルの詳細な紹介と比較です。

---

## 1. MCP (モデルコンテキストプロトコル)

- **開発チーム**: Anthropic による提供
- **問題 ** に対処: 外部データ ソースおよびツールに接続して対話するための大規模言語モデル (LLM) に標準化されたインターフェイスを提供することを目的としています。
- **技術ルート**: JSON-RPC 2.0 メッセージ形式に基づいて、状態接続を確立し、サーバーとクライアント間の機能ネゴシエーションをサポートします
- **生態開発**: 業界の事実上の標準となり、広く採用されています
- **公式サイト**：https://spec.modelcontextprotocol.io/specification/

---

## 2. ANP (エージェント ネットワーク プロトコル)

- **開発チーム**: Chang Gaowei が代表を務める地元の中国チームによって開発されました。これは GitHub でオープンソース化されており、中国で初期のインテリジェント エージェント通信プロトコルの 1 つです。
- **問題の解決**: エージェント時代の「HTTP」の構築を目標に、エージェント間のID認証、暗号化通信、プロトコルネゴシエーションの問題の解決に取り組む
- **技術ルート**: 分散型アーキテクチャを採用し、W3C DID (Decentralized Identity Identifier) 標準に基づく ID 認証とエンドツーエンド暗号化を実装します。 「メタプロトコル層」を導入して自然言語主導のプロトコルネゴシエーションとコード生成をサポートし、エージェントがコンテキストに基づいて通信プロトコルをネゴシエートできるようにします。ネットワーク全体はポイントツーポイントのメッシュ構造であり、集中サーバーは必要ありません。
- **生態開発**: オープンソース化されており、リファレンス実装 (AgentConnect など) を提供しています。中国のオープンソース コミュニティや大学の開発者の間で注目を集めており、W3C WebAgents ワーキング グループに参加しています。現在、エコロジーはまだ主に国内で行われており、国際協力が拡大されています。
- **公式サイト**：https://agent-network-protocol.com/

---

## 3. アゴラプロトコル

- **開発チーム**: オックスフォード大学とEigent AIによって提案された、柔軟性、効率性、移植性のバランスを達成することを目標とした研究メタプロトコルです。
- **問題の解決**: 「エージェント通信のトリレンマ」(トリレンマ) への対処: 汎用性、効率性、移植性の両方を達成することは困難です。現在のエージェントは、多くの場合、プラットフォーム間での通信やプロトコル形式の適応に困難を抱えています。
- **技術ルート**: LLM の理解能力を使用して「プロトコル文書」の交換を推進し、エージェントは自然言語を通じて通信プロトコルを説明し、合意に達します。これは 3 つのプロトコル層に分かれています。一般的なシナリオでは既知の API が使用され、複雑なシナリオでは LLM を使用してプロトコルが生成され、極端な場合には自然言語ネゴシエーションが使用されます。
- **生態開発**: 現在は概念実証段階にあり、オープンソース実装はありません。これは学術レベルの研究であり、まだ産業応用には至っていない。
- **公式サイト**：https://agora-protocol.org/

---

## 4. エージェントプロトコル

- ** 開発チーム **: AI Engineer Foundation によって開始されたコミュニティによって主導され、中心的な開発者は Div99 であり、目標は統合エージェント API を定義することです。
- **問題の解決**: 現在のエージェント システム間のインターフェイスの不一致、統合の難しさ、再利用できないツールの問題を解決して、相互運用性とパフォーマンスの比較を容易にします。
- **技術ルート**: RESTful API 仕様セット (OpenAPI 形式) を提供し、起動、リセット、送信ターゲット、ストリーミング出力などのコア操作をサポートし、将来的には支払いやその他の機能のサポートを拡張する予定です
- **エコロジー開発 **: エージェントの評価と標準化された通話のために Auto-GPT コミュニティで最初に採用されました。 TypeScript と Python SDK を提供し、徐々に汎用的な「エージェント インターフェイス プロトコル」の候補になりつつあります
- **公式サイト**：https://github.com/AI-Engineer-Foundation/agent-protocol

---

## 5. agents.json

- **開発チーム **: コミュニティ メンバー (Wildcard AI など) によって提案され、まだ正式に標準化されていません
- **問題** を解決します: Web サイトには、AI エージェントにインタラクティブ機能を公開する機械可読な方法がありません。 Agents.json を使用すると、Web サイトでインターフェイス、認証方法、権限、使用ポリシーなどを宣言し、クローラーがヒューマン インターフェイスを取得するのを回避できます。
- **テクニカルルート**: インストールされている標準のJSONファイルであるrobots.txtとssitemap.xmlに触発 `/.well-known/agents.json` パスの下には、ウェブサイトが提供するスマートボディ用の利用可能なインターフェイスと特権が含まれます
- **生態開発**: まだドラフト段階にあり、主流のプラットフォームはまだサポートされていません。ただし、Reddit やテクノロジー ブログで開発者によって議論されており、将来的には Web3 または AI Web の重要なインフラストラクチャになることが期待されています。
- **公式サイト**：https://docs.wild-card.ai/agentsjson/introduction

---

## 6. AITP (エージェントインタラクションおよびトランザクションプロトコル)

- **開発チーム **: NEAR 共同創設者 Illia Polosukhin が率いる NEAR プロトコル (ブロックチェーン プラットフォーム) によって開始され、2025 年初めに提案
- **問題 ** を解決します: エージェントには、信頼境界間の通信と値交換のための標準プロトコルがありません。 AITP は、エージェントが会話の中でサービスの交渉、支払い、サブスクライブを行えるように設計されています。
- **技術ルート**: スレッド化された対話モデル、メッセージ形式 JSON を採用し、拡張機能モジュール (支払い、データ要求、意思決定交渉など) を備えています。本人認証や暗号化通信を重視した複数の通信プロトコル（HTTP/WebSocket）をサポート
- **生態開発**: NEAR AI Hub によって最初に採用され、Web3 シナリオに適用されました。現在はアルファ段階です。 NEAR コミュニティは最初にこれを実装して実証し、他のエコシステムにも拡大する予定です。
- **公式サイト**：https://github.com/nearai/aitp
- **応用プラットフォーム**：https://app.near.ai/agents

---

## 7. ACP (エージェント接続プロトコル、Cisco AGNTCY プロジェクト)

- **開発チーム **: シスコが LangChain、Galileo、その他のパートナーと協力して AGNTCY エコシステムを構築し始め、2024 年末までにオープンソースになる予定です
- **問題の解決**: 異なるエージェント フレームワーク間で相互運用できない問題を解決し、LangChain や Haystack などの異なるフレームワークのエージェントが相互運用できるようにします。
- **技術ルート**: 標準化された OpenAPI インターフェイスと JSON 通信プロトコルを提供し、エージェント記述標準 (OASF) とディレクトリ サービスをサポートし、エージェント機能の登録、検出、呼び出しをサポートします。セキュリティ認証とストリーミング、マルチラウンドセッションなどの機能を重視
- **エコロジー開発 **: Cisco から企業承認を取得し、LangChain などのコミュニティからの初期参加を得ました。仕様と SDK はオープンソース化されており、「インテリジェント インターネット」の通信層プロトコルを構築することを目的とした標準化団体に推進される予定です。
- **公式サイト**：https://github.com/agntcy/acp-spec

---

## 8. ACP (エージェント通信プロトコル、IBM)

- **開発チーム **: BeeAI プロジェクトの一環として IBM Research が主導し、2024 年末に設計が開始され、現在はアルファ版であり、Linux Foundation AI コミュニティが主催しています。
- **問題の解決**: Anthropic MCP (Model Context Protocol) の拡張に基づいて、エージェント間の通信、機能発見、コンテキスト共有の問題を解決し、マルチエージェント システム用の標準化された通信プロトコルを構築します。
- **技術ルート**: JSON-RPC に基づいており、MCP 形式および拡張と互換性があり、エージェント機能の登録、対話管理、および ID 認証をサポートします。実用性を第一に考え、複数の通信プロトコル（HTTP、WebSocket）をサポート、将来的には状態永続化、ストリーミングなどもサポート予定
- **生態開発**: IBM オープンソースによって開始され、コミュニティが共に進化することを望んでいます。現時点では大規模な導入は行われていない。目標は、これを企業のマルチエージェント システムの標準プロトコルとして推進することです。
- **公式サイト**：https://docs.beeai.dev/acp/alpha/introduction

---

## 9. LMOS（言語モデルオペレーティングシステム）

- ** 開発チーム **: Eclipse Foundation によって育成されたこのプロジェクトは、当初はドイツテレコムの AI インフラストラクチャ プロジェクトでしたが、後にコミュニティ オープン プロジェクトになりました。
- **問題 ** を解決します: 現在のマルチエージェント システムの展開とコラボレーションは困難であり、統合されたインフラストラクチャが不足しています。 LMOS は、エージェントの検出、登録、通信、スケジューリング、セキュリティのためのオペレーティング システム レベルの基本フレームワークを提供することを目的としています。
- **技術ルート**: W3C Web of Things 標準をベースにしており、アイデンティティ層 (DID)、トランスポート層 (交渉可能な HTTP/MQTT/P2P)、およびアプリケーション層 (エージェント機能の記述に JSON-LD を使用) の 3 層アーキテクチャを採用しています。グループ管理と許可システムにより、ローカルおよびグローバルの検出をサポート
- **生態学的開発**: Eclipse コミュニティでの孵化段階にあり、まだ大規模に商用化されていません。ただし、ANP、AITP、MCP、その他のプロトコルを統合できる統合マルチプロトコル プラットフォームの可能性があると考えられています。ドイツテレコムなどの企業の支援により導入の可能性があり、将来的には業界の共通インフラとなることが期待されている。
- **公式サイト**：https://eclipse.dev/lmos/docs/multi_agent_system/agent_communication

---

## 10. IEEE SA-P3394 (大規模言語モデルエージェントインターフェース標準)

- **開発チーム **: IEEE Standards Association によって組織されたワーキンググループによって開発されました
- **問題の解決**: 異なる AI システム間の相互運用性を確保するために、大規模言語モデルのエージェント インターフェイスの標準化された仕様を提供します。
- **技術ロードマップ **: リファレンス実装が開発中で、BSD3 ライセンスに基づいてリリースされる予定です。複数の通信プロトコルに対応しながらAPI仕様設計に注力
- **エコロジー開発**: 約1年にわたって開発が進められ、着実に標準化作業が進められており、業界から幅広い注目を集めています。
- **公式サイト**：https://standards.ieee.org/ieee/3394/11377/

---

## 11. WOT（モノのウェブ）

- **開発チーム**: W3C Web of Things ワーキング グループが主導
- **問題の解決**: IoT デバイス間の相互運用性とデータ交換の課題を解決し、IoT 用の標準化された Web インターフェイスを提供します
- **技術ルート**: Web テクノロジーを使用して IoT デバイスを接続し、クロスプラットフォーム デバイスのアクセスと統合を簡素化します。
- **生態開発**: モノのインターネットの分野における重要な標準の 1 つとして発展し、複数のプロジェクトやプラットフォームで採用されています。
- **公式サイト**：https://webthings.io/


## 比較の概要

これらのエージェント通信プロトコルにはそれぞれ独自の焦点とアプリケーション シナリオがあり、通常はいくつかのカテゴリに分類できます。

1. **モデル指向プロトコル **: MCP など、モデルと外部ツール間の相互作用に焦点を当てる
2. **エージェント指向プロトコル**: ANP や ACP など、エージェント間の通信とコラボレーションに重点を置いています。
3. **ネットワーク指向プロトコル**: WOT、Matter/Thread など、デバイスの相互接続と相互運用性に重点を置いています。
4. **メタプロトコル**: プロトコルのネゴシエーションと動的生成に焦点を当てた Agora など

AI とエージェント テクノロジーの発展に伴い、これらのプロトコルはより標準化され、相互運用可能で、安全で信頼性の高い方向に進化し、エージェント インターネットのインフラストラクチャを共同で構築することになります。
