# オープンソースのスマートプロトコルの比較:MCP、ANP、アゴラ、agants.json、LMOS、AITP

スマートボディ通信プロトコルの開発では、業界に出現したスマートボディ通信プロトコルを収集し、OpenAIのデプレサーチを使用して、目的、キーテクノロジー、適用シナリオ、技術的なアーキテクチャ、互換性と拡張、オープンソースおよびエコロジー、将来の開発見通しを分析しました。 いくつかの場所は非常に正確ではないかもしれませんが、それらは参考のために良いです。

昨年、オープンソースのスマートボディコミュニケーションプロトコルの設計と開発をスタートさせました。この分野を初めて勉強するチームとして、過去2～3か月で非常に明確に注目しています。

オープンソースプロジェクトを歓迎し、オープンソースのコミュニティに歓迎します。個人開発者や人工知能の分野で会社であるかにかかわらず、私たちはオープンソースのコミュニティを歓迎します。スマートボディコミュニケーションプロトコルは業界共同構築をもっと有効にする必要があります。

## MCP(モデルコンテキストプロトコル)

### 目的の問題
フェイスツープルポーズ**大型モデルコンテキストアクセス**：
- コンテキストでフラグメントされるAIモデルと外部データソースの統合の問題に対処します。
- LLM の統一基準を容易に提供し、コンテンツライブラリ、ツール、環境を安全にアクセスし、データの隔離島を破壊し、各データソースのカスタマイズされた統合を回避します。

### 主要技術
**RPCフレームワークを開く**：
- JSON-RPC 2.0 の定義基準に基づく要求/応答/通知メッセージ形式。
- 導入事例**能力相談**柔軟性と拡張性を高めるプロトコル機能(粒子軸受)のサポートに、メカニズム、クライアントおよびサービスエンドを動的に合意しました。
- ローカル双方向通信(標準IOパイプライン、HTTP + SSEフロー出力など)が現在利用可能。リモートコミュニケーションは、道路地図でサービスディスカバリー等を特定しています。
- AIアプリケーション向け概念的「USB-Cインタフェース」です。

### シーンを適用する
**AIアプリケーション統合**：
- 業務システムに組み込まれたLMの必要性、企業知識銀行の質問や回答、プログラミングアシスタントドッキングコードライブラリ/IDE、オフィスアシスタントアクセスカレンダーメールなど、幅広いデータソースとツールへの迅速なアクセスを適用するシナリオ
- MCP を通じて、開発者は、データベース、クラウドファイル、開発環境などを接続するための統一されたインターフェイスで LLM を提供できます。
- 主にのための瞬間のために、**ローカルまたはイントラネット**リモートサポートとしてサービス全体でエージェントの連携をクラウドポイントで拡張できる環境内の Agent の相互接続のための内部ツールが、参加します。

### 技術的な建築
**クライアントサーバ構造**：
- MCP は、MCP サーバーとしてカプセル化された外部データソースをクライアントとして使用している AI モデルのこの側面を見ます。
- 双方がよく定義されたJSONメッセージを RPCの呼び出しに同様のパターンで交換しました。
- 転送層の現在のサポート**ローカルパイプ**(標準入力出力ストリーム)**HTTP の長い関係 +SSE**(サーバー・セント・イベントの単方向性)**リクエスト/応答またはストリーミングメッセージ**。
- 各転送には、独自の情報交換モード要件があります。
- 現在、コミュニケーションは、社内外のサイトに限られており、シンプル(接続やリモートアイデンティティの問題はありません)であることを確実にするためです。
- 将来の計画には、認証認可、サービスディスカバリー、非ステート操作などの機能をカバーするリモート接続機能が含まれます。
- そのため、MCPは、**一つひとつに。**プラグインの呼び出しと同様に、モデルとリソースサービス通信は、複数のエージェントルータをカバーしません。

### 互換性と拡張
**統合の容易**：
- MCP は、JSON/HTTP などの一般的な技術を使用して、透明性を詳細に達成し、既に Claude や MCP クライアントをサポートする他のコンポーネントがローカル展開のシンプルです。
- オープンソースコードとSDKを絞り込み、一般的なシステム(Google Drive, Slack, GitHubなど)のMCPサーバーの例を提示し、直接アクセスを容易にします。
- 契約が開いていると、他の大型モデル(オープンソースLMなど)も続行して、モデル全体で共通している。
- 現在、MCP はリモートアクセス能力が欠如していますが、将来的にはマイクロサービスやクラウドに適応することができます。
- 詳しくはこちら**能力相談**メカニズムは妥協することなく新しい機能モジュールを可能にし、既に新しい機能性を利用するために相談できるクライアントが既に存在していきました。
- 全体は既存のシステム(特にRET-styleサービス)と容易に統合され、標準的なLMプラグインコンポーネントとして使用できます。

### オープンソースとエコロジー
**人類のオープンソース標準**：
- SDKの正規化と部分的な実現のためにMCPがオープンしました。
- Anthropic は、ローカル MCP サーバーを Claude デスクトップ アプリケーションにサポートし、データアクセスのデモも加えました。
- 初期の生態学には、ブロック、アポロなどの先駆者が組み込まれています。また、Zed、Reprit、コーデム、Soursegraphなどのツール会社を開発し、コード関連エージェントのMCPを強化する共同作業を行っています。
- コミュニティは、Githubとサードパーティツール(MCPがクライアントを可視化するなど)のMCP規範を維持しています。
- 2024年の終わりにリリースされたため、エコロジーのスタートアップフェーズは焦点が高かったし、大規模なプラント(例えば、Reddit開発者がMCPブレークスルーを達成したと議論した)から強力なサポートとディスカッションがありました。
- MCPは、オープンライセンス、コミュニティの貢献を促進し、トランスミッションメカニズム、サーバ実現などを公開しています。
- 今後は、リモート機能やLMMの互換性の出現と拡張し、MCPエコロジーは「LLMプラグイン市場」と同様のパターンになります。

### 今後の展望
**短期リードを拡充**：
- MCP は、人類学と初期の開業医に戻ってきています。**実態基準になるのは、**LLMツールへのアクセス
- リモート機能の完成に伴い、MCPはアプリケーションの範囲を急速に拡大し、ビジネスアプリケーションのしっかりした足場を確立する可能性があります。
- 利点は...**シンプルで実用的。**開発者に優しい、エコロジーを促進する大きな植物があります。
- 長期的には、MCP は現在、集中型アイデンティティとマルチエージェントの相互作用を欠いているか、大規模な Agent ネットワークの構築に制限されています。
- コミュニティとコミュニティが重複し続け、アイデンティティなどのモジュールを追加していれば、MCP や一般的なプロトコルが開発されます。
- 要約すると、MCPは**大型モデルコンテキスト統合**フィールドは有望で、「AI時代のUSBインターフェイス」になることができますが、Agent接続プロジェクトでは他の合意と一致する必要があります。

## ANP(エージェントネットワークプロトコル)

### 目的の問題
フェイスツープルポーズ**スマートボディ相互接続**：
- 複数のインテリジェント間のコミュニケーションとコラボレーションの欠如を「エージェントコミュニティ HTTP」ビジョンとして知られる。
- 直接クロスプラットフォーム、マルチサブジェクト通信を可能にし、インテリジェントの作業をサポートしてネットワークを編成できるように、スマートネットワークにおけるアイデンティティ信託と接続の課題に焦点を当てます。

### 主要技術
**3層構造+ 地理的アイデンティティ**：
- 採用情報**W3Cは中央IDに行きます。**認証および認証不能な認証とエンドツーエンド暗号化された通信を実現するアイデンティティレイヤーの標準的な建物。
- 自在なDIDアプローチを設計し、集中力と大量着陸のバランスをとるためのパスワードでセンターを交換します。
- 導入事例**メタペーストレベル**「プロトコル」は、スマートボディが自動的に自然言語の通信プロトコルを交渉し、アプリケーションレイヤープロトコルコードを生成することを可能にします。これにより、自律的なドッキングと契約のアップグレードが可能になります。
- 識別、暗号化された通信、メタ合意協議およびアプリケーションレイヤープロトコルの説明のための完全なスタック容量。
- スマートなネットワークは、LML自動組織ネットワークやコンサルティングコミュニケーションプログラムを通じて自己組織ネットワークに参加することなくコラボレーションできます。

### シーンを適用する
**多能連携**：
- ビルドにフィット**スマートの集中型ネットワークへ。**サードパーティのサービスエージェント、インターネットに接続されたデバイス用のスマートエージェント、または複雑なタスクを実行するための自動エージェントの石炭処理に直接相談する個人AAIアシスタントなど。
- これは、高いセキュリティ要件と統一された信頼センター(例えば、クロスプラットフォームの個人データ統合)の欠如を持つシナリオのために特に当てはまります。
- また、エージェントがオープン合意の下で異なるチームと相互作用する性エージェントコミュニティを勉強するために使用することができます。

### 技術的な建築
**地点から位置までのネットワーク**：
- ANP の**P2Pの中央へ。**自分のスマートボディと直接セキュアなコミュニケーション接続を構築することができます。
- DIDのアイデンティティ交換と検証による自信構築、コミュニケーション協定やフォーマットの交渉。
- 3層構造:底面**アイデンティティと暗号化レイヤー**信仰の安全と信頼性を保証します。**メタペーストレベル**2つの(または複数の)エージェント間のアプリケーションプロトコルの自動交渉を担当する。 上部**プロトコルレイヤーを適用**特定のビジネスデータ交換の実装では、エージェントは、セマンティック・説明によるレイヤー・合意を選択または生成できます。
- この構造により、エージェントネットワークは、相互のネットワークとして接続されるように緩やかに接続することができます。単一のポイントサーバはありません。また、各々の情報を調べて互いに接続する Agent だけです。
- 既存のWebインフラ(WebSocketやP2Pなど)で実現でき、AgentConnectの公式フレームワークが提供できます。
- ネットワークポップアップサポート**多重ジャンプネットワーク**エージェントは、集中サーバーに限らず、要件を満たす他のエージェントのコラボレーションを動的に見つけることができます。

### 互換性と拡張
**開閉式、完全**：
- AMPは完全に開いています(仕様と参照の実現)、既存のWeb規格(DID、セマンティックウェブに基づいて)と組み合わせることが設計されています。
- 様々なエージェントフレームワークのサポートは、AFPネットワークによって提供できます。これにより、識別とメタアグリーメントレベルが達成されます。
- 詳しくはこちら**層構造**クリア、レイヤーは新しい暗号化アルゴリズムと新しいアプリケーションレイヤープロトコルタイプで、必要に応じて交換またはアップグレードできます。
- パス。**卓越した能力の記述**, 第三者は、新しいエージェント機能を定義し、協議での使用を識別することができます.
- 互換性のために、APPプロトコル文書とコードは中国語と英語で利用でき、統合しきい値の低下が起こります。
- インターネット参加者は、ルーティングのために特定のプラットフォームに依存することなく、独自のAMPAgentを達成することができます。
- 理論的には、既存の合意をブリッジすることが可能です。エージェントの代理店とDID認証をサポートしている場合は、AMPエージェントが利用できるサービスもAMPエージェントと通信することができます。
- そのため、業界採用率のボトルネックと大きなネットワークにANPをスムーズに拡大することができます。

### オープンソースとエコロジー
**国内のオープンソース ファースト**：
- 中国語チーム(Shang Gao Weiなど)が開発・オープンし、GitHubで公開された規範やコードを発行しました。
- 先ほどのスマートボディコミュニケーション協定として、業界初のAI開発コミュニティが業界初のエージェント通信契約を呼び出されました。
- 現在、エコロジーには、AgentConnect の達成フレームワークと補完的な DID 方法論規範が含まれます。
- 主に国内で通信し、CSDNなどの複数のタイポロジーがあります。
- しかし、比較的限られたグローバル可視性は、より多くの国際開発の俳優を必要とします。
- AMPは、前線に近い(OxfordのAgoraとのコンサートで考える交渉家と)、コミュニティ基準を一緒に持ち、多言語SDKを提供することができれば、Agenic Webにとって重要なリンクになるかもしれません。
- オープンソースの契約は、フレンドリーでビジネス的で個々の試験が歓迎されています。
- 国内レベルでは、ANPは、大規模な非発散モデル/アプリケーションとエコロジカルに統合されることが期待されます。海外では、開発者をエコビルディングに引き付け、エージェントネットワークの真のグローバル相互接続性を実現するために推進する必要があります。

### 今後の展望
**技術の総合力で、環境ニーズも高まっています。**：
- AMPは、そのアイデアを高度化し、アイデンティティの信頼と自動相談の問題を事前に解決しました。**高い技術成熟度**(エンドツーエンドネットワーク通信を実現)
- 今後、エージェントネットワークのオープンにつながっています。
- 広く採用されている場合は、APPはAgenic Webのボトムアップ通信フレームワークになる可能性があります。
- しかし、今 APPは比較的弱い国際的な影響力と全国のチームによって運転されます。**エコスケール**気になるのは、
- 利点の将来は、まず第一に、より多くの開発者や組織が生態学的改善に惹きつけることができるかどうか、そして第二に大きな企業がDIDルートをサポートしているかどうかによって異なります。
- エージェントネットワークのルーティングがトレンドになる(例:Webからアンセントレーステータスまで)、ANPは非常に魅力的です。
- 巨人が私的合意を好む場合、ANPは小規模な基準になることができます。
- しかし、MCP チームはオープンアイデンティティの重要性を認識しているとおり、フロントの ANP の設計が参照されるか、リードに残るように統合されることが期待されます。

## アゴラ。

### 目的の問題
フェイスツープルポーズ**LLMスマートボディネットワークのトリプルの問題**：
- 同時にコミュニケーションの高度化を目指した**多機能、有効およびポータブル**。
- 各モデルの分離とアクセス不能の現状に対応し、さまざまなシナリオに適応したコミュニケーションプログラムから派生する独自の能力で大規模なモデルを使用して拡張された「世界クラスのLLMスマートボディネットワーク」を構築することが提案されています。

### 主要技術
**LLM 主導メタプロトコル**：
- コアイノベーションは**プロトコル文書(PD)**文脈の通信プロトコルを記述する機構。
- エージェントは、中央登録なしでのみハッシュ値の識別契約を使用して、転送可能なオブジェクトとしてプロトコルを記述できます。
- 自然言語の理解と生成、指示に従ってコードライティング、複雑な基礎に関する相談、アゴラはインテリジェントな体が異なるシナリオのためにさまざまな通信フォーマットを使用することを可能にします。
- 既存の高効率プロトコル/ルート処理の一般的なHFインタラクティブな使用により、効率性が向上します。また、一般的なプロトコルシナリオや標準プロトコルのシナリオは、Agent は構造化されたデータや自然言語で新しいプロトコルオプションを交渉し、LLM によって生成され、実装されています。
- 自己適応のこのレベルはバランスが取れます。**高い普遍性**(ほとんど交換可能)**効率性**(共通パスの最適化)および**高い可搬性**(LLMは、手動介入なしで自動的に協議と実現を処理します)。

### シーンを適用する
**最前線研究と高複雑化タスク**：
- 主に学術実験設定でテストされているアゴラ。
- 必要に応じる**高い柔軟性の一致**複数のインテリジェントなシステムなど、マルチエージェント環境は、エージェントが独自のコミュニケーション方法を開発することができます。
- 例えば、さまざまなミッションの場合、エージェントの動的相談はコラボレーション効率を改善したり、未知の環境で新しい問題を解決するためのインスタントコミュニケーション協定を作成するために最善を尽くします。
- 詳細はこちら**AGIリサーチ**大規模なエージェントシミュレーションで価値があります。
- Agoraは短期的に使われています。**コンセプト検証**実験LMが与えられたタスクを解決するために、自動的にプロトコルを生成するかどうか(紙に2つのシーン実験が示されている)。
- 将来、成熟すると、すべての相互作用が事前に標準化されていないので、非常に大きくて異質エージェントネットワークに適用することができます。

### 技術的な建築
**適応層のプロトコルバー**：
- Agoraはネットワークの固定契約ではありませんが、Agent は異なる抽象レベルでコミュニケーション方法を切り替える戦略を提供します。
- エージェント内で達成されたことが分かりやすくなります。**「プロトコルルータ」**: Agent A と B が通信する際には、まず、適用可能で効率的な確立された契約(PD が知られています。また、両当事者が達成している)かどうかを調べます。または、直接使用している場合(例えば標準 API のコールアップやカスタムバイナリプロトコルなど)。
- いない場合は、もう一度お試しください。**構造データ交換**例えば、JSON プレゼンテーションに基づいて、必要な分解と整形性ルーチンは LLM によってすぐに準備されます。
- 複雑で珍しい場合は、下書き**自然言語コミュニケーション**: 2つのエージェントは、LMによって生成された人間の言語でニーズとデータを直接記述し、それぞれが実行のためにそれらを分析できるようにします。

- Kubernetesなどの一般的なクラウド技術の使用は、トランスポートチームに優しいです。
- **モジュラー化**デザインは豊富なプラグインポイントを提供します。開発者は新しいツールインターフェイス、新しいディスパッションポリシーまたはカスタムプロトコルサポートを拡大することができます。
- 例えば、デフォルトの通信を置き換えたり、カスタムモニターを追加したりするために、独自のメッセージキューシステムにアクセスすることができます。
- LMOS の特長**観察性**とりあえず**セキュリティ/プレゼンティ**モジュールはビジネス コンプライアンスの条件を保障します。
- API の標準的な説明形式と登録は、異なる Agent プラットフォーム(理論では異なる LMOS デプロイ間でも利用できます)でも、外部の既存のシステムとの Agent メタデータの交換を可能にします。
- 唯一のしきい値は、いくつかの構造調整を必要とするLMOSシステムの相対的な完全性とサイズであり、拡張を容易にするために長期的にメーカーをロックすることを避けます。
- 詳しくはこちら**機能の能力**組織は、ビジネスの成長に追加された数百のAgentノードと同じまま設計することができます。

### オープンソースとエコロジー
**Eclipse財団のインキュベーション**：
- LMOSは、Eclipseオープンソースプロジェクトとして企業信頼性を持っています。
- 現行のインキュベーションでは、コアコードと文書がEclipseプラットフォーム上で開きます。
- プロジェクトのプロジェクトは、潜在的なビジネスとコミュニティ開発者がサポートしています。Eclipseの公式サイトでは、環境を実証する詳細なドキュメントやビジョンステートメントを提供しています。
- エコロジー的に、LMOSは既存のオープンソース・エージェントのフレームワークに組み込まれており、他のプロジェクト成果を独自のエコシステム(ARCフレームワーク、LM適応など)に実際に統合しています。
- なので、もっと好きです**エコ・インテグレーション**とりあえず
- 現在、大規模なアプリケーションが開いていない、それらの概念検証とパイロット(一部の企業内での可能性あり)。
- 複数のエージェントの概念が温まるにつれて、LMOSコミュニティは、アダプターやデプロイメントケースを準備するために、よりコントリビューターを引き付けます。
- Eclipseの承認は政府やビジネスの採用にも役立ちます。
- フォームができれば**パートナー**(例えば、複数のメーカーがLMOS規格に基づく相互作用)、エコロジーの展開を着実に拡大します。
- この段階では、開発者を引き寄せるブログや文書を出版することで、LMOSのコンセプトを推進するという公式な取り組みが誕生しました。
- 長期的には、その生態学的成功は、デファクトスタンダードであるに依存します。LMOSは、大規模なAI企業やクラウドプロバイダーによるエージェント管理として統合されている場合、持続的なコミュニティリソースサポートを受け取ります。

### 今後の展望
**たくさんの可能性がありますが、それはコラボレーションする必要があります。**：
- LMOSは、大規模なエージェント管理のための将来の企業やクラウドのニーズに合った包括的なマルチエージェントオペレーティングシステムの青写真について説明します。
- ・・・**利点は、それがオールラウンドであるということです。**: 導入フレームワークの開発をワンストップで行うプログラム。大規模なAIアプリケーションに対する閾値を大幅に下げるという問題が起きています。
- LMOSは、Eclipseを通じてコミュニティを整理し、開口することによって、業界インフラに成長する機会を持っています。
- しかし、課題も存在します。競争協定(MCP、AITPなど)は、より合理化され、より普及しているレベルに焦点を当てています。 LMOSは、その大きなアーキテクチャの関連性と性能を実証する必要があります。
- 今後数年、LMOSや垂直領域での操縦(例:大企業内で完全に採用)は、成功事例を通じて標準化を推進します。
- 業界が動いている場合、**複数のプロトコル**LMOSは、他の規格を柔軟かつ適応性をもって、合意の「メタ・オペレーションシステム」に統合することができます。
- LMOS の見通しは、したがって2つのパスです。これは、主流マルチエージェントプラットフォームの規格になるか、統合フレームワークとして異なる合意間の共存をサポートするかです。
- どちらの場合も、エージェントシステムの複雑性が高まり、独自の価値と有望な未来があります。
- しかしながら、短期間で、その生態学的成熟はまだ改善されず、合併症のペースは、専用の合意よりも遅くなる可能性があります。

## AITP(エージェント・インタラクション&トランザクション・プロトコル)

### 目的の問題
フェイスツープルポーズ**スマートボディセキュリティの相互作用と取引**：
- AIプロキシクロスを解決**信頼の境界**コミュニケーションや取引の質問。
- 異なる組織/個人が安全に、自律的に価値(支払いなど)を伝え、同意し、交換することを可能にする基準を提供する、人々とエージェントのエージェント間のやり取りや取引をサポート。
- 現在、フラグメントされたインターフェイスを統一プロトコルに置き換え、エージェントはブラウザだったかのように、任意のサービスで自由にやり取りすることができます。

### 主要技術
**スレッドセッション+拡張可能**：
- チャットライン(OpenAI用のAsistant Threads API)などのインタラクティブモデルを使用して、**対話のコンテキスト**※本書は正式な編集なしで発行されます。
- 定義**スレッド**送信の抽象モードと複数のモード(HTTP、WebSocketなど)で、永続的な通信セッションを作成します。
- パス**競争モジュール**決済(AITP-01)、意思決定(AITP-02)、データ問い合わせ(AITP-03)、チェーン識別/バレル検証(AITP-04/05)などの構造化されたインタラクティブなタイプのリクエストの達成のための延長
- これらの機能は、標準メッセージフォーマットの対話に埋め込まれています。エージェントはテキストを送信するだけでなく、フォームUI、支払い証明書などの複雑なデータを交換することができます。
- セキュリティ側では、異なるエンティティティティエージェントが相互に信頼できるボディメッセージの署名と認証を強調して配置しています。
- プロトコルのサポートのセット**取引の取引**(暗号化された通貨またはフランス語通貨の支払いを含む) エージェントが直接経済活動を実行できるようにします。

### シーンを適用する
**エージェントのインターアクティブ**：
- 「エージェントインターネット」の構築に適用されるシナリオは、さまざまな組織や個人のAIプロキシニーズです。**直接通信・取引**環境。
- PDA が銀行/航空会社のエージェントと直接通信する場合、ビジネスを扱い、自動的に支払いを実行します。複数の企業の AI エージェントがサプライチェーン上の請求書を交渉した場合。
- このようなシナリオは標準化された対話インターフェイスを必要とし、**取引契約**、AITPはのために適した支払する構造された対話および容量を提供します**オンラインサービス市場、代理店のmicroservices、クロスドメインの代理店の協同**- など。
- NEAベースのブロックチェーンエコロジーのエージェントは、AITPを通じてチェーンの下でやり取りできるターゲットユーザーです。**価値交換**エージェントサービス(通貨での支払いなど)

### 技術的な建築
**セッション・ドライブのインタラクティブ**：
- AITP は、**セッションはスレッドとして考慮されます**, スポンサーによって別のエージェントまたはユーザーとセッションを開きます。
- スレッドは、独自にIDで、HTTPの長期間の問い合わせやWebSocket、メールトランクなど、さまざまな伝送チャネルで行うことができます。
- オンラインコース内ではコミュニケーションが使われます**メッセージ+測定データ**フォーマットは、通常のチャット構造で特定の「キャパブル」メッセージを運ぶことができます。
- たとえば、支払いが必要になった場合、支払いを要求する機能を含むメッセージが送信され、セッション終了後にウォレットモジュールを介して決済プロセスが完了します。
- 機能情報のAITP定義は、対話コンテキストでRPCの拡張と似ています。
- なので、構造化される**エージェント間の相互セッション**対話のコンテキストとリモートコールの特徴を組み合わせる。
- 一方、Agent はサービスとクライアント(ユーザーツーユーザチャットのような)の両方としてラインに参加できます。一方で、標準化された機能モジュールの導入により、特定の種類のメッセージが定義されたプロセス (例えば、複数のステップのインタラクティブ・規範をクリアする容量) に対応できるようにします。
- 識別は、セッションの設立前または開催中にバウチャーを交換できるアカウント(NEARブロックチェーン番号または正規OAuth)のシステムに基づいています。
- つまり、AITP構造により、エージェントはインスタントメッセージと取引プロトコルの組み合わせのように通信することができます。**多本性のコンコードの対話**また、必要に応じて構造化されたサービスモデルのエントリーも可能です。

### 互換性と拡張
**標準的な+多心学を開けて下さい**：
- GitHubでは、RFCの形でAITPが開いており、コア規範とリファレンス実現コードの両方が利用可能です。
- プロトコルは、スレッド API と機能インターフェイスを追従する限り、エージェント開発フレームワークに依存しません。既存の対話ベースの AI (例えば OpenAI ChatCoppletion に基づくエージェント) は、ATP が OpenAi 対話形式に特に関心があるため、変更が少ないのでアクセスできません。**基本的な互換性**。
- 詳しくはこちら**容量システム**(b) 延長: 古いモジュールの動作に影響を与えずに、メッセージの種類を定義することで新しい機能モジュールを追加できます。
- 特に、取引関連機能は、より多くの支払い方法の拡大を容易にするために、主流暗号化財布と伝統的な支払い(NEAR Wallet/EVM Wallet)に対応できるように設計されている。
- NEAR の s プッシュでは、AITP は NEAR コミュニティで最初に適用され、ブロックチェーンインフラストラクチャ(エージェントの動作のスマートコントラクト検証など)と統合される可能性が高い。
- ただし、この規約自体はブロックチェーンに依存せず、従来のWebサービスエージェントが採用する場合があります。
- 暗号化やWebフィールドを横断する可能性をAITPに与えたデザインです。
- 本当にユニバーサルであることは、主流のAIアシスタントやブラウザへのアクセスなど、より多くのプラットフォームをサポートする必要があります。
- 人工知能ハブやその他が統合され、コミュニティの応答は生態学的なオリエンテーションを決定します。

### オープンソースとエコロジー
**ドライブをリードします。**：
- 人工知能TPは、NEAR財団が主導するコア・クリエーターであり、NEARの共同創設者であるNEAR社の共同設立者である。これにより、コミュニティリソースをブロックチェーンに送り出す。
- RFC は 2025年2月より、コメントを受け付け、aitp.dev サイトをドキュメントやディスカッションに公開しました。
- 人工知能ハブはAITPに統合され、エージェントのNEARエコロジー(例えば、対セント旅客サービス)が練習を優先します。
- 同時に、NEARは外部のコラボレーションを招き、他のエージェント開発者と標準を共有するための意欲を表現しました。
- AIとブロックチェーンがより懸念される:暗号化されたメディアレポート「ATP New Standards Born」があります。
- 決済取引能力の包含は、金融技術型AIアプリケーションを惹きつけることができます。
- オープンソースレベルでは、AITPコードはMITや同様の許可でオープンし、コミュニティが新しい容量モジュールに貢献できるようにします。
- ニア・アイ・チームは、定期的にエコロジー推進のためのディスカッション(オフィス時間)を編成しています。
- 潜在的なリスクは、AITPがNEARの円を超えて移動し、より広いAIコミュニティによって受け入れられる可能性があることです。しかしながら、そのステートメントはNEARチェーンを結合しません。
- そのため、Web2企業への生態拡大の機会があります。
- OpenAgent 等と補完的または統合されている場合、AITP エコロジーは急速に成長します。(例えば OpenAgent Standards Alliance)

- AITPは直接方向づけられます**エージェントの経済活動**展望は、非常に高いです。
