# AI アクセス専用に設計された初の WebAgent が誕生

ますます多くの **エージェント ** がインターネットから直接情報を入手しようと試み始めています。現在、コンピュータでの使用、ブラウザでの使用など、多くのテクノロジーが利用可能です。しかし、従来の Web サイトは主に人間のユーザー向けに設計されています。 AI がこれらの Web サイトを使用したい場合、多くの場合、人間のブラウザーの動作 (クローラーのように HTML ページを解析するなど) をシミュレートする必要がありますが、これは非効率的で複雑です。

この問題点を解決するには、**WebAgent** を構築する必要があるかもしれません。

この記事では、WebAgent とは何か、および最初の WebAgent がオンラインになる意義と技術的な詳細について紹介します。 WebAgent を検出して操作する方法、WebAgent の ID 認証メカニズム、および関連プロトコルにアクセスするためのコード例を紹介します。最後に、AI 専用に構築されたデータ ネットワークを構築する方法を紹介します。

## Webエージェントとは

WebAgent は、既存の Web インフラストラクチャ (PKI、DNS、HTTP、CDN、検索エンジンなど) を使用して構築されたエージェントです。これは Web 上で実行され、他のエージェントが Web 経由でアクセスして対話できるように設計されています。人間のユーザーを中心として設計された従来の Web サイトとは異なり、WebAgent は AI 専用に設計されており、AI が読みやすく理解できる公開情報と、ユーザー インターフェイスを必要とせずに構造化言語や自然言語を含む複数種類のインターフェイスを提供します。

従来の Web サイトと比較すると、WebAgent には次のような大きな違いがあります。

- **異なるオブジェクト指向**: 従来の Web サイトは主に人間のユーザーにサービスを提供し、ブラウザーを通じてアクセスして対話します。一方、WebAgent は AI 用に特別に設計されており、他のエージェントが Web を通じて AI にアクセスし、対話できるようにすることを目的としています。
- **構造化データ形式 **: WebAgent から返されるデータは、AI が直接読み取って処理するのに便利な構造化形式 (JSON、YAML など) ですが、従来の Web サイトは通常 HTML を返すため、必要な情報を抽出するには追加の解析が必要です。
- **自己記述機能**: 各 Web エージェントは、他のエージェントが Web エージェントと対話する方法を理解しやすくするために、その機能、インターフェイス形式、呼び出しメソッドなどの詳細を記述した説明ファイルを提供します。
- ** ID 検証メカニズム **: Web エージェントには、情報やインターフェイスの悪用を防ぐために、訪問者向けの認証サポートが組み込まれています。既存の Web サイトは、Web クローラーによって情報が勝手にクロールされるという問題に直面することがよくあります。

過去には、AIは、複雑で非効率的なヒューマンページビューのシミュレーションを必要とするWebベースの情報にアクセスしています。 WebAgentは、AI用に設計された「ネイティブウェブサイト」であり、アプリケーションサービスに直接データにアクセスしたり、コールするようなタスクを実行することができます。これにより、AIはより効率的かつ正確になり、開発者はAIのためのサービスを最適化し、人的閲覧に限定されることはできません。 WebAgentは、スマートインターネット(アジェンティックウェブ)を構築するための基礎コンポーネントとなり、AIが直接通信やコラボレーションを行うことができるようになるでしょう。

このパスにアクセスすると、JSON-LD 形式のファイルを返します。**ドキュメントの検索**このドメインで公開されているすべてのWebAgentの説明のアドレスをリストします。 [ANPスマートディスカバリープロトコル](https://github.com/agent-network-protocol/AgentNetworkProtocol/blob/main/08-ANP-Agent-Discovery-Protocol-Specification.md)(エージェント・ディスカバリー・プロトコル)。

## WebAgentの認証メカニズムにアクセス

WebAgentは、自動AI訪問者に向けて指向されていることを考えると、オープンインターフェイスは、大量のモデルトレーニング会社による最近のドライブなどの悪用や過分な問題に直面している可能性があるため、ウェブサイト上でデータを登る病気の高発生率で。

です。**WebAgent は、通常、呼び出し側から識別を必要とする**当ウェブサイトにアクセスする際に必要なこと、またはAPIキー、OAuthの対応となります。

しかし、WebAgentはインテリジェントな身体の生態により適切であるソリューションを持っています: に基づく **W3C DID (集中識別子、中央識別に行きます)** 標準認証メカニズム。スマートは、他のシステムに追加のアカウントを登録する必要のない、各スマートな人がWebAgentにアクセスするための識別子としてDIDを使用することができます。

AgentNetworkProtocol(AMP) は、特別な DID メソッドを提案します。 **`did:wba`** (WebAgent DID) の [同一証明のためのANPの標準](https://github.com/agent-network-protocol/AgentNetworkProtocol/blob/main/03-did%3Awba-method-design-specification.md)(ID:WBA法規制)、`did:wba` 既存のWebインフラを使用して、集中的なアイデンティティを実現し、特にインターインテリジェンス用に設計されています。 簡単に言えば、各スマートボディ(またはWebAgentを使用したエンティティティティティティティ)が1つ所有できます。 `did:wba:` 初期識別子(例:  

```
did:wba:example.com:agent:weather123
``` 

これは、ドメイン名情報を含むメールアドレスやユーザーIDの類似性です。 WebAgent の認証システムでは、既存のネットワークインフラストラクチャを他の人に登録しなくても、DID を介して識別できる他の側面が見えます。これはクロスプラットフォーム AI-Agent コラボレーションを大幅に簡素化します。

`did:wba` 識別プロセスは、次の通り要約することができます。
- **DID 文書リリース:** 各DIDは、公鍵などの認証資料を含む「ID文書(DDD文書)」に相当します。`did:wba` このメソッドは、DID ドキュメントが HTTP 経由で簡単にアクセスできる対応するドメイン名の特定のパスでホストされていることを指定します。例えば DID `did:wba:agent-did.com:user:alice` DID ドキュメントを解析できます(Aliceの公開鍵が利用可能)。
- **署名のリクエスト:** リクエスト中に、AI スマートボディがWebAgentにアクセスする場合、WebAgentがDID認証を必要とする場合、要求時に本人の署名を要求します。具体的には、リクエストパーティは独自の秘密鍵を使用してチャレンジ文字列や要求されたコンテンツに署名し、HTTPリクエストの頭(例えば、)に署名を付けます。 `Authorization`) 送信する。
- **検証プロセス:** WebAgent サービスプロバイダからリクエストが受けられると、パブリックキーは対応する DID ドキュメントから抽出され、署名が有効であるかを確認し、申請者を識別します。検証が渡される場合、要求は DID によって表されたエンティティティティからなると考えられ、決定は戦略に従ってアクセスまたはサービスを提供するために行われます。認証障害は 401 の承認エラーなどを返します。

DDが集中化されるため、**集中化されたユーザーデータベースに依存することなく、お互いを信頼できます。**. これはメールシステムのように少しです。つまり、DNSを介してドメイン名を検索し、対応する公開鍵を信頼できる限り、他のメールサーバにアカウントを登録する必要はありません。`did:wba` . DIDは従来のOAuthまたはAPIのキー プログラムより適切です**大規模、多潜水**各エージェントがアイデンティティ、認証、そしてどこでも利用できるため、インテリジェントなボディエコロジー。 [Ofコース、既存のシステムに適合させるために、WebAgentは従来のAPIキーなどにも対応するかもしれませんが、DIDは将来の指向のソリューションです]

**権威の乱用と制御の防止:** WebAgent は、呼び出し元から DID の ID をリクエストすることでこのリクエストを行うことができます。
- 呼び出しクォータ、パーミッションレベルをDIDに割り当てます。例えば、特定のレベルの信頼がある場合のみ、いくつかの機密操作を呼び出すことができます。

## AIに特にアクセス可能なデータネットワークの構築

ライン上で最初のWebAgentで、今後インターネットの新しい形を1つ見ていきます。**インターフェイスなし、AIだけに開く**ネットワークは、ここに提示された3つの主要要素に基づいています。

- **スマートディスカバリー**:標準の検出プロトコルを通して `.well-known` アクセス、AIはマニュアルディレクトリなしでインターネット上でスマートボディサービスを自動インデックス化できます。
- **スマート 説明**: 各WebAgentには、機能的な説明とインターフェイスの仕様が含まれており、AIはサービスを自動的に呼び出して、高度に自己記述されたネットワークを形成する方法を理解することを可能にします。
- **認証情報**:: 分散型アイデンティティ(ID)機構により、ネットワークの相互作用の安全性と信頼性を確保し、クロスプラットフォームの権限管理をサポートし、健全なネットワーク運用を実現します。

この「AIデータネットワーク」には、以下のような機能があります。

- **AI、UIレスのために設計されている**ネットワーク内のサービスは、直接ページやグラフィックインターフェイスを人間に提供しなくなり、すべての相互作用はインテリジェントな身体の間で発生します。従来のヒューマンインタフェースは保存され、システム複雑性が低下し、Webサービスは1秒あたりのデータに焦点を当てており、AIのための効率的なデータ交換環境が集中しています。
- **半構造化データ**WebAgentは、AIインテリジェンスの迅速な分析と処理を可能にする構造化されたフォーマット(JSON、YAML)のデータを提供します。そして、インテリジェントな人々がサービスコンテンツをよりよく理解したり、パーソナライズされた機能を表現するのに役立つ、個別化された物語情報を運ぶための自然言語表現のローカル使用。
- **自己記述機能**: WebAgent は、提供するサービス、インターフェイス定義、コールメソッドを詳細に示す標準化された説明ファイルを含んでいます。AI インテリジェンスは、手動で介入や追加のインタフェース文書なしでサービスを見つけるときに、サービス固有の機能と相互作用を独立して理解できます。
- **安全、信頼できる。**WebAgentは、自動AI訪問者に向けて指向されていることを考えると、オープンインターフェイスは悪意のある誤用や過配分(例えば、近年では、広スプレッド病変、およびウェブデータを持つ大型モデル企業の狂った揺れ行動)のリスクにさらされるかもしれません。 WebAgentは、集中されたアイデンティティ(ID)に基づいてアイデンティティと権限管理メカニズムを持ち、データの乱用を回避し、インターフェースのセキュリティを確保します。

今後、すべての業界データとサービスは、WebAgent:天気、ニュース、ナレッジベース、取引プラットフォーム、ビジネス...AIが、現在、APやウェブページを直接Webインターフェイスを介して実行できる主要な「ユーザー」になる可能性があることを想像してみてください。 ヒューマンユーザーは、AIと連携して複雑なことを行うために、これらのWebAgentsの多くにそれを取得します。
