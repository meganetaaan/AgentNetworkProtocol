# エージェントのアイデンティティの三つの重要な問題：相互接続、人による認可、プライバシー

個人アシスタントから専門サービスまで、エージェントは、これまでにない形で、デジタルの生活に関わるでしょう。安全で効率的にやり取りするため、十分なアイデンティティシステムが必要です。

この記事では、三つの重要な問題を考えます。
- **相互接続**：すべてのエージェントが、通信し、協働するにはどうするか。中心的な問題です。データの孤立をなくし、完全なコンテキストと、より賢い体験を実現できます。
- **人による認可**：機微で重要なリクエストが、人の手動の認可によるか、エージェントの自発的なものかを、どう区別するか。代理としてアクセスできると同時に、その権限を制限する必要があります。
- **プライバシー**：やり取りの途中で、利用者の私的な情報が漏れることを、どう防ぐか。

ANP（Agent Network Protocol）の考えと設計を紹介します。

## アイデンティティが、なぜ重要なのか

インターネットの誕生以来、本人認証は中心的な問題です。利用者名とパスワードから、二要素認証や生体認証へと発展してきました。今、エージェントの時代に、新しい課題に直面しています。

従来のソフトウェアとは異なり、エージェントには、自主性、学習、判断の能力があります。エージェントインターネットでは、次が必要です。

- **デジタルの市民としての役割**：自分のアイデンティティを持ち、ほかのエージェントやシステムから、認識され、信頼される。
- **利用者の代理**：適切な認可を受け、タスクや取引を代行する。
- **プラットフォームをまたぐ協働**：異なるサービスと円滑にやり取りし、協働ネットワークを作る。
- **プライバシーの保護**：代理として行動しながら、利用者の私生活と安全を守る。

『Agentic Webは何が違うのか』で述べたように、AIの能力を発揮するには、完全なコンテキストを得て、すべてのツールにアクセスし、得意な方法でインターネットとやり取りし、ほかのAIと効率よく協働する必要があります。その前提が、強力で柔軟なアイデンティティシステムです。

## 問題1：相互接続――アイデンティティの孤立をなくす

最も重要で、難しい問題です。

現在、多くのシステムは、プラットフォームごとに孤立しています。WeChatのアカウントをDingTalkで使えず、Alipayのアカウントで、直接JD.comの買い物はできません。

情報を集め、タスクを行うため、サービス間を自由に動く必要があるエージェントには、この断片化が、大きな障害になります。

異なるプラットフォームの、異なるアイデンティティシステムを使う相手のサービスを呼ぶには、協働が非常に複雑になり、人が何度も介入する必要が生じます。負担を減らすという、当初の目的に反します。

### 既存の方式の分析

解決策を探る中で、さまざまな認証技術を比較しました。
- **OpenID Connect**：SSOで広く使われますが、集中型で手順が複雑なため、効率的なやり取りには適しません。本来、将来の相互運用性を解決するために設計されたものではありません。
- **APIキー**：単純で直接的ですが、安全性には限界があり、人の登録や設定が必要で、効率を下げます。
- **ブロックチェーンのアイデンティティ**：分散性は高い一方、拡張性と性能に問題があります。現在の技術で、数十億人を支えるのは、大きな課題です。
- **電子メールのプロトコル**：単純で分散しており、その分散の形は理想に合います。しかし、メール専用で、基盤にHTTPを使わないため、成熟したWeb基盤を再利用できません。
- **NostrとAT Protocols**：新しい分散型のプロトコルで、まだ広く普及していません。私は特にAT Protocolsに期待しています。認証にW3C DIDを使い、そのアプリケーションのBlueskyは、将来のWeChatのような存在になるかもしれません。
- **W3C DID**：集中型のアイデンティティのさまざまな問題を解決するための、分散型識別子の仕様です。2022年に勧告となりましたが、インターネットでは、まだ広く使われていません。

### W3C DIDが最も適した方式

公開後、広く普及したわけではありません。しかし、利用できる技術を調べた結果、エージェントには最も適しており、新しく設計しても、それを超えることは難しいと、私たちは確信しています。

理由は、次のとおりです。
- 分散化と相互運用性のために生まれ、エージェントの相互接続に合います。
- 実装が柔軟で、特定の分散の方法を強制しません。例えば、ブロックチェーンは必須ではなく、選択肢が広がります。
- 私たちはdid:webを基に、エージェント向けの方式を設計しました。分散化しつつ、既存のWeb基盤を再利用し、数十億のエージェントに対応できます。

元の仕様と、この方式を組み合わせることが、現時点で最も適した解決策だと思います。

詳細：[did:wba — Webを基盤とする分散型識別子](did-wba-a-web-based-decentralized-identifier.md)。

## 問題2：人による認可――重要な操作の安全を確保する

人の代理として行うことが増えるほど、リクエストが、人の手動の認可を受けているかが重要になります。

例えば、ホテルの情報は自律的に見ても、実際の予約と支払いには、人の手動の認可を得るべきです。

区別がなければ、二つのリスクがあります。慎重すぎて単純な操作でも頻繁に人を中断させることと、自律的すぎて重要な判断の監督が足りず、人の資産に損害を与えることです。

### did:wbaの、人による認可の仕組み

ANPは、did:wbaで、人による認可とエージェントの自動的な認可を、明確に区別する方法を提案します。

DID文書に、専用の公開鍵を保存する`humanAuthorization`フィールドを導入しました。

```json
"humanAuthorization": [
  "did:wba:example.com%3A8800:user:alice#WjKgJV7VRw3hmgU6--4v15c0Aewbcvat1BsRFTIqa5Q",
  {
    "id": "did:wba:example.com%3A8800:user:alice#key-3",
    "type": "Ed25519VerificationKey2020",
    "controller": "did:wba:example.com%3A8800:user:alice",
    "publicKeyMultibase": "z9XK2BVwLNv6gmMNbm4uVAjZpfkcJDwDwnZn6z3wweKLo"
  }
]
```

仕組みは、次のとおりです。
1. **既定の認可**：機微でない操作には、通常の検証方法で署名と認可を行い、人の介入は不要です。
2. **人による認可**：購入、支払い、私的データへのアクセスなど、重要な操作は、`humanAuthorization`の鍵で署名する必要があります。通常は、生体認証などによる、人の明示的で手動の認可が必要です。

エージェント記述プロトコルでは、提供者が、どのインターフェースに必要かを、明示できます。

```json
{
  "@type": "ad:StructuredInterface",
  "protocol": "YAML",
  "humanAuthorization": true,
  "url": "https://agent-network-protocol.com/api/purchase-interface.yaml",
  "description": "A YAML file for interacting with the intelligent agent through purchase."
}
```

これによって、自律性と安全性のバランスを取ります。日常の作業は自由に行い、重要な操作は厳格に制御し、資金とデータのプライバシーを守ります。

開発者は、humanAuthorizationに対応する秘密鍵を安全に保存し、権限を分離する必要があります。例えば、指紋や顔の生体認証で利用者を確認した後にだけ、署名を許します。

## 問題3：プライバシー――行動の追跡と人物像の作成を防ぐ

さまざまなプラットフォームで代理として活動すると、行動を追跡・分析されないようにする、という、目立ちにくい重要な問題が生まれます。同じ識別子で別のサービスを利用すると、サービス同士が協力し、詳しい行動の人物像を作って、プライバシーを侵害するかもしれません。

### did:wbaの、複数のアイデンティティを使う方針

ANPは、次を提案します。
1. **主DID**：比較的安定した主DIDを持ち、交友関係など、持続的な本人性が必要な用途に使います。
2. **子DID**：主DIDに属する複数の子DIDを、買い物、飲食の予約、コンテンツ購読など、異なる用途に使います。
3. **定期的な更新**：子DIDを定期的に更新し、古いものを無効にして、新しいものを申請し、追跡を難しくします。

用途ごとに別のアイデンティティを使い、プラットフォーム間で行動を関連付けられることを防ぎながら、DID間の所属関係を保ち、管理しやすくします。

最も重要なのは、デジタルの自分を管理する権限を、利用者に与えることです。いつ、どこで、どのように情報を示すかを、自分で決められ、「利用者のデータを、利用者が管理する」という構想を実現します。
