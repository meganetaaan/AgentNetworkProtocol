# Agent Network Protocol 技術構想

この文書は旧版です。[Agent Network Protocol 技術白書](01-AgentNetworkProtocol技术白皮书.md)を参照してください。

## ビジョン

私たちはAgentNetworkProtocol（ANP）を**エージェント型Web時代のHTTP**にすることを目指しています。

人工知能が急速に発展するこの新しい時代に、私たちはエージェントネットワークという新たな時代に入りつつあります。未来を想像してください。食事を注文するとき、個人アシスタントのエージェントがレストランのエージェントとシームレスに通信します。スマートホームのエージェントは、エネルギー管理エージェントと協力して電力使用を最適化します。投資顧問エージェントは、世界の市場分析エージェントとリアルタイムで情報を交換します。これが、これから到来するエージェントネットワークの時代です。

しかし、ビル・ゲイツが[ブログ記事](https://www.gatesnotes.com/AI-agents)で述べたように、現在はエージェント同士が通信するための標準プロトコルがありません。Agent Network Protocol（ANP）が解決しようとしているのは、この問題です。

Agent Network Protocol（ANP）のビジョンは、**エージェントが互いに接続する方法を定義し、数十億のエージェントに向けた、オープンで安全かつ効率的な協働ネットワークを構築すること**です。インターネットの標準プロトコルの発展が過去30年間の情報化時代を可能にしたのと同じように、近い将来、数十億のエージェントがANPを通じて前例のない協働ネットワークを構築し、既存のインターネットを上回る価値を生み出すと考えています。AI技術とANPによって、エージェントネットワークは最終的に**自己組織化し、自ら交渉する**効率的な協働ネットワークへと進化するでしょう。実に楽しみな未来です。

## 課題

Agent Network Protocol（ANP）は、接続に関する次の3つの大きな課題に取り組みます。

- 任意の2つのエージェントが接続できるよう、互いをどのように認証するか。
- 通信の安全性を確保するため、エンドツーエンド暗号化通信をどのように確立するか。
- 協働の効率を高めるため、データをどのように効率よく交換するか。

## プロトコルアーキテクチャ

この3つの大きな課題に対応するため、Agent Network Protocol（ANP）は、下から順に「アイデンティティと暗号化通信層」「メタプロトコル層」「アプリケーションプロトコル層」で構成される、次の3層アーキテクチャとして設計されています。

### アイデンティティと暗号化通信層

これはプロトコルの最も基礎となる部分で、エージェント通信の2つの大きな課題、すなわち相互認証とエンドツーエンド暗号化通信の確立に取り組みます。

Agent Network Protocol（ANP）は、W3C DID（分散型識別子）仕様に基づき、ブロックチェーン技術とエンドツーエンド暗号化を統合した画期的な解決策を提供します。

- **完全な分散化**：エージェントはプラットフォームに制限されず、自らのアイデンティティを完全に管理できます。
- **障壁のない接続**：あらゆるプラットフォーム間でエージェントの認証を可能にし、プラットフォームの壁を取り除きます。
- **高い安全性**：エンドツーエンド暗号化により通信を保護し、中間ノードによる内容の復号を防ぎます。
- **低コストと効率性**：既存のWeb基盤を利用し、最小限のコストで迅速に導入できます。

W3C DIDは、ANPのアイデンティティと暗号化通信層の土台です。その分散性と相互運用性がANPのオープンさを可能にし、任意の2つのエージェントが接続して、オープンなエージェント協働ネットワークを構築できるようにします。

詳細な技術文書：[GitHub](https://github.com/agent-network-protocol/AgentNetworkProtocol)

### メタプロトコル層

メタプロトコルによって、エージェントネットワークは**自己組織化し、自ら交渉する**効率的な協働ネットワークへ進化する可能性を持ちます。楽しみな未来です。

メタプロトコルとは、通信プロトコルを交渉するためのプロトコルです。この層では、主に[Agora Protocol](https://arxiv.org/html/2410.11905v1)を参照し、着想を得ています。

現在のデジタル世界には大量のデータサイロがあり、データの流れはサイロの内部に集中し、サイロ間では限られています。ビジネス上の理由に加え、技術的な制約も大きな要因です。異種ネットワーク、つまりアーキテクチャ、機能、設計が異なるネットワークの間で、プロトコルによる通信を実現するには、しばしば莫大な費用がかかります。根本的な理由は、Agora Protocol論文で提示された、異種ネットワーク通信の不可能三角形（汎用性、効率性、移植性）にあります。

LLMによって能力を得たエージェントとメタプロトコルの組み合わせは、優れた解決策を提供します。

- エージェントはまず、それぞれの能力、データ交換形式、利用するプロトコルなどについて自然言語で通信し、通信プロトコルの詳細を決めます。
- 交渉結果に基づいて、LLMを使ってプロトコルメッセージを構築・処理するか、プロトコルを処理するコードを生成します。
- エージェントはプロトコルをデバッグし、LLMでメッセージが交渉済み仕様に適合するかを検証します。適合しなければ、自然言語でのやり取りによって問題を解決します。
- 最後に、確定したプロトコルを使って通信します。

LLMの自然言語理解とコード生成の能力、およびメタプロトコル技術により、エージェントネットワークは最終的に、自己組織化し、自ら交渉する効率的な協働ネットワークへ進化すると考えています。そこでは、人間が定義するプロトコルの数をはるかに上回る、多数のエージェント間合意プロトコルが生まれるでしょう。

### アプリケーションプロトコル層

アプリケーション層のプロトコルは、電子メールのプロトコル、RTC仕様、既存のW3C仕様などの業界標準と、エージェントネットワークが自動交渉する合意プロトコルの2種類に分かれます。いずれも、エージェントが具体的な業務タスクで協力できるようにすることを目的としています。

プロトコルが送信するデータ型は、大きくテキスト、ファイル、リアルタイムのマルチメディアストリームの3種類に分類できます。この3種類で、現在の業務シナリオのほぼすべてを扱えます。

エージェントは、データや業務の特性に基づいて基本プロトコルを拡張できます。エージェントネットワークにおける標準仕様の役割は、主として交渉の複雑さを減らすことであり、規則を強制することではありません。2つのエージェントは、それぞれの業務シナリオに最適な個別のプロトコルを交渉できると考えています。

## AgentConnect：Agent Network Protocol（ANP）のオープンソース実装

私たちは、Agent Network Protocol（ANP）の機能を実装するプロジェクトAgentConnect（https://github.com/agent-network-protocol/AgentConnect）をオープンソースで公開しました。そのアーキテクチャを以下に示します。

<p align="center">
  <img src="/images/agent-connect-architecture.png" width="50%" alt="プロジェクトアーキテクチャ"/>
</p>

ANPの3層アーキテクチャに対応し、AgentConnectは主に以下の構成要素を含みます。

1. **認証モジュールとエンドツーエンド暗号化モジュール**
   W3C DIDに基づく認証とエンドツーエンド暗号化通信を実装します。DID文書の生成、検証、取得、およびDIDとECDHE（楕円曲線一時Diffie-Hellman）に基づくエンドツーエンド暗号化の実装を含みます。

2. **メタプロトコルモジュール**
   LLM（大規模言語モデル）とメタプロトコルに基づく実装で、アプリケーションプロトコルの交渉、プロトコルのコード実装、デバッグ、処理を含みます。

3. **アプリケーションプロトコル統合フレームワーク**
   他のエージェントとの通信に使うプロトコルの仕様とコードを管理します。プロトコルのロード、アンロード、設定、処理を含みます。このフレームワークを使うと、エージェントは必要なプロトコルを必要時に容易にロードして実行でき、プロトコルの交渉を加速できます。

これらの機能に加え、AgentConnectは性能と複数プラットフォーム対応にも注力します。

- **性能**：基盤となるコードベースとして高い性能を目指し、主要部分をRustで書き直す予定です。
- **複数プラットフォーム対応**：現在はmacOS、Linux、Windowsに対応し、将来はモバイルプラットフォームとブラウザーにも対応します。

## マイルストーン

プロトコルとオープンソース実装の両方について、次の順序で段階的に進めています。

- 認証とエンドツーエンド暗号化通信のプロトコルおよび実装を構築します。これはプロジェクトの基盤であり中核です。現時点では、プロトコル設計とコードは基本的に完成しています。
- メタプロトコルを設計・実装します。これにより、エージェントネットワークが自己組織化し、自ら交渉する効率的な協働ネットワークへ進化できるようになります。この楽しみな機能は現在開発中で、初版を近く公開する予定です。
- アプリケーションプロトコル統合フレームワークを開発します。これにより、Agent Network Protocol（ANP）がさまざまな場面のエージェントに役立つようになります。

また、細部よりも全体構造を優先する原則に従います。初期段階では、完璧でも動かないモジュールを作るのではなく、全体のアーキテクチャを組み立て、主要モジュールごとの骨格を一通り用意して、迅速に動かすことに集中します。

Agent Network Protocol（ANP）を業界標準として推進するため、適切な時期にANP標準化委員会を設立し、W3Cなどの国際標準化団体に認められる業界標準となるよう取り組みます。

最後に、設計を進める中で、ブロックチェーンのほうがエージェントに適したネットワーク基盤かもしれないと、ますます感じるようになりました。今後、この方向を積極的に探究する可能性があります。

## Agent Network Protocol（ANP）を選ぶ理由

- **オープンな相互接続**：W3C DIDに基づく分散型認証によって、エージェントがプラットフォームの制限を越え、自由で安全な接続を実現できます。
- **技術革新**：ブロックチェーンとDID技術を統合し、プラットフォームをまたぐエージェント認証に先駆的な解決策を提供します。
- **効率的な実装**：既存のWeb基盤を利用して、低コストで迅速な導入を可能にし、エコシステムの発展を加速します。
- **未来志向**：エージェントネットワーク時代の基盤を構築し、自己組織化する協働ネットワークの進化と革新を促進します。
- **専門的なチーム**：分散システム、プロトコル設計、人工知能の豊富な経験を持つ、熟練した技術者と研究者が中核チームを構成しています。
