## リンクトデータ（Linked Data）

セマンティック Web は、単にデータを Web 上に置くことではなく、人や機械がデータの Web を探索できるよう、リンクを作ることです。リンクトデータでは、あるデータを持っていれば、関連する別のデータを見つけられます。

ハイパーテキストの Web と同様、データの Web はオンラインの文書から構成されます。ただし、ハイパーテキストのリンクが HTML 文書中のアンカーであるのに対し、データの Web のリンクは、RDF が記述する任意の事物間の関係です。URI はあらゆる種類の対象や概念を識別できます。HTML と RDF のいずれにも、Web の成長を促す次の共通の期待があります。

1. 事物の名前として URI を使う。
2. 名前を調べられるよう、HTTP URI を使う。
3. URI を調べたときに、RDF や SPARQL などの標準を使って有用な情報を提供する。
4. さらに多くの事物を発見できるよう、他の URI へのリンクを含める。

これらのルールは単純明快です。それでも2006年には、いずれかの手順の問題により、大量のデータがリンクされないままでした。本文では、問題の解決策、実装上の詳細、データ公開の選択に影響する要因を論じます。

---

## 4つのルール

上記の手順をルールと呼ぶことはできますが、実際には振る舞いに対する期待です。違反しても何かが壊れるわけではありませんが、データを相互接続する機会を逃します。その結果、将来の予期しない再利用の可能性が制限されます。まさに、この予期しない再利用こそ Web がもたらす付加価値です。

### ルール1：URI で事物を識別する

セマンティック Web 技術に携わる大半の人には、すでに明らかなことです。共通の URI 記号体系を使わなければ、セマンティック Web とは呼べません。

### ルール2：HTTP URI を使う

このルールも広く知られています。しかし Web の誕生以来、LSID、DOI、XRI など、新しい URI スキームが発明されがちでした。通常、DNS による権限の割り当てを避けたい、あるいは HTTP URI がアドレスだけでなく名前でもあることへの理解不足が背景にあります。

### ルール3：情報を提供する

大半のオントロジーでは、2006年時点ですでに十分に守られていましたが、一部の重要なデータセットではまだ守られていませんでした。通常、データ中のプロパティやクラスを調べ、RDF、RDFS、OWL のオントロジーから情報を得られます。しかし、多くのデータセットはリンクトデータとしてオンラインで提供されず、圧縮ファイルに埋もれています。

### ルール4：リンクを作る

データを真に無限の Web に結び付けるには、リンクが必要です。ハイパーテキストの Web で関連する外部資料にリンクしないのは、一般に作法が悪いとされます。同様に、セマンティック Web でのデータの価値は、データ自身の価値と、リンク先の内容によって決まります。

---

## 基本的なリンクトデータの作成

最も簡単なのは、あるファイルの URI で別のファイルを指す方法です。例えば、RDF ファイルでは次のようにローカル識別子 `#albert` を使えます。N3 形式では次のように表します。

```n3
<#albert> fam:child <#brian>, <#carol>.
```

これにより、世界中から `http://example.org/smith#albert` のようなグローバル識別子で Albert を参照でき、セマンティック Web の価値が高まります。

---

## URI の変形：スラッシュなしと HTTP 303

識別子を文書単位に分ける方法が適さない場合があります。例えば `http://wordnet.example.net/antidisestablishmentarianism#word` のような URI 形式を使う場合です。その場合は HTTP 303 リダイレクトにより、概念の URI からその記述文書の URI を指せます。

---

## FOAF と rdfs:seeAlso

FOAF ファイルでは、2つのプロパティを指定して別の人物へリンクできます。

```n3
<#i> foaf:knows [
    foaf:mbox <mailto:joe@example.com>;
    rdfs:seeAlso <http://example.com/foaf/joe>
].
```

この方法で成長を続けるソーシャルネットワークが形成されますが、人に一意な URI を割り当てられないという欠点があります。そのため、FOAF ファイル作成時は自分自身に URI を割り当て、他者を参照する際にはその人の URI を使うことを推奨します。

---

## 閲覧可能なグラフデータ

データの閲覧可能性は、リンクを作る際の重要なパターンです。データの構造を段階的に探索し、理解できるようにします。

### 閲覧可能なグラフ

リンクを作る方法を検討したので、次にどのようなときにリンクを作るかを考えます。

重要なパターンの1つは、リンクを通じて段階的に探索できるデータセットです。Web ブラウザーでハイパーリンクをたどる方法に似ています。セマンティック Web では、データの構造と関係性により、URI を通じて関連情報を段階的に取得し、理解できます。これを「閲覧可能なグラフ」（Browsable Graph）と呼びます。

#### データの閲覧パターン

閲覧可能なグラフでは、データをノード（Node）とエッジ（Edge）で構成します。ノードは対象や概念、エッジはノード間の関係を表します。人や機械は関係をたどってノード間を移動し、さらに多くの情報を発見できます。

例えば：

1. ある人の FOAF ファイルから、その人の友人を見つける。
2. 友人の URI から、参加プロジェクトなどの属性や関係を探す。

この閲覧パターンは情報の発見を助けるだけでなく、複数の主体によるデータのやり取りで、より豊かな意味のネットワークを作れます。

#### セマンティック Web の未来

十分に接続されたデータの Web には、世界規模の協力と一貫性が必要です。具体的には次のことが含まれます。

1. 高品質な URI を提供する。
2. HTTP URI 標準に従う。
3. RDF や SPARQL など、開かれた共通形式を使う。
4. 孤立したデータセットではなく、データの相互接続を推奨する。

Tim Berners-Lee は、セマンティック Web の可能性が「予期しない再利用」（Unexpected Reuse）にあると強調しています。データをリンクで組織すれば、情報の発見と利用の範囲を広げるだけでなく、将来の無数の可能性を生み出せます。
