**Scientific American**

**2001 年 5 月**

**セマンティック Web**

**コンピューターにとって意味を持つ新しい Web コンテンツが、新たな可能性の革命を起こす**

**著者：TIM BERNERS-LEE、JAMES HENDLER、ORA LASSILA**

電話が鳴ったとき、娯楽システムはビートルズの「We Can Work It Out」を流していた。ピートが応答すると、電話は音量調節機能を持つ近くの全機器へメッセージを送り、音を小さくした。妹のルーシーが診察室から電話してきた。「お母さんは専門医を受診して、その後は理学療法を続ける必要があるの。だいたい 2 週間に 1 回。私のエージェントに予約させるわ」。ピートは送迎を分担するとすぐに答えた。ルーシーは携帯 Web ブラウザーで自分のセマンティック Web エージェントに指示する。エージェントは医師のエージェントから母の治療指示を取得し、医療機関の一覧を探し、自宅から 20 マイル以内で母の保険が使え、信頼する評価サービスで「優秀」か「非常によい」とされた施設を確認した。そして各医療機関のエージェントが Web で示す予約枠と、兄妹の忙しい予定を照合し始めた。（強調された語句は、エージェントにとっての意味がセマンティック Web で定義される用語を表す。）

数分後、エージェントは計画を示した。しかし大学病院は母の家から遠く、帰りは渋滞するため、ピートは気に入らなかった。場所と時間の希望を厳しくし、自分のエージェントに再検索を指示した。この仕事の範囲ではピートのエージェントを完全に信頼するルーシーのエージェントが、アクセス証明書と整理済みデータへの近道を渡して自動的に支援した。

すぐに、もっと近い診療所でもっと早い時間という新計画が出た。ただし警告が 2 つあった。ピートが重要度の低い予定をいくつか変更する必要があり、確認すると問題なかった。もう 1 つは、保険会社の一覧ではその医療機関が理学療法施設として登録されていないことだった。「サービスの種類と保険加入状況は、別の手段で安全に確認しました」とエージェントは保証した。「詳しく見ますか？」

ピートが「詳しい話はいい」とつぶやく一方でルーシーは同意し、準備が整った。（もちろんピートは気になり、その夜、正しい一覧にない医療機関をどう見つけたのか、エージェントに説明させた。）

**意味の表現**

こうした仕事をエージェントに任せられるのは、現在ではなく将来の World Wide Web のおかげである。**現在の Web コンテンツの大半は人が読むために設計され、プログラムが意味のある処理を行うためには作られていない。**コンピューターは見出しやリンクを解析して配置や定型処理を行えるが、意味は一般に確実には扱えない。ここがハートマン＆ストラウス理学療法診療所のホームページで、このリンクがハートマン医師の経歴だとは分からない。セマンティック Web は、ページ内の意味を持つ内容に構造を与え、ソフトウェアエージェントがページ間を巡り、利用者の複雑な仕事を容易に実行できる環境を作る。診療所のページに来たエージェントは、「治療、医療、身体、療法」といったキーワードだけでなく、ハートマン医師が月・水・金に勤務し、スクリプトに yyyy-mm-dd 形式の日付範囲を渡すと予約時刻が返ることも知る。それに『2001 年宇宙の旅』の HAL や『スター・ウォーズ』の C-3PO 並みの人工知能は必要ない。計算機科学の入門授業も受けていない事務責任者が、セマンティック Web 用の作成ツールと理学療法協会のサイトにある資源を使ってページを整える際に、意味が符号化される。これは別のネットワークではなく、情報に明確な意味を与え、人と機械の協働を助ける現在の Web の拡張である。既存の Web に織り込む最初の作業は既に進んでいる。近い将来、今は表示するだけのデータを機械がもっと処理し「理解」できるようになり、重要な新機能が生まれる。Web の基本的な性質は普遍性だ。**ハイパーテキストの力は「何でも何にでもリンクできる」ことにある。**技術は、草稿と完成した作品、商業と学術、文化、言語、媒体などを差別してはいけない。情報の違いには多くの軸があり、人向けか機械向けかもその 1 つだ。前者には 5 秒のテレビ広告から詩まで、後者にはデータベース、プログラム、センサー出力がある。これまで Web は、自動処理できるデータや情報より、人向け文書の媒体として急成長した。セマンティック Web はその偏りを補おうとする。

インターネットと同様、セマンティック Web は可能な限り分散させる。ネットワーク型のシステムは、大企業から個人までを刺激し、事前には予測しにくい恩恵をもたらす。分散化には妥協が必要だ。Web は、すべての接続を完全に整合させる理想を捨て、悪名高い「Error 404: Not Found」を受け入れる代わりに、制限のない指数的成長を可能にした。

**知識表現**

機能させるには、構造化された情報と推論規則の集合をコンピューターが利用でき、それらによって自動推論できなければならない。AI 研究者は Web より前からこうしたシステムを研究してきた。「知識表現」というこの技術は、Web 登場前のハイパーテキストに似ている。よい考えで優れたデモもあるが、まだ世界を変えていない。重要な用途の種を持つものの、十分な力を発揮するには世界規模の単一システムへ結び付ける必要がある。従来は中央集権型が多く、「親」「車両」などに全員がまったく同じ共通定義を使う必要があった。しかし中央管理は窮屈で、規模や対象を広げるとすぐ管理が難しくなる。また、確実に回答するか回答しないかを計算機が判断できるよう、許す問いを慎重に制限する。これはゲーデルの定理を思わせる。有用なほど複雑な体系には、「この文は偽である」の複雑版のような、答えられない問いが含まれる。その回避のため、従来の知識表現システムはそれぞれ狭く特別な推論規則を使うことが多い。

例えば家系図データベースには「おじの妻はおば」という規則を入れられる。データは別システムへ移せても、規則はまったく異なる形式で存在し、通常は移せない。

対してセマンティック Web の研究者は、パラドックスや答えられない問いは、多用途性のために払う代償だと考える。必要に応じて広く推論できるよう、規則の言語に必要な表現力を与える。これは従来の Web と同じ発想だ。初期の批判者は、中央データベースや木構造がなければ整理された図書館にはならず、すべてを発見したと確信できないと指摘した。それは正しかった。しかし表現力のおかげで大量の情報が公開され、10 年前には非現実的に見えた検索エンジンが、その大半を索引化できるようになった。したがって課題は、データと推論規則を表す言語を用意し、既存のあらゆる知識表現システムから規則を Web へ書き出せるようにすることだ。

規則で推論し、行動を選び、問いに答える「論理」を Web に加えることが、現在のコミュニティの仕事である。数学的判断と工学的判断が混じり、難しくなる。対象の複雑な属性を表せるほど強く、エージェントがパラドックスを考えさせられて困らない程度には弱い論理が必要だ。幸い、表したい情報の多くは「六角ボルトは機械用ボルトの一種」といったもので、既存言語に語彙を加えれば簡単に書ける。

重要な技術である XML（Extensible Markup Language）と RDF（Resource Description Framework）は既にある。XML では `<zip code>` や `<alma mater>` のような独自の隠れたタグでページや一部のテキストを注釈できる。プログラムは複雑に利用できるが、作成者が各タグを何のために使ったかを知る必要がある。要するに XML は任意の構造を付けられるが、その意味は定めない［Jon Bosak、Tim Bray「XML と第二世代の Web」、Scientific American、1999 年 5 月を参照］。

RDF は、主語・動詞・目的語のような三つ組に意味を符号化する。XML タグでも書ける。人、ページなどの対象が、「姉妹である」「著者である」といった属性と、別の人やページといった値を持つと表明する。この構造は、機械処理する大半のデータを記述するのに自然である。主語と目的語は URI（Uniform Resource Identifier）で識別する。URL（Uniform Resource Locator）は最も一般的な URI の種類だ。動詞も URI で識別するので、Web のどこかで URI を定義すれば、新たな意味を持つ文書や動詞を誰でも定義できる。人の言語では同じ語を少し違う意味で使えるが、自動化ではそうはいかない。誕生日の客へ風船を届ける道化師のサービスを雇ったとしよう。相手は、こちらの「address」が請求書の送り先で、私書箱も多いと知らずに移す。道化師は多くの郵便職員を楽しませることになる。悪くはないが、意図した結果ではない。概念ごとに別の URI を使えば、郵便宛先と所在地、さらに演説という意味の address を区別できる。三つ組は関連する物事のネットワークを作る。URI によって、概念は単なる単語でなく、Web で誰でも見つけられる一意な定義につながる。住所を含む人物データベースを横断して、ある郵便番号に住む人を探すには、どの欄が名前や郵便番号か知る必要がある。RDF では語句の代わりに URI を使い、「（データベース A の第 5 フィールド）（フィールド型が）（郵便番号である）」と指定できる。

**オントロジー**

同じ郵便番号の概念に 2 つのデータベースが異なる識別子を使う場合があるため、話はまだ終わらない。比較や統合を行うプログラムは、2 つの用語が同じ意味で使われていると知る必要がある。理想的には、出会うどんなデータベースでも共通の意味を発見できなければならない。その解決策が第 3 の基本要素、「オントロジー」という情報の集合だ。哲学では存在の本質や存在する物の種類に関する理論を指し、それを研究する分野でもある。AI と Web 研究者は、用語間の関係を形式的に定義する文書・ファイルという意味で使っている。

典型的な Web オントロジーは、分類体系と推論規則を持つ。分類体系は対象のクラスと関係を定義する。住所を位置の一種とし、市コードは位置にだけ適用する、といった具合だ。クラス、サブクラス、実体間の関係は強力な道具である。クラスに属性を割り当て、サブクラスに継承させることで多様な関係を表せる。市コードが都市型でなければならず、都市が通常サイトを持つなら、直接のリンクを持つデータベースがなくても、市コードに関連するサイトを考えられる。

推論規則はさらに力を加える。「市コードが州コードと関連し、住所がその市コードを使うなら、住所はその州コードを持つ」と表せる。すると、イサカにあるコーネル大学の住所はニューヨーク州、さらに米国内にあり、米国標準の書式にすべきだと推論できる。

コンピューターは本当に「理解」したわけではないが、人にとって有用で意味のある形で、用語をより効果的に処理できる。

オントロジーのページが現れると、用語などの問題を解く方法が出てくる。ページ上の語や XML コードの意味は、オントロジーへのポインターで定義できる。もちろん、私がある郵便番号の概念を含む住所定義を、あなたが別の郵便番号の概念を使う定義を参照すれば、同じ問題が再び起きる。しかし片方か両方のオントロジー、あるいは別の Web サービスが、両者が等価だと示せば混乱は解消する。

道化師の例も、異なる住所定義を参照することで一部解決する。異なる概念に異なる URI を使えば混同せず、両者の関係を発見する必要があると分かる。そのうえで、第 1 のオントロジーに従う郵便宛先の一覧から私書箱などの不適切な宛先を除き、第 2 のオントロジーに従う所在地一覧へ変換するサービスを使える。構造と意味が定義されていれば、事業者はこのサービスを提供しやすくなり、利用者から変換を隠すこともできる。

オントロジーは、単純には、曖昧なキーワードを使う全ページではなく厳密な概念を参照するページだけを探し、検索の精度を上げられる。高度な用途では、ページ内の情報を知識構造と推論規則へ関連付ける。

例は [http://www.cs.umd.edu/\~hendler](https://www.google.com/url?sa=E&source=gmail&q=http://www.cs.umd.edu/~hendler) にある。ブラウザーには「Dr. James A. Hendler」という普通のページが見える。人なら略歴のリンクを見つけ、ブラウン大学で博士号を取得したとすぐ読める。しかしプログラムが略歴に情報があると推測し、英語を理解するには非常に複雑な処理が必要だ。

コンピューター向けには、計算機科学科の情報を定義するオントロジーのページにリンクしている。例えば教授は大学に勤務し、通常博士号を持つ。通常のブラウザーに見えない追加のマークアップは、その概念を使い、ヘンドラーが URI [http://www.brown.edu](https://www.google.com/url?sa=E&source=gmail&q=http://www.brown.edu) で表される実体、ブラウン大学で博士号を得たと指定する。研究プロジェクトの所属、メールアドレスなども発見できる。機械は容易に処理し、今は検索結果を人が読まなければならない「どこで学位を取ったか」といった問いに答えられる。さらに、1 ページだけには答えがない複雑な問題のプログラムも作りやすくなる。

昨年の商談会で会ったクックさんを探したいが、名前を忘れたとする。顧客の会社で働き、息子が自分の母校の学生だとは覚えている。賢い検索プログラムは、料理人、料理、クック諸島などを避けて「Cook」という人のページを探し、顧客一覧にある会社に勤める人を見つけ、子のページのリンクをたどって学校を確認できる。

**エージェント**

さまざまな情報源から Web コンテンツを集め、処理し、結果をほかのプログラムと交換するプログラムが多数作られたとき、真価が現れる。機械可読なコンテンツや、ほかのエージェントを含む自動サービスが増えるにつれ、エージェントの効果は指数的に高まる。意味付きのデータなら、明示的に連携用に設計されていないエージェント同士でも交換でき、この相乗効果を促せる。

重要な機能は「証明」の交換である。オントロジーで指定した規則と情報を用いる論理推論を表す、セマンティック Web の統一言語で記す。例えばオンラインサービスがクックさんの連絡先をヨハネスブルクで発見し、驚いたとしよう。確かめたいのでコンピューターが証明を要求すると、サービスは内部の推論を統一言語へ変換して返す。手元の推論エンジンは探す人物と一致すると容易に検証し、まだ疑問があれば関連ページを示せる。潜在力には遠いが、初期版の統一言語を使って既にこの交換を行うプログラムもある。

もう 1 つの重要な特徴はデジタル署名だ。信頼する特定の情報源が添付情報を提供したと確認する暗号学的データである。会計ソフトへ届いた「オンライン店への未払い金がある」という通知が、隣家のコンピューターに詳しい若者の偽造でないと確かめたいはずだ。エージェントは情報源を確認するまで、Web の表明を疑うべきである。（人間にも、もっとそうしてほしいものだ。）

自動化された Web サービスは既に多いが、意味が付いていなければ、ほかのプログラムは特定の機能を実行するものを見つけられない。この「サービス発見」には、機能と利用方法をほかのエージェントが「理解」できる共通の記述言語が必要だ。サービスやエージェントは、黄頁に似たディレクトリへ記述を登録するなどして能力を公開できる。Microsoft の Universal Plug and Play は機器の接続、Sun Microsystems の Jini はサービスの接続を目指す低水準の方式だが、構造・構文を扱い、事前に決めた機能記述群の標準化に大きく依存する。将来の需要すべてを予測できない以上、標準化には限界がある。セマンティック Web はより柔軟で、利用側と提供側はオントロジーを交換し、議論の基盤を共有できる。新たなオントロジーから、新しい推論能力を段階的に獲得することさえできる。要求に部分的に合うサービスも利用しやすくなる。典型的には、情報の部品がエージェント間を流れ、各段階で価値を加え、最後に利用者の求める製品を作る「バリューチェーン」になる。ただし複雑な連鎖を要求に応じて自動作成するには、セマンティック Web に加え AI 技術も必要だ。セマンティック Web はその技術を実用化する基礎と枠組みを提供する。すべてを組み合わせたものが、冒頭の兄妹のエージェントの能力である。機能の広告から見つけたサービスやエージェントへ、仕事を小分けに委託する。

例えば信頼するサービスで医療機関一覧を取得し、特定の保険と治療内容について保険対象内か判定できる。一覧は別の検索サービスが提供する、といった連鎖になる。Web 全体に散らばった状態ではほとんど価値のない大量の情報を、兄妹の予定や条件に合う予約計画という、少量で価値の高い情報へ段階的に絞り込むのである。

次に、仮想世界から物理世界へ広がる。URI は物理的な実体も指せるので、携帯電話やテレビも RDF で記述できる。機器も、何ができ、どう制御するかという能力をエージェント同様に公開できる。Universal Plug and Play のような低水準の方式より柔軟で、多くの可能性がある。現在の家庭自動化には機器を慎重に設定する必要があるが、能力と機能を意味的に記述すれば、人の介入を最小限にできる。ピートの着信時に音量を下げる例では、個別機器に設定せず、音量調節機能を公開するテレビ、DVD プレーヤー、その晩職場から持ち帰ったノート PC のプレーヤーなどすべてに、1 回設定すればよい。画面サイズなどの能力と利用者の好みを記す標準化は既に始まっている。RDF に基づく Composite Capability/Preference Profiles（CC/PP）である。当初は携帯電話など通常と異なる Web クライアントの特徴を示し、コンテンツを動的に適応させる。その後オントロジーと論理の全機能を加えると、機器は自動的にほかのサービスや機器を探し、情報や機能を得られる。Web 対応電子レンジが冷凍食品メーカーのサイトに最適な加熱条件を尋ねるのも、容易に想像できる。

**知識の進化**

適切に設計すれば、ここまでの個人向けの仕事だけでなく、人類の知識全体の進化も助けられる。人の活動には、小集団で独立して動く効率と、広い共同体への統合の必要性の板挟みがある。小集団は速く革新できるが、ほかの人に概念が通じない下位文化ができる。大集団の調整は遅く、大量の伝達が必要だ。世界は両極の間で、個人の考えから小さく始め、時間をかけて広い理解へ進む。共通言語が必要になると下位文化が融合することが、基本的な過程である。独立に似た概念を育てた 2 集団が、その関係を記述するだけで大きな恩恵がある。フィンランド語・英語辞典や度量衡換算表のように、用語がまだ共通でなくても、関係があれば意思疎通と協働ができる。

セマンティック Web では、URI で概念に名を付けるだけで、誰でも新概念を表せる。統一論理言語が、それらを徐々に共通の Web へつなぐ。この構造により、知識と人の活動をエージェントで意味のある形で分析でき、共に暮らし、働き、学ぶための新しい道具が生まれる。
