# 新しいエージェントネットワーク

- 開いた相互接続：
  - 全エージェントをつなぎ、データの孤島をなくして全体の文脈を渡す。微信や淘宝などの孤島は AI の協働に適さない。
- AI ネイティブのインターフェイス：
  - API やプロトコルで通信し、AI が得意な方法で情報を交換する。
- 効率的な協働：
  - 自律的に組織化し、交渉し、最も効率的に協働する。

# 3 つの大きな課題

- 身元と通信の安全性：プラットフォームをまたぐ仕組みで識別、認証、認可を行う。
- 接続コスト：特にプロトコル設計、結合テスト、運用保守を低コスト化する。
- 自律的な組織化と交渉：最も効率的な協働を実現する。

# 研究成果：Agent Network Protocol（ANP）

- 3 課題を解くための研究を ANP として公開した。接続方法を定義し、数十億のエージェントに開かれ、安全で効率的な協働網を作る。3 層のスタックが各課題に対応する。
  - アイデンティティ・暗号化通信層：W3C DID を基礎に、認証とエンドツーエンド暗号化を実現し、分散性、安全性、低コストを確保する。
    - TODO：DID を簡単に紹介する。
  - メタプロトコル層：「プロトコルのためのプロトコル」である。
    - 通信前に、役割と使用する方式を自然言語で交渉する。
    - LLM が合意した方式から処理コードを自動生成し、実行する。設計・結合テスト・運用保守のコストを下げる。
    - 自律的に組織化・交渉する網を作る。
  - アプリケーションプロトコル層：具体的な通信方式で、主に次を含む。
    - 既存の業界規格。
    - エージェント網が自ら交渉・選出する規格。
    - 2 つのエージェント間の個別プロトコル。

# 将来の課題

- 合意：毎回の交渉は高コストなので、他者が合意済みの方式を再利用し、合意アルゴリズムで標準方式を選ぶ仕組みが必要だ。
- コード生成：LLM にプロトコル処理や業務フローのコードを直接生成させ、安全上の危険をなくすことが課題だ。
- 標準化：ANP が最適解とは思わず、改善が必要だ。業界が共通標準を確立できるかが、急速な発展の鍵になる。

# エージェントネットワークの新たな形：AI の接続と協働を再定義する

## エージェントの紹介

- **エージェントは未来だ**：技術界の共通認識であり、次の技術革命を主導する。
  - **ビル・ゲイツの見解**：Android、iOS、Windows に続く次の主流プラットフォームである。
  - **OpenAI の AGI の分類**：
    - **Level 1**：チャットボット。
    - **Level 2**：推論者。
    - **Level 3**：エージェント。
    - **Level 4**：革新者。
    - **Level 5**：組織者。

## エージェントの発展

- ChatGPT 公開以来、急速に発展した。公開プロジェクトから見て 3 段階を経ている。
  - **第 1 段階：単独のエージェント**
    - **代表**：AutoGPT、babyagi、XAgent。
    - **特徴**：独立した探索とタスク実行の初期段階。
  - **第 2 段階：複数エージェントの協働**
    - **代表**：AutoGen、Swarm、MetaGPT、Magentic-One。
    - **特徴**：エージェント同士が協働する段階。
  - **第 3 段階：エージェントネットワーク（Agentic Web）**
    - **代表**：Agentic Web（面壁の公開プロジェクト）、Agora Protocol、Agent Network Protocol。
- **例え**：
  - 単一サーバーから LAN、インターネットへ進化している。
  - 1,000 億ドルの価値がある問いに答えなければならない。
    - **エージェントの網は従来のインターネットと何が違うか？**
- **考える方向**：
  - 本質である実体間の情報交換に立ち返る。
  - デジタル世界との対話、エージェント間の情報交換を調べる。
  - まず現在の実装を見る。

## 移行期の形：コンピューターを操作するエージェント

- **関連製品**：
  - **Claude**：Computer-Use API。
  - **智譜 AI**：AutoGLM。
  - **OpenAI**：Operator（2025 年 1 月公開予定）。
- **現状分析**：
  - PC・携帯を使って仕事を行う製品が現れ、Claude と智譜 AI が公開し、OpenAI も計画中だ。
  - 人向けの従来のネットにつなぐ、最善の移行方式かもしれない。
  - しかし人の操作を学ぶことは、将来の最高効率の方法ではない。
- **将来の展望**：
  - 人の模倣より、AI の特性に合わせたネットの改造が最も効果的だ。

## 将来の効率的な情報処理と交換

- **キーワード**：
  - **下位のデータを直接処理**：
    - **説明**：UI・画像に頼らず、バイナリや構造化データを直接扱う。
    - **施策**：AI 向けインターフェイスで効率を高める。
  - **全体の情報を把握**：
    - **説明**：関連情報をすべて取得・処理し、文脈を完全に把握する。
    - **意義**：網羅的な情報があってこそ最善の判断・行動ができる。
  - **自律的な交渉とコード生成**：
    - **説明**：情報交換方式を自分で交渉し、コードを生成して情報を処理する。
    - **利点**：通信を効率化し、協働を実現する。
- **結論**：AI の能力を最大限に解放し、効率的な接続・協働を実現する必要がある。

## 新しいエージェントネットワーク

- **開いた相互接続**：
  - **特徴**：すべてをつなぎ、データの孤島をなくす。
  - **利点**：全体の文脈を把握し、協働と革新を促す。
  - **現状の問題**：微信、淘宝などの孤島は AI の協働に適さない。
- **AI ネイティブのインターフェイス**：
  - **特徴**：API やプロトコルを使う。
  - **利点**：AI の得意な方法で交換し、効率と正確さを高める。
- **効率的な協働**：
  - **特徴**：自律的な組織化と交渉。
  - **利点**：効率よく複雑な問題を解く。

## 3 つの大きな課題

- **身元と通信の安全性**：
  - **問題**：プラットフォームをまたぐ身元体系をどう作るか。
  - **目標**：相互識別、認証、認可で安全に通信する。
- **接続コスト**：
  - **問題**：接続の費用をどう下げるか。
  - **課題**：設計・結合テスト・運用保守の複雑さと資源消費を減らす。
- **自律的な組織化と交渉**：
  - **問題**：どう自律的に組織化・交渉するか。
  - **目標**：変化に適応し最も効率的に協働する。

## 研究成果：Agent Network Protocol（ANP）

- **概要**：
  - 3 課題の研究成果を **ANP** として公開した。
  - **構想**：接続方法を定義し、数十億のエージェントに開かれ、安全で効率的な協働網を作る。
  - **検索サービス**：ANP で他のエージェントが提供するサービスを探せる。
  - **記述プロトコル**：ANP でサービスを記述し、他者が呼び出せるようにする。
- **スタックの構造**：3 課題に対応する 3 層である。
  1. **アイデンティティ・暗号化通信層**：
     - **基礎**：W3C の**分散型識別子（DID）**標準。
     - **機能**：認証とエンドツーエンド暗号化。
     - **利点**：分散性、安全性、低コストを確保する。
     - **DID の紹介**：W3C が定める Decentralized Identifier。
       - **特徴**：中央の登録機関に依存しない分散性、自分で身元を作成・管理する自律性、暗号化と検証による安全性。
  2. **メタプロトコル層**：
     - **定義**：通信方式を交渉する「プロトコルのためのプロトコル」。
     - **機能**：通信前に自然言語で役割と方式を交渉し、LLM が合意から処理コードを自動生成して実行する。
     - **利点**：設計・結合テスト・運用保守を大幅に低コスト化し、自律的に組織化・交渉する網で協働の効率を上げる。
  3. **アプリケーションプロトコル層**：
     - **機能**：具体的な通信で実際の業務を行う。
     - **構成**：広く受け入れられた業界規格、網が自ら交渉して選ぶ規格、特殊な需要に応える 2 者間の個別方式。

## 将来のネットワーク構成の案

- 人向けのエージェント助手。
- バックエンド向けのエージェントサービス。
- 発見サービス：記述プロトコル。
- 重要な方式：身元、エンドツーエンド暗号化、メタプロトコル、発見・記述、業界標準、エージェントの合意によるプロトコル。

## 将来の課題

- **合意の仕組み**：
  - **問題**：通信ごとの再交渉は高コスト。
  - **課題**：合意済み方式の再利用と、合意アルゴリズムによる標準の選出。
  - **意義**：大規模な協働の鍵になる。
- **コード生成能力**：
  - **問題**：LLM に処理・業務フローを直接生成させる方法。
  - **課題**：危険がなく、信頼性と安定性を保つコード、および複雑な場面での生成能力。
  - **意義**：配備と実行の効率を大きく高める。
- **標準化**：
  - **問題**：ANP はまだ最適とは限らず、継続改善が必要。
  - **課題**：業界で確立・普及し、各者を調整して標準を作り改善する。
  - **意義**：急速な発展の基礎である。
