HTTP は設計時からインターネットのアーキテクチャを考慮し、プロキシ、ゲートウェイ、キャッシュ、ルーティング、負荷分散などの仕組みを備えています。これらの仕組みを、私たちはどう利用できるでしょうか。

第一段階として HTTP を基盤にするのは、非常に現実的な選択です。
第二段階では、独立したプロトコルを設計するか、HTTP 4.0 を補うものとして設計します。

HTTP の設計目標はエージェントの目標と一致しているのでしょうか。ここには最適化の余地があります。
