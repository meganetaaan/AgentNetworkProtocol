現在、OAuth ベースのプログラムについて話し合い、既存のインフラを複製するために十分に標準化されていますが、全体的なプロセスはやや複雑です。
W3C DID(Decentrazed Identifiers)規範に基づいて新しいプログラムを提案したいと思います。 このプログラムは長い間研究し、このプログラムを探求してきました。アイデンティティ認証の問題やインテリジェントなボディ間の暗号化された通信に対処する主な目的は、MCPクライアントとMCPサービスプロバイダにも使用できると思います。

まず、将来のAI通信プロトコル(MCPなど)がオープンし、中央の信頼機関の使用を避けるべきだと私は同意します。これはW3C DIDが推進しているものであり、そうするものです。W3C DIDは、集中認証機関に依存することなく、ユーザーが自分のアイデンティティ情報を完全に制御できるようにすることを目指しています。

DIDメソッドを設計し、IDの生成と認証に使われるすべてのメソッドが簡単に記述します。

- アリスとボブはそれぞれ独自のDIDを生成し、次のように生成しました。
  - 自分によって保存される非対称暗号化用の秘密鍵と公開鍵を生成します。
  - Hashアルゴリズムを使用して、IDを独自のアイデンティティとして生成します。例: id:all: 14qQsnEPZy2wcpRy2xeR737ptkE2Wwwww@example.comはDIDドキュメントサーバーです。
  - DID と公開鍵情報を DID ドキュメントにし、秘密鍵で署名して、DID ファイルにアクセスして DID から対応する公開鍵情報を取得する Web serverexample.com に保存します。

- アリスとボブが接続されたとき、その識別プロセスは次の通りでした。
  - アリスは、接続リクエストで、自分のDIDを提示し、プライベートキーを使ってメッセージを署名します。
  - Bob は、Alice の DID に基づいて、Webserver EXAMPLE.com から Alice の DID ファイルを取り、DID ドキュメントの公開鍵を通した Alice の DID (DDD が DHash によって生成されます) を認証します。シグネチャが正しい場合は、Alice が接続を開始したことを示します。
  - 同じように、Bobは接続応答で自分のDIDを提供し、接続メッセージにプライベートキーを署名します。Aliceは同一のプロセスを使用してアイデンティティを認証します。
  - 両当事者の識別が完了し、その後の通信が暗号化されました。

- アリスとボブは、非対称暗号化キーを持っているので、暗号化キーの協議のために、ECDHE(エリプティックカーブディフィーヘルマン電子)を使うことができます。これにより、エンドツーエンド暗号化された通信を実行するために使用できるのです。
