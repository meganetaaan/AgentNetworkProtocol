# 題名：Anthropic MCP に対抗する中国発のオープンソースプロトコルが、エージェント自身によるネットワーク形成を実現
# 題名：Anthropic MCP に対抗する中国発のオープンソースプロトコルが、AI スタートアップの消費者向け事業の壁を破るかもしれない

## はじめに

Anthropic が数日前に公開したオープンソースプロトコル MCP（Model Context Protocol）が、インターネットで大きな話題になっています。一方、中国のあるチームは以前からこの分野に取り組み、同種のプロトコル ANP（Agent Network Protocol）を公開しています。ANP の最新版では、エージェント自身がネットワークを形成できます。AI 時代の HTTP に当たるプロトコルが、今まさに定義され、従来のインターネットの生態系を根底から変えつつあるのかもしれません。

## MCP とは

MCP は AI の大規模モデルが外部データと「対話」するための新技術です。橋のように働き、AI が各種ツールやデータ源を容易に取得・利用できるようにします。以前の AI アプリケーションは、データ接続の難しさから「情報の孤島」に閉じ込められがちでした。MCP があれば、万能プラグのように必要なあらゆる資源へ接続できます。AI 製品の体験を大きく改善し、インターネットの生態系を変える可能性があります。

![mcp-architecture](../../../../chinese/思考&问题/pic/mcp-architecture.png)

しかし現時点の MCP には、リモート接続に対応せずローカルサービスにしかアクセスできないという致命的な欠点があり、実用性が大きく制限されます。

根本的な理由は、MCP コミュニティが AI と外部サービス間の認証方法をまだ決めていないことにあります。中国のあるチームは数か月前にこの問題を解決し、エージェントに通信能力を与える同種の ANP（Agent Network Protocol）をオープンソース化しました。

## ANP

ANP チームの大半のメンバーは Alibaba 出身です。2024年初頭からエージェント通信の探究を始め、プロトコル仕様と実装を公開しました。最新版はエージェント間認証、E2EE 通信、メタプロトコル交渉、アプリケーション層のプロトコルコード生成に対応します。これらにより、エージェントは自らネットワークを形成し、協働できます。仕組みを見てみましょう。

プロトコル仕様：https://github.com/agent-network-protocol/AgentNetworkProtocol

実装：https://github.com/agent-network-protocol/AgentConnect

### 認証：最も重要な課題

エージェント間の認証は重要ですが、難しい問題でもあります。そうでなければ、MCP が完全な認証方式を備えずに公開されることはなかったでしょう。

何が難しいのでしょうか。最も難しいのは、AI 時代の認証要件がインターネット時代とまったく異なることです。

インターネット時代の認証は、WeChat のように集中型であることが一般的でした。WeChat ID は WeChat の生態系内でしか使えず、淘宝や Douyin では使えません。これが情報の孤島を作り、データが相互に通じないため、AI は利用者の情報全体を得られず、正しい判断や行動ができません。その結果、AI 製品の体験も飛躍的には改善しません。

Anthropic の MCP チームのように、このことに気づいているスタートアップは多数あります。彼らは MCP の生態系が開かれているべきだと考え、中央の信頼機関を使うことを避けようとしています。

![mcp-auth-thinking](../../../../chinese/思考&问题/pic/mcp-auth-thinking.png)

AI にとって分散型認証がこれほど重要なのはなぜでしょうか。

ここ2年間に中国で起きた事例を見ると、理解できるかもしれません。

会読は昨年人気を集めた読書用 AI アプリで、主に WeChat 上で展開していました。しかし利用者数が増えるとアカウントが頻繁に WeChat に停止され、最終的にプロジェクトは失敗しました。多くの利用者が製品を気に入っていても、利用者のアイデンティティを WeChat が握っていたため、どうにもなりませんでした。

この観点から見ると、集中型の従来のインターネットやモバイルインターネットの大手は、AI という先進的な生産力の支援者ではなく、障害です。

最近の中国の大規模モデル分野の主要スタートアップの苦境と合わせると、従来のインターネット大手が築いた生態系から抜け出して初めて、AI の生産力を解き放ち、スタートアップが新たな道を見つけられることが分かるかもしれません。

その第一歩は分散型認証方式の設計です。

ANP は標準を一から作ったのではなく、W3C が2022年に公開した DID（Decentralized Identifiers）標準を基盤としています。DID は当初からインターネットの集中型アイデンティティ問題の解決を目的に設計され、利用者自身によるアイデンティティ管理とプラットフォームをまたぐ認証を可能にします。

ANP の最大の貢献は、中央機関ではなく暗号技術に認証を依存させる DID メソッドを設計したことです。分散性と拡張性のバランスを取り、分散性を保ちながら DID の大規模な実用化を可能にしました。

### メタプロトコルによるエージェント自身のネットワーク形成

メタプロトコルとはプロトコルのプロトコルであり、エージェント間の通信プロトコルを交渉するためのものです。

従来のサーバーとの最大の違いは、エージェントが AI の能力を使って条件を満たす相手を探し、2体で自然言語による通信プロトコル交渉を行い、AI が生成したプロトコルコードでデータ通信を行えることです。この過程で、メタプロトコルによって接続試験や更新も自動化できます。以下は ANP のメタプロトコルを使って接続を確立する全体の流れです。

![meta-protocol-flow](../../../../chinese/思考&问题/pic/meta-protocol-flow.png)

天気情報の取得を例に、エージェント A と B がメタプロトコルで交渉する基本的な流れを示します。

![meta-protocol-weather](../../../../chinese/思考&问题/pic/meta-protocol-weather.png)

メタプロトコルがあれば、人間を介さずにネットワークを自ら形成し、協働できます。自律的に組織し交渉するエージェントネットワークは、将来さらに大きな生産力を解き放つでしょう。

### アプリケーション層のプロトコル：発見と記述

あらゆる接続をメタプロトコル交渉で確立するとコストが高く、手順も長いため時間がかかります。そのため ANP は、アプリケーション層にエージェントの能力を発見・記述する仕組みを設けました。この点は MCP の設計と似ています。

例えば、エージェントが自分のアイデンティティ、能力、対応プロトコルを発見サービスに登録すれば、別のエージェントは条件に従って相手を検索し、対応プロトコルを使って通信できます。これにより接続効率を大幅に高められます。

![agent-find](../../../../chinese/思考&问题/pic/agent-find.png)

アプリケーション層のプロトコルには、既存の人間の標準、エージェント間の合意による標準、2体間だけの独自プロトコルなどを使えます。将来、エージェントが自動交渉するプロトコルの数は、人間が策定したものをはるかに上回るかもしれません。

## 将来

Anthropic の MCP に比べて ANP の業界への影響力ははるかに小さいものの、よい設計上の考え方を見ることができます。

MCP であっても ANP であっても、この分野はまだ非常に初期の段階であり、すべてが不確定です。

最も重要なのは、MCP や ANP が業界標準になることではなく、将来の業界に、開かれた分散型の標準が必ずあることかもしれません。それによって初めて AI の生産力を最大限に解き放てます。
