## 1. 回復とチェック

Node.js22 を使用して、プロトコルのワークツリールートディレクトリで実行するか、バージョンを更新します。

```sh
node scripts/generate-anp02-vectors.mjs
node scripts/check-anp02-vectors.mjs
```

最初の注文は、保存された文書と特定の再構築を比較し、それらに書きません。 2番目のチェックは、フォルダの引用、選択した基礎アルゴリズムによって知られている答え、シグネチャ/summation/オブジェクトプルーフ/AEADバイト、拒絶およびシーンカタログカバレッジで改ざんします。 SDKはゼロを報告します。

これらのキットの再生は、ベクトルを変更し、レビュー後に行うことを目的として行われます。

```sh
node scripts/generate-anp02-vectors.mjs --write
```

固定時計として `2026-09-07T08:00:00Z`;壁ではなくシーンクロックを使用するテスト。 キーダーivedラベル `ANP02-PUBLIC-TEST-ONLY:` 生成されたキーはテストの外で使用できません。 P5 メッセージ キー/したがって、ビルドアップセッションの制御入力です: ベクターチェック AAD / AEADバイト、X3DH、ラチェット推進またはデバイスエントリを検証しません。 P6 境界証拠には本物が備わっていますが、フルコード化された MLS KeyPackage や MLS グループが実行されていません。

## 2. 認証と送信ボーダー

`HTTP-*` 実際のHTTPメソッド/オブジェクト/コンテンツコンポーネントの使用`JSON-*` 宣言された HTTP JSON メタデータ結合、要約のオーバーリーフを使用しない `auth` 初めて見たのは、大事でした。`ORIGIN-*` 変更されていないP1署名付きレビューオブジェクトを使用して、 `anp://` 対象マップ。これらの署名は交換できません。

プロトコルシーンは、解像度、方法論的証拠、使用許可、時間/再オープン状態およびビジネス特権を独立してチェックします。バイトチェックはこれらの条件を作成していません。Webがドキュメントプログラムを持っていないときに必要なバンドル、制御オーガンプルーフ、MLS、メッセージ認証は引き続き完了する必要があります。

## 3. サイトアダプタ契約

このパッケージのセットには、Ed25519、Multikey、JWK を使用して、適切な機能の下で相互運用性を実証する意図があります。これは、ANP-02 の一般的な最小アルゴリズムまたは表現要件を追加していません。宣言されたサポートを達成するために、シーンを選択します。 JWT の発行者/udience/scope シナリオは、トークン ポリシーとエラーマッピングの例を明確に選択します。この戦略が達成されるときだけ、すべての AMP-02 はこれらの単語や戦略を使用する必要はありません。 EBAE1 および有効なパスワードは、既存の要件を満たしている必要があります。

指定されたシーンの認証 `applicability: illustrative-implementation-policy-not-additional-anp02-conformance`. 境界、キャッシュ、Resolver、証拠選択、エラーマッピング、要約およびトークンポリシーの再生は、AMP-02標準要件に追加しないか、変更を有効化する既存の行動を必要とする選択肢の例です。元のテキストにセットされていない特定の条件がある場合、それはAMP-02 1.2で説明され、計画されたシーンベースのバックスラッシュプロトコルを使用せずに目的の結果を達成する必要があります。元のテキストは、元のJWT日付文字列も保持します。この例では、NuDateは、現在選択されていないとNuDateが変更されることはありません。

各シナリオは以下で構成されています。

- `input`: 同一/バイトおよび管理された初期状態への参照;
- `actions`: プロファイルプロセスに実装または関連する正確な変更。
- `expected`: 拒絶、受容、信頼性、またはこのシナリオで選択した戦略のスコープ下にあるステータス副作用の境界;
- `normative_refs`_: これら要件を保有する規範
- `execution_status`: この段階では、Pディレクトリはそのまま残っています。 `design-only-not-run-against-sdk-or-product`。

アダプターは、負の修正を適用する前に法的ベースラインを確立しなければなりません。 WBA文書がその後の認証レイヤーをテストすることによって変更された場合、E1プログラムファは、ターゲット認証層を分離するためにテストルートキーを使用して再生されるべきです。 無効なE1証拠をテストするときに修復することはできません。 MLSシナリオは、適法パッケージとグループの状態を精密、KeyPackage/リーフで結合し、指定された変更を実行するために使用します。 分離されたバイトは、そのステータス自体を提供することはありません。

WNS シーンは、元のスキームに従います。WBA はドメインの制限、パブリックな正確なハンドル、プライベートプロジェクターの確認を保持します。Web リザーブは DID および HTTPS プロジェ ドメイン宣言を強制せず、逆エンドポイントが非リファレンスまたは弱限結合マイグレーションに強制的にチェックされています。 `legacy-domain-binding-accepted` 通常の API フォルダーには、マイオッティングのハンドル、サービス、機器マニフェストの目的があります。フルメッセージのシーンは WBA をカバー?WBA、WA ??? Web ? WBA、Web ?? Web ? Web_Packet、P5/P6、定期的な/暗号化されたプライベートチャットとグループチャットの添付ファイル、普通/暗号化されたメンション、およびサービス ID およびコールアッチャーメソッドを独立して変更します。

SDK/プロダクトランナーは、このディレクトリの設計状況を運用として書き換えることなく、独自の証拠で真の結果を記録すべきです。メソッドの解像度、TLS/Cache、共同発見、耐久性、リボベーション、MLS、オブジェクトストレージ、およびユーザー可視性は、ステージA/ Bによって行われます。非有効化された方法は、既に存在するWebVHを代表さない、WebVHを拒否します。
