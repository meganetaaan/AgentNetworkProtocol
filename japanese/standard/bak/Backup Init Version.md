## 1. 概要 - Huacheng、移動

AIエージェント技術の開発に伴い、アプリケーションシナリオを継続的に拡大しています。 初期の簡単なタスク実行から複数のエージェント間で複雑なコラボレーションタスクまで、エージェントはさまざまなフィールドで大きな可能性を発揮しています。 個々のエージェントの強みを最大限に活用し、タスク実行の質と効率性を向上できるマルチエージェントコラボレーションモデルです。 しかし、マルチエージェントのコラボレーションに対する需要が高まるにつれて、エージェント間で標準化された通信プロトコルを定義して、広域相互接続、クロスドメインの相互運用性、安全なコラボレーションが対処する緊急の問題となっている。
AIエージェントの通信ニーズを満たし、マルチエージェントコラボレーションの広範なサービスを促進するため、信頼ドメイン内のエージェント間の相互接続、相互運用性、および安全なスケーラビリティをサポートする標準化されたエージェント通信プロトコルを定義することが重要です。
### 1.1. . オブジェクト
- 標準化: エージェント間でシームレスな通信と相互運用性を可能にする統一された通信プロトコル規格を確立します。
- 広域連携: エージェント間の情報交換が地理的境界によって制限されていないこと、さまざまなシナリオでエージェントの通信ニーズを満たすことを確実にする、幅広い領域にわたって安定した効率的な接続をサポート。
- セキュリティとスケーラビリティ: エージェント通信におけるデータセキュリティ、プライバシー保護、アイデンティティ認証の確保、攻撃やデータの漏洩を防ぎます。 また、プロトコルはエージェント技術や新しい要件の継続的な開発に適応し、機能的なアップグレードとプロトコルの最適化を促進するための優れたスケーラビリティを持っている必要があります。
### .1.2.(日) スコープ
ネットワークサービスドメインの分裂の観点から、展開拠点をベースとした3種類のエージェントを、ネットワークの外部代理店やネットワークサイドエージェント、エージェントなどから簡単に分類できます。 このドラフトは、主にオペレータのネットワーク内で管理されたエージェント間の通信に焦点を当てています。 エージェントの2つのタイプの通信:
1. 同一ネットワークサービスドメインに登録された端末側エージェント間の通信。
2. 端末側エージェントとネットワーク側のエージェント間の通信は、同じネットワークサービスドメインで登録されています。
3. ネットワークサービスドメインに登録されたネットワーク・サイドのエージェント間の通信。
また、異なるネットワークドメインに登録されたエージェント間の通信は、この議論の範囲内では行われません。
### .... 用語と定義
- タスク:タスクは特定のゴールを達成するために必要なアクションです。 これらの行動は、物理的または認知的であることができます。
- タスクチェーン:タスクチェーンは、タスクの順序セットを定義し、適用される制約を注文するタスクを定義します。例えば、パケット、フレーム、フローなど。 アーキテクチャは複数のブランチのタスクチェーンを可能にし、またタスクが適用する必要がある順序で柔軟性がある場合を可能にするので、黙った命令は線形進行ではないかもしれません。
- コーディネーターエージェント:タスクを受信し、他のエージェントにタスクを分解または配布するエージェント。
- 執行エージェント:コーディネーターの業務を遂行する責任を持つエージェント。

## 3. デジタルID
会員登録、発見、コミュニケーションの流れにデジタルアイデンティティ機構を採用。
- 参加登録:デジタルアイデンティティは、通信フロー中に認証とアドレスをベースとしてAIエージェントのグローバル一意の識別子を持っています。 複数のエージェント関連の属性(キャパビリティ/スキル/サービス)は、デジタルアイデンティティに含まれており、同時に識別子で登録されています。 デジタルアイデンティティの関連資格情報は、検証に使用できます。
- 発見:登録されたAIエージェントは、識別子または機能に基づいて他のエージェントによって発見することができます。 エージェントは異なるドメインで発見することができます。
- コミュニケーション:AIエージェントは、発見されたデジタルアイデンティティから得られた識別子で初期メッセージを送ることで、他のAIエージェントと通信することができます。 この識別子を使用して、ターゲットAIエージェントにメッセージをアドレス化しルーティングすることができます。
- 認証: 通信施設では、AIエージェントは認証のために識別子の資格情報を使うことができます。 認証後には、属性が交渉できます。
- 認可:人間通信と比較して、AIエージェントのコミュニケーションは、常に明示的に許可される必要があります。 属性ベースの認可メカニズムは、ユーザー認証でも、直接エージェントの承認と委任された承認の両方をサポートできます。
上記要件を満たすため、W3C分散型識別子(DID)と汎用性(VC)規格を基本デジタルアイデンティティコンポーネントとして導入することをおすすめします。
- DID: コアDID仕様は、特定の計算インフラを使用して分散型識別子を構築するために、実装者を必要としません。これにより、既存の成熟技術と十分に確立されたネットワークインフラストラクチャを完全に活用して、DIDを構築することができます。
- VC: VC は、AI エージェントの属性のコンテナとして使用できます。 AIエージェントの属性は、VCによって検証できる異なるソースから来ることができます。 これにより、横断的なコミュニケーションの相互運用性が向上します。

## 4. エージェントの説明 - ANP
ドキュメントのフォームにエージェントの説明(AD)が存在します。 AD文書は、エージェントにアクセスするためのエントリポイントとして機能します。 ウェブサイトのホームページに同様に機能します。 エージェントの名前、アフィリエイトエンティティティティ、機能、製品、サービス、およびインタラクション API やプロトコルなどの情報を取得するには、この AD ドキュメントから取得できます。 エージェント間のデータ通信とコラボレーションが実現できる情報です。
### 4.1. . エージェントの説明 ドキュメント形式
Agent 説明(AD)文書は、エージェントの外部エントリ ポイントとして機能し、次の形式で提供することができます。
#### 4.1.1.1.1. の 自然言語の形式
AI機能の進歩を重んじると、AD文書は自然言語で完全に記述できます。
#### 4.1.2. . 構造化されたフォーマット(推薦される)
異なるエージェントは、異なる機能を持つモデルをさまざまな機能で活用する可能性があるため、多様なモデル間で同じデータの一貫性と正確な解釈を保証するために構造化されたアプローチが推奨されます。
構造化されたフォーマットは複数の文書タイプを支えます:
- JSON(推奨)
- JSON-RPCの特長
- その他の構造文書フォーマット
### 4.2. . エージェント情報インタラクション機構
システムは、情報相互作用メカニズムを「Webクローラー」にアナログで採用しています。具体的には、エージェントはURLを利用して外部に提供したリソース(例えば、情報、インターフェイス)をエージェントの説明文書から相互接続し、ネットワーク化されたエコシステムを形成します。 他のエージェントは、クローラーのように動作し、説明されたメタデータに基づいて、適切なリソースをローカルシステムに選択的に取得することができます。その後の意思決定と処理が自律的に起こる。
Web クローラのような情報インタラクション モードの利点:
- 既存のインターネットアーキテクチャとの互換性:エージェントの公開情報を検索エンジンインデックス化を促進し、効率的なエージェントデータネットワークの作成を可能にします。
- プライバシー保護の強化:リモートデータをローカルシステムに引き出すことで、タスクデリゲーションモデルに固有のユーザーのプライバシー漏洩リスクを軽減します。
- 階層構造:多数のエージェント間でスケーラブルな相互作用をサポート
エージェントの説明文書には、次の2種類のリソースが含まれます。
#### 4.2.1.1. . インフォメーション
エージェントは、以下の種類のデータを提供できます。
- テキストファイル(例:.txt、.csv、.json)
- .jpg, .png, .svg などの画像ファイル
- ビデオファイル(例:.mp4、.mov、.webm)
- オーディオファイル(例:.mp3、.wav、.aac)
- その他のファイル
#### 4.2.2.2. インターフェース
エージェントインターフェイスは2つのタイプに分類されます。
- 自然言語インターフェイス
-- エージェントが自然言語のやり取りを通じてパーソナライズされたサービスを配信できるようにします。
-- 人間のようなコミュニケーションおよび適応応答を支えて下さい。
- 構造インターフェイス
-- 定義された議定書によって有効な、標準化されたサービス配達を促進して下さい。
--相互運用性および機械に機械に機械オートメーションを保障して下さい。
### 4.3. . セキュリティメカニズム
Agent 説明(AD)文書のセキュリティ設定は必須です。 エージェントレベルでのセキュリティ・定義は、セキュリティ・メンバーによって有効化されなければなりません。 この設定は、エージェントのインタラクションに必要なセキュリティメカニズムを構成する。
- グローバルスコープ: セキュリティーが AD ドキュメントのルートレベルで宣言されると、文書内のすべてのリソースはアクセスのためにこのセキュリティメカニズムを強制しなければなりません。
- リソース・スペフィックスコープ: 個々のリソース内でセキュリティが定義されている場合は、指定されたセキュリティ条件が満たされた場合のみ、そのリソースへのアクセスが付与されます。
- 優先ルール:リソースレベルのセキュリティがルートレベルのセキュリティと競合する場合には、リソースレベルの定義は優先されます。
### 4.4. . 整合性検証
悪意のある改ざん、偽装、またはエージェントの説明(AD)文書の再使用を防ぐため、検証メカニズムの証拠はAD文書構造に組み込まれています。
証拠の定義は仕様書に従うものとします。 [https://www.w3.org/TR/vc-data-integrity/#defn-domain].

## 5. タスク - 中国クラウドコア、ANP関与
### 5.1. . プロフィール
タスクのコア機能は、通信に関与するAIエージェントが「何をすべきか」に合意できるようにすることです。これにより、誤解によるコラボレーション障害を回避することができます。
機能の発見およびコミュニケーション手順でタスクを使用することができます:
- 機能の発見:タスクの説明に基づいて、AIエージェントをマッチング機能で取得します。
- コミュニケーション: Coordinator Agent が Execution Agent に通信リクエストを開始したときに、リクエストメッセージはタスクの説明を運ぶことができます。 また、画像、動画、ファイルなどのその他の補助情報もタスクの達成に役立つタスクの説明と共に送信することもできます。
タスクの説明やタスクテンプレートの正確な記述 REQUIRED あらゆるエージェントが目的、運用上の制約および基準の一貫した理解を維持するようにします。
よく定義されたタスクの説明:
- 曖昧性を低減:エージェント間での誤解や競合行為を最小限に抑えます。
- 汎用性:抽象的な目標を実行可能かつ測定可能な計画に翻訳します。
- 堅牢性の向上:コラボレーションが、動的条件下で一貫性と効率性を維持できるようにします。
AIエージェントがタスクを実行できます。 複雑なタスクがAIエージェントによって受信されると、このタスクは一連のサブタスクに分割され、タスクチェーンとして知られるクリアな実行シーケンスで、AIエージェントのグループによって実行されます。 タスクチェーンは、複数のAIエージェントがポリシーに基づいて特定のシーケンスで異なるタスクを実行し、複数のAIエージェントを共同して複雑なタスクを達成することができます。 エージェント通信プロトコルは、タスクチェーン情報をカプセル化するためにサポートする必要があります。例えば、下流ネットワーク輸送(IP、MPLSなど)とは独立しています。

タスクは、グローバル固有のタスクIDで識別されます。 タスク ID は、タスクを作成または割り当てるエージェントによって生成され、実行する責任のあるエージェントにタスクと共に送信されます。
### 5.2. . タスク・ステート
タスクを受信すると、Coordinator Agentは複数のサブタスクに分解し、動的機能のメカニズムを介して異なる実行エージェントにそれらを委任することができます。 AIエージェントプロトコル設計は、タスク実行ライフサイクル全体で包括的な状態の説明をサポートする必要があります。
タスクを完了する時間の長さに基づいて、タスクは次のように分類できます。
- 短期タスク: これらのタスクは、天気をクエリするなどの簡単なタスクに素早く実行し、完了することができます。
- 長期タスク: これらのタスクは、長時間の期間を必要とするか、複数のラウンドの相互作用または記事を書くなどの待機期間を延長することが必要です。 長期タスクの実行中、AIエージェントは、必要に応じてタスクの状態や中間結果を同期させることができます。
Coordinator Agent は、実行エージェントとコンテキスト情報の中間結果に応じてタスクのターゲットを動的に調整できます。 AIエージェントプロトコルの設計は、長期および短期のタスク管理をサポートすべきです。
タスクの状態は実行AIエージェントによって維持され、必要に応じてタスクステータスをエージェント間で同期させることができます。
### 5.3. . タスクのコーディネート
AIエージェント間のタスクコラボレーションは、異なるモードを持つ可能性があります。
- プライマリ/セカンダリモード:Coordinator Agentは複数のタスクにタスクを分解し、処理のために実行エージェントに配布します。 Execution Agent は、実行結果を Coordinator Agent に返し、結果を集計してエンドユーザーに配信します。
- ピアネゴシエーションモード:Coordinator Agentは、エンドユーザーのタスクをExecution Agentに配布し、その割り当てられたタスクを独立して実行します。 実行エージェントは、Coordinator Agent で処理を行なうことなく、Coordinator Agent を介してエンドユーザーに結果を直接返します。
- サブスクリプションモード:Coordinator Agentは、サブスクリプションベースのタスクをExecution Agentに委任することができます。 例えば、「正月の祝日の1週間前に北京へ切符を予約」というタスクは、指定された時刻で実行するコオルディネータエージェントが、そのタスクを、実行エージェントに割り当てられます。
異なるタスクは、長い短い接続を必要とする場合があります。AIエージェントプロトコルは、メッセージマルチキャスト、出版物/サブスクリプション(PUB/SUB)、非同期通知などの複雑なインタラクションモードを含む、単純なリクエスト/応答を超えたメカニズムを提供することができます。
AIエージェントプロトコル設計 MUST タスクメッセージの転送を容易にするために、エージェント通信サーバーのサポートを検討してください。 エージェント通信サーバー SHOULD タスク要件に基づいてメッセージをスケジューリングし、転送を優先して、効率的なエージェントのコラボレーションを確保し、トランスミッションQoSの目標を達成します。
例えば、エージェント通信サーバー MAY 優先階層(最上位から最下まで):
- 信号伝達タスクの制御
- メディアストリーム送信タスク
- トレーニングデータストリーム送信タスク
この優先化スキームは、混雑やリソースのコンテンツシナリオで重要なメッセージが優先的に処理されるようにします。
タスクを Execution Agents に委任すると、Coordinator Agent は、エンドユーザーの連絡先情報、タスク自体、Coordinator Agent が知られる履歴設定情報、および作業の実行を容易にするために必要な会話データを含むことができます。 例えば、旅行計画の場合、これは歴史的に予約されたフライト/ホテルの好みを伴うか、最近のユーザー ダイアログのような動的に知覚されたコンテキストを伴うかもしれません。 AIエージェントプロトコルは、コンテキストタイプ、長さ制約、エンコーディングフォーマットの標準化された定義により、タスク実行の有効性を高めるためにコンテキスト共有メカニズムを継続的にサポートする必要があります。

## 6. コミュニティモード - 中国
二つの次元からAIエージェントの通信モードを定義します。 コミュニケーションの場として、ポイントツーポイント通信(2AIエージェント)とグループコミュニケーション(3つ以上のAIエージェント)に分けられ、この次元に基づく2つのサブセクションに分割される。 一方、AIエージェント間の通信は、直接通信と間接通信に通信を分割する中間ノードの参加を必要とするかという次元で、各サブセクション内の分類においてさらなる精緻化が図れます。
### 6.1. . ポイントツーポイントコミュニケーション
ダイレクト・コミュニケーション:AIエージェントは、処理のための中間ノードの必要性なしに、直接プロトコルメッセージを送受信したり、AIエージェントはこれらの中間ノードの気にしています。
間接通信:AIエージェント間のコミュニケーションは、エージェント通信サーバの処理・修復を要し、AIエージェントはエージェント通信サーバーに意識してやり取りしなければなりません。 エージェント通信サーバーの機能には以下が含まれますが、以下に限定されません。
- AIエージェントのアクセス制御(AIエージェントのメッセージのIDや権限に基づいてブロックする)
- アプリケーションレイヤープロキシ(AIエージェントの通信動作の監視/監査を容易にしたり、AIエージェントのアイデンティティを隠すための)。
- リレー(コミュニケーションメッセージの転送、クロスドメイン通信を容易にするなど)
- 交通集計(ツリー構造のトラフィック規制、通信効率の改善)
- 認証とメッセージのやり取りを2つのコミュニケートパーティ間で処理します。
### 6.2. . グループコミュニケーション
コミュニケーションコラボレーションをうまく達成するために、エージェントはグループを動的に形成することができます。 グループ内でのエージェントが送信する情報は、同じグループ内の他のエージェントで同時に受信できます。
### 6.3. の PUB/SUB コミュニケーション
このモードでは、AIエージェントが情報を送信すると、AIエージェントがどのAIエージェントに受け取る必要があるのかは分かりません。 エージェント通信サーバーに情報を公開し、このエージェント通信サーバは、購読状況に基づいて、サブスクライブエージェントに情報を配信します。 アプリケーションレイヤーでは、パブ/サブは、大規模なグループ通信シナリオに適した、特に情報分布の一般的で効率的な方法です。

## 7. マルチメディア - のための2012年
AIエージェント間のインタラクションは、テキスト、ファイル、ドキュメント、画像、構造データ、リアルタイムのオーディオストリーム、ビデオストリーミングなど、多変性をサポートしなければなりません。 異なる多変性や伝送モード(例、リアルタイムスチームリング、またはプッシュ通知)のデータサイズは異なる場合があります。
上記のようなトラフィック特性を付与し、エージェント通信プロトコルは、上記のマルチモーダルデータ伝送をサポートすべきです。 同時に、エージェント通信プロトコルと他のレイヤーの可能なプロトコルは、マルチモーダルデータが区別され、認識できるという原則で設計されているはずです。これにより、パフォーマンスの検証やリソース効率性を向上させるために、差別化されたポリシーで処理できます。 例えば、異なるマルチモーダルデータが異なる品質保証の異なる輸送ストリームで送信することができます。 または、同じ輸送の流れの中で送信することができますが、異なるポリシー(例えば、伝送優先)で。

## 8. 機能登録 — 通信、モバイル参加
容量登録プロセスとキーメッセージ、パラメータ
信頼ドメインにおけるAIエージェントの登録手順は、図1のステップ(A)-(B)を参照することができます。 信頼ドメインシナリオでは、AIエージェントは、エージェント、ネットワーク機能、サードパーティサーバーなど、集中管理された Agent 登録サーバに属性を登録する必要があります。 例えば、6Gコアネットワークでは、エージェント登録サーバはネットワークリポジトリ機能(NRF)に基づいて進化し、従来のネットワーク機能やネットワークエージェントの登録を支援します。
エージェントが信頼ドメイン(ステップA)に登録する必要があるパラメーターには、次のものが含まれます。
- 名前: エージェントの名前は、ユニークで通常文字列として表されるわけではありません。
- ID:ネットワーク事業者が構成するエージェントのグローバル一意ID。
- 説明: セクション4のADとは異なり、エージェント登録情報の説明は、通常、ADの抽象的として役立つ、自然言語に基づいて、エージェントの関連の詳細の簡潔な要約を提供する必要があります。
- アドレス: URL、FQDN、ICNアドレス等があるエージェントのアクセスアドレス
- バージョン: エージェントの現在のバージョンはリアルタイムで更新できます。
- 機能: 通信機能、インタラクションモード、マルチモーダル機能など、エージェントがサポートする機能 通信機能とは、エージェントがサポートする通信プロトコル(http/2, http/3, A2A, ANP, MCPなど)を指します。 対話モードには、リクエスト応答やサブスクリプション通知などが含まれる場合があります。 多項的機能とは、エージェントがテキストや画像、ビデオなどの処理が可能なデータモダリティを指します。
- サービス: エージェントが提供できるサービス。 例えば、6Gコアネットワークでは、通信サービス、AIサービス、センシングサービス、コンピューティングサービス、データサービスなどを含む場合があります。 ネットワークエージェントは、これらのネットワークサービスの一部または複数のネットワークサービスをサポートすることができます。
- スキル:エージェントがサポートするスキルの詳細な説明のリスト。 各スキルの内容には、氏名、ID、対応するサービス、簡略的な抽象的、必須入力などが含まれます。 例えば、6Gコアネットワークサポートスキル「Policy Control」と「User Location Prediction」にデプロイされたAgent。 これらの中で、「ポリシーコントロール」は通信サービスに対応し、ユーザーポリシー関連の情報を含む入力を要求します。 「ユーザーロケーション予測」はAIサービスに対応しており、ユーザー識別や履歴位置情報を含む入力が必要です。
- インターフェイス:エージェントが提供できるネットワーク・インタフェース。
- セキュリティ関連情報:例えば、ライセンス、認証資格、エージェントのキー。
エージェント登録サーバーは、エージェントの登録情報をローカルに解決します。 エージェント登録サーバーは、登録担当者(ステップB)に参加登録応答を返します。


## 9. 資本の発見 -- 移動

前章では、AIエージェントの登録メカニズムが導入され、エージェント登録サーバーに頼りになるようになり、独自の機能やアイデンティティ情報など、信頼できるドメインでAIエージェントの登録を完了しました。 AIエージェントの発見は、エージェント登録サーバーに依存し、検出プロセスは「クエリマッチング」と「結果フィードバック」の2段階で構成されます。

** クエリマッチング
開始AIエージェント Aは登録サーバーに問い合わせを送信します。そして、サーバ画面と機能データベースに基づいてターゲットエージェントにマッチします。クエリリクエストはMQTT Publishプロトコルを介して送信することができ、要求パラメータは構造化されるべきです(あいまいな説明を避けるために)。 以下に例を示します。

要件の種類:「医療画像解析」
位置範囲:「基地局BS-001の1キロ以内」
実時間条件:「潜在能力≤100ms」
保安レベル:「医療用資格VC」が必要です。

参加登録サーバは、次の優先順位に従ってスクリーニングを実施します。
優先: アイデンティティの有効性(有効なVCがあるかどうか)
第二優先:場所とリアルタイムのパフォーマンス(指定されたエリア内であっても、レイテンシ要件を満たしているか)
第三優先:資源冗長性(例えば、計算力アイドル率≥50%のエージェントは優先されます)

マッチングが完了すると、各エージェントのDID、通信アドレス、および能力マッチング度を含む「ターゲットエージェントリスト」が生成されます。

** 結果のフィードバック
参加登録サーバは、マッチングした結果をイニシエータAIエージェントAに送り返し、イニシエスタが結果に基づいてセッションの立ち上げを開始します。 このプロセスでは、登録サーバが「ターゲットエージェントリスト」を押します。 リストを受信した後、イニシエストは、ターゲットエージェントを優先的に選定し、リストの「コミュニケーションアドレス」と「プロトコル設定」に基づいて選択します。 例えば、ターゲットエージェントがリアルタイムのインタラクションや非リアルタイムのデータ同期の設定を優先している場合、送信者は必要に応じて適切な通信プロトコルを選択することができます。


## 10. セッション管理 -- 移動
セッション、セッションステータス、コンテキスト管理の作成
ピアエージェント(Agent D)を発見した後、ローカルエージェント(Agent S)は、通信するためにセッションを確立する必要があります。 タスクが完了したら。 セッションリソースを解放することができます。
### 10.1 セッションの設置と管理
エージェントDとの通信の前に、エージェントSはまず、エージェントコミュニケーションサーバーと安全な接続を確立する必要があります。 エージェントSは、エージェント通信サーバーの認証を受けなければならない。 同様に、エージェント D は、エージェント通信サーバーが安全な接続を確立するために認証する必要があります。
そのため、エージェント通信サーバーは、エージェントSやエージェントDの状態など、添付エージェントのステータス維持をサポートする必要があります。 つまり、エージェント通信サーバーにエージェントステータステーブルがあり、テーブルにはエージェントIDやエージェントIPなどの情報が含まれるはずです。
エージェント D との通信のため、Agent S は、Agent Communication Server のセッション・インストール要求を開始します。 権限の確認後、Agent Communication Server は、セッション ID をグローバルに一意のセッション ID を新しいセッションに割り当てることにより、セッションの確立を進めます。 セッションのライフサイクル全体を通して、全てのアクティビティとデータを関連付けるIDを使用します。 応答的に、Agent Communication Server はセッションテーブルを維持する必要があります。これは、セッションに関与するすべてのエージェントに関する情報を含む、特にセッションイニシアクターに関する情報が含まれます。
### 10.2 差別化された QoS 保証
セッションの確立中に、Agent S はセッションの関連した QoS 要件を提供できます。 その結果、エージェント通信サーバーは、セッションのQoSを確実にするために、これらの要件に応じてメッセージを処理し転送を優先することができます。
## 11. ルーティング - カウント
### 11.1. リリース エージェントIDベースのルート検索
このセクションで説明したシナリオは、エージェントが別のエージェント(またはエージェントのグループ)にメッセージを送信し、送信エージェントのIDやグループIDを受け取ったことを知らせるときです。 セクション6の通信モードの2つの主要なタイプに従って、状況は次のように分類することができます。
- 点間対ポイント通信(P2P):
	- 直接通信モードでは、エージェントは受信者のIDを使用して対応するIPアドレスを調べます。これにより、メッセージが受信者に送信できるようにします。
	- 間接通信モードでは、エージェントはIDの検索タスクを Agent コミュニケーション サーバーに委任することができます。これにより、IDに基づいてメッセージ送信者エージェントにメッセージを送信できます。
- グループコミュニケーション:
	- エージェントは、グループ ID の検索タスクを Agent コミュニケーション サーバーに委任し、同じグループで受信者のエージェントにメッセージを送信する責任を負います。
### 11.2. . 準道ベースのルートの解像度
このセクションで説明したシナリオは、エージェントが特定の機能や属性を持つ他のエージェントと通信したいというときにありますが、まだ自分のIDを知らないのです。 この場合、エージェントが記述する機能や属性に基づいて基準を満たす Agent ID を検索するには、セマンティックな検索システムが必要です。 取得したIDに従って、メッセージがルーティングされます。

## 12. プロトコルのプロパティ
### 12.1. . アプリケーションプレーヤーワワイはクラウドコアです

- アプリケーションのレイヤーで柔軟なルーティング機構をサポートし、DNS のクエリや DID によるセグメントベースのルーティングに基づく直接ルーティングを含みます。

QoSの保証:複数のレベルのQoSシステムは、エージェントセッション内のデータタイプとサービス要件の違いに基づいて構築する必要があります。 輸送層は、資源分離を実装しながら、エージェントサービスに割り当てられたQoS優先度を輸送層のスケジューリング優先度に変換する必要があります。 また、モバイルシナリオでは、QoS の規定に応じて、動的にQoSパラメータを最適化し更新する必要があります。

多項データ・オフロード/データストリーム・マルチプレックス:マルチパス・トランスミッション機能(MPTCP、MPQUIC)は、エージェントから複数のソース・データの柔軟な伝送管理をサポートするように採用される。 複数のデータが、単一のリンクで混雑を防ぐため、データタイプやネットワークリンク条件に基づいて適切な伝送経路に割り当てられます。 一方、複数のセッションのデータが伝送ユニットにカプセル化されると、複数のセッションのデータストリームを多重化することができます。 データ識別子がデータ所有権を区別するために導入され、分離メカニズムはデータのストリームの多重化中に相互干渉が起こらないことを保証します。

モビリティ管理:モバイルシナリオのエージェントユーザーのためのサービス継続とセッションの持続性をサポートする必要があります。 たとえば、QUICの接続IDは、モビリティをサポートするために使用されます。 エージェントの動き中、マルチパス伝送と高速ハンドオーバーをサポートします。 ハンドオーバー通知を受信すると、トランスポートレイヤーは、未完成のデータパケットを新しいリンクに送信するか、データをバックアップリンクに切り替えるか、エージェント通信のモビリティ管理を有効にする必要があります。

- アイデンティティ:AIエージェントは、エンボディされたロボットから仮想アシスタントまで様々で、異なるアイデンティティとクレデンシャルストレージのアプローチを紹介します。 プロトコルは、SIMベースのロボット、証明書ベースのAIアシスタントなど、これらの要件を満たす統一された互換性メカニズムを考慮する必要があります。

- 認可:エージェント通信の現在の慣行は、既存の OAuth 2.0 関連メカニズムに依存しています。 直接の承認、委任された承認およびユーザー認可のための別の承認メカニズムがあると考慮されるべきです。

- ディスカバリープライバシー:AIエージェントの出版物は、所有者の承認を得る必要があります。 天然人である可能性がある所有者に関連した可能性のある機密情報を考慮して、すべてのエージェントカード/説明/アイデンティティが公開されるべきではありません。
- タスクプライバシー:タスクの実行に関与するエージェントは、タスクの説明の最小化の原則に従うべきです。つまり、各エージェントがタスクを完了するために必要な最低限の情報のみを受け取る必要があります。機密情報への不正なアクセスを防ぐためです。 また、コンテキスト共有はユーザーのプライバシーに影響を及ぼす可能性があるため、特にユーザーの名前、年齢、住所などの機密情報について、コンテキスト共有のスコープに関する制限を考慮することが重要です。
